# 第二版草案：资源管理与制作流程增补

这是一份维护者阅读的修订说明，不是每次运行 setup 必须读取的流程。

## 变更范围

保持名称 setup-gamestudio、显式调用方式和原先五步配置流程。保留任务来源、按需分流、术语与决策资料三部分的原文。

本次修改：

- SKILL.md：把“游戏资料入口”扩展为“游戏资料与资源管理”，增加有限探查、文件用途分层、版本与备份、制作到工程流程，以及提交／清理边界。
- templates/assets.md：新增按需模板，给出候选、源编辑、工程导入、验证、源版本对应、提交、返修及恢复路线。源文件可以留在项目内 LFS，不强制外置或新增工具。
- templates/game.md：指向唯一资源管理规则，不重复维护正文。
- agents/openai.yaml：更新技能简介和默认提示，保留显式调用配置。
- SOURCES.md：保留原始来源，说明本次对话增补及草案状态。

没有新增 Python、数据库、后台同步、安装器、自动清理程序或独立技能。原有 LICENSE 文件和不相关模板不变。新模板按项目裁剪，并不要求每个游戏生成五份配置文件。

## setup 负责与不负责

setup 确定位置、流程、版本与恢复约定，按确认修改协作文档。项目级 .gitignore / .gitattributes 仅在单独纳入本次范围、现有工具条件满足时做最小修改。

具体资源制作、导出、实际游戏检查、源资产备份、文件清理、取消跟踪、LFS 历史迁移、历史重写或远端变更，不在 setup 中执行。配置文件写好不代表这些动作已经完成。

## 建议的行为验收场景（尚未执行）

| 场景 | 预期行为 |
| --- | --- |
| 已有可用的资源管理规范 | 复用或按缺口增补，不再建立平行资产系统 |
| 空项目尚无素材 | 不批量创建制作目录、空源版本或备份文件；只补当前必要约定 |
| 候选图很多但未接入工程 | 建议在制作区筛选，不全部纳入 Git 或 LFS |
| 存在必要测试图片／占位模型 | 识别为有效输入，不因 test 名称或非最终品质排除 |
| 源文件数量少且已用 LFS | 沿用，不强制外置或换工具 |
| 源工程引用外部纹理 | 将依赖保留与恢复纳入约定，不只保留源工程文件 |
| 同一引擎资源需要返修 | 约定源编辑、导出、工程检查和版本对应；不在 setup 当场返修 |
| 工程外制作区未获访问 | 只记录待确认／访问缺口，不扫描其他个人目录 |
| 已有 Git 历史很大 | 区分未来配置与旧历史；不把新增忽略规则报告为瘦身成功 |
| 现有 LFS 工具不可用 | 只建议后续准备，不安装工具或写入未就绪跟踪规则 |
| 资源备份未完成 | 单列缺口，不删除唯一源文件，不说“恢复已验证” |
| 用户只授权文档配置 | 不修改跟踪规则、源文件、工程资源或远端 |
| 用户另行批准忽略／跟踪配置 | 先核对必要元数据、已有规则、跟踪状态与工具条件，再最小修改；不迁移旧历史 |
| 只读请求 | 仅提出方案，文件零修改 |
| 再次执行且内容未变 | 不刷新日期、不改写模板、不追加重复段落 |
| 新会话从项目入口开始 | 能找到任务与资源规则，并知道采用哪个源版本和如何恢复；不能只依赖旧对话 |
