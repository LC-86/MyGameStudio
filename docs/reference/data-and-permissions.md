# 数据、写入与权限

安装技能只解决「技能能否被发现、技能目录内的文件能否被读取」。加载一项技能不授予任何权限。

## 数据在哪

| 种类 | 位置 | 谁维护 |
|---|---|---|
| 技能正文、共享参考与许可通知 | 宿主技能目录下的 `<技能名>/`（例如 `.agents/skills/ask-gamestudio/`），安装来源是本仓库的 `skills/` | 技能版本 |
| 游戏项目代码与资源 | 你的游戏仓库 | 你 |
| 项目资料：GDD、spec、术语表、决策记录、资源约定 | 你的游戏仓库，实际位置由 `setup-gamestudio` 记录 | 你 |
| 任务记录 | 项目已有的承载方式（GitHub Issues、本地 Markdown 或其他） | 你在协作约定里声明的现行来源 |
| 本仓库的 `AGENTS.md` / `docs/agents/` | 仅本仓库 | 维护者；不要复制到游戏项目 |

`docs/`、`provenance/`、`tests/`、`scripts/` 是维护资料，不随技能安装，也不是技能运行的隐性必需输入。

## V3 没有专用记录运行层

V2 的 `plugin/records/` 程序层已经删除。任务读写现在用**游戏项目已有的工具**完成：CLI、连接器、文件操作，以及项目自己的记录格式。

因此本库不再提供、也不宣称下列保障：程序级幂等恢复、跨后端一致性、待写入索引、写入前快照与安全切换。作为替代，技能正文承担三条要求：

1. **写入后回读**：确认落盘内容与意图一致，不以命令退出码代替核对。
2. **部分成功单独报告**：多份文档或多条记录中有一部分失败时，分别说明哪些成功、哪些失败、失败原因，不合成一句「已完成」。
3. **不宣称原子多文档写入**：跨 GDD、spec、术语表或任务记录的多处更新不是事务；中断后的状态以实际回读结果为准。

缺少这些保障不是提示词层面的等价替代，取舍记录在 [provenance/v2-retirement.md](../../provenance/v2-retirement.md)。

## 会读取什么

只读导航、状态核对与诊断会读：项目内已有文档、代码、任务记录、最近检查结果，以及技能目录内的共享参考。读取资料是了解情况，不是开始制作，也不构成写入授权。

## 会修改什么

- `setup-gamestudio`：先探查、提建议、等你确认，再做获准的最小文档修改并回读；约定完整时重复运行不改文件。
- `grill-gamestudio-docs`、`gdd-gamestudio`、`spec-gamestudio`、`domain-gamestudio`：只在已授权的文档协作任务中落盘已确认内容。
- `tasks-gamestudio`：按项目约定保存或发布任务；标签变更会触发现有自动化时先核对授权。
- `implement-gamestudio`、`tdd-gamestudio`、`debug-gamestudio`、`merge-gamestudio`：按已确认范围改代码、资源或解决冲突；提交、继续操作与推送各自需要授权。
- `review-gamestudio`：只读检查，不自动修复，不改任务状态。
- 联网与外部写入：使用宿主已配置的工具与凭据，只在本次任务授权范围内使用；不读取无关凭据。

## 从不假定的授权

写入项目文件、上传或发布、付费、修改全局配置或账户权限、`git commit`、`git push`、打标签、创建或修改工单与 PR、发送消息、删除或覆盖既有资料。每一项都需要你在当前任务中明确给出；项目文档或任务标签本身不是授权凭证，夹具或示例里的开关也不算已授权。

## 联网

本库没有专用 MCP 服务，也不自带后台进程。研究、任务发布与远端写入会走宿主已配置的工具，可能联网。不要把「没有 MCP」写成「完全离线」。
