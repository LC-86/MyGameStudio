# 数据、写入与权限

安装插件只解决“技能能否被发现、包内文件能否被读取”。
它不自动授权改你的游戏、提交 git、推送远端或发版。

## 数据在哪

| 种类 | 位置 | 谁维护 |
| --- | --- | --- |
| 插件技能与合同 | 客户端安装的插件根（来自 Release 的 `plugin/`） | 插件版本 |
| 游戏项目代码与资源 | 你的游戏仓库 | 你 |
| 游戏工作流资料 | 接入后常见为项目内 `docs/mygamestudio/` | 你，经确认清单写入 |
| 任务记录 | 本地 Markdown **或** GitHub Issues，每项目一种 | 你在协作配置里声明的现行来源 |
| 本插件仓库的 `AGENTS.md` / `docs/agents/` | 仅本仓库 | 插件维护者；不要复制到游戏项目 |

## 会读取什么

只读分析与状态查询会读：项目内已有文档、代码、任务记录、包内阶段资料。
读取专业资料不是开始制作。

## 会修改什么

- `game-init`：确认前不写入；确认后只应用清单内条目
- `game-design`：可保存讨论过程；正式规格要你调用 `to-spec`
- `game-producer`：状态查询不改记录
- `implement`：按任务改代码；**无提交授权则不提交**
- GitHub 写入：CONFIG 中必须有明确到该仓库的 issues-write 授权记录，未记录即未授权

## 联网

无专用 MCP 服务。GitHub 模式需要网络、`gh` 或等价传输，以及你的账号权限。
本地 Markdown 模式仍可能因宿主、模型或工具而联网。不要把“无 MCP”写成“完全离线”。

## 授权边界

插件不能扩大系统权限。隔离验收使用临时 `HOME` / `CODEX_HOME`，不等于已经装进日常客户端。
真实个人项目迁移与技能来源切换需要单独授权；夹具里的开关不能当成已授权。
