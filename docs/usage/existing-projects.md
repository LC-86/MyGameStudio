# 接入与修改已有游戏

已有项目先分析，再决定补什么。不要把隔离验证或文档示例写成已经改过真实游戏。

## 只读接入分析

```text
请使用 MyGameStudio 的 game-init 分析当前游戏项目。

这一轮先只读，不修改文件。
请说明已有玩法、设计资料、工程与资源，以及接入工作流仍缺的内容。
列出建议复用、新增和需要我决定的事项，等我确认后再写入。
```

成功标准：指出实际读取的资料与缺口；分析阶段不改游戏文件；未运行的配置不当成完成。

确认清单之后，才允许接入写入。每项目只维护一种现行 tracker：本地 Markdown 或 GitHub Issues，不双向同步。

通用分流标签和 `CONTEXT.md` 布局仍由你调用 `setup-matt-pocock-skills`。Game-Init 不代做那一套。

仓库里可对照的样例与调用说明：[examples/existing-game-change](../../examples/existing-game-change/README.md)。

## 修改已有玩法

```text
请使用 MyGameStudio 的 game-design。

我希望把当前体力系统从“按次数扣除”改成“随时间恢复”。
先读取已采纳规则，说明会影响哪些系统，再和我讨论候选方案与取舍。
这一轮不要修改正式规格，也不要开始编码。
```

讨论记录不是现行规格。你采纳方案后，再主动调用 `to-spec`。
不要把技能之间的箭头当成自动授权。

## 已有资料迁移

本地 Markdown 或 GitHub 旧项目的完整资料转换，成果先处于待切换；核对完整后才切换现行指针。
切换合同用隔离目录演示时，不等于已经在真实客户端完成安装或迁移。
