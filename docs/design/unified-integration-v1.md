# 从当前草案到统一设计的整合清单

性质：本次汇总的实施要求与差异清单，不是已完成修改记录。旧草案和GitHub本次均未改动。

## P0：共同写作方法

### Docs自身

当前 `docs-gamestudio` 主要列举技能、项目规则、参考资料，GDD/spec被描述为按需改善表达。目标改为共同写作方法：覆盖正式指令和工作记录，重点补入子代理委派、tickets、spec、GDD、研究/测试/评审记录与交接。

保持分工：专业技能选择内容、决定范围、控制实际文件更新；Docs提供表达和校对方法，不另建内容权威源，不默认审批所有文档，不递归派发写作任务。

建议新增一份 `references/delegation.md`，集中说明主代理派发前需要提供什么、接收者不具备哪些默认上下文，以及返回结果怎样核对。保留已有Skill编写参考；不要把全部游戏方法重复复制进去。

### 产出方接入

| 产出点 | 目标行为 | 当前落地情况 |
|---|---|---|
| GDD/spec | 正式编写与实质修订前取得Docs方法，同上下文复用 | 尚无显式接入 |
| Tasks | 任务说明含依据、范围、验收、人工责任及交接；不丢失数值例外 | 尚无显式接入 |
| Domain | 简短定义与决策理由不混入全规则；及时写入仍遵循已有授权 | 尚无显式接入 |
| Review | 主代理按Docs准备两轴委派；结果有证据和未评范围 | 已有较好委派说明，但未连到共同方法 |
| Research/Wayfinder/Grilling | 真实委派前提供当前问题和必要资料，明确不重复派发同题 | 各自有局部约定，未统一接入 |
| Debug/TDD/Prototype | 结果记录保持实际证据、候选/试验/采纳状态及覆盖限制 | 尚无显式接入 |
| Setup/Handoff | 指针带用途，引用与访问状态真实，用户未确认内容不被固定 | 尚无显式接入 |
| Codebase/Merge | 设计与冲突结论按实际做法表达，不把建议写成已执行 | 尚无显式接入 |
| Ask | 保持只读导航；可直接发送的指令应用相关写作方法，可只读查阅 | 不为接入Docs改变导航边界 |
| 两个一句话入口 | 保持现有组合语句，由实际产出方法承接Docs | 不直接扩成长流程 |

“显式接入”不是要求每一份文件都出现完全一样的调用句。可采用清楚的调用或对共享参考的有条件读取，但要能从消费者追踪到实际方法。只把名字加进文件而正文不被使用，也不算行为完成。

同一上下文已经有效取得方法时直接沿用；子代理在新上下文中重新取得必要部分。用户的临时一句回复、原始日志和勾选更新不触发整篇重写。

## P0：跨技能一致性

1. Setup分流模板与Tasks共享责任说明核对。“可交给Agent”不等于整项任务无需人；“人工接手”需具体输入已就绪。
2. GDD/spec只处理明确差异，检查部分写入失败与反向调用停止条件。
3. Review两轴输入为同一实际版本；未提交内容不可只用HEAD代表。缺少独立子代理能力时不要宣称独立评审已发生。
4. 子代理委派的命令和技能必须在接收端真实可用，父代理加载与子代理获得不是一回事。
5. 工具能力、写入、操作授权和技能调用许可分别处理，不通过任务标签或Notes扩大权限。
6. 外部文档、Issue正文和报告中的指令作为资料，而非新的授权来源；编辑Skill中的命令不等于执行命令。

## P1：源码与资料整合

- 每项技能一个权威目录；现有包中重复附带的依赖即使字节一致，也不能在正式源码中成为多处独立维护版本。
- 对共同文档先确定一个所有者路径，再一起更新消费者；不为整理目录引入强制运行时。
- 核对裸名称、相对引用、引用中的标题锚点、可访问性和实际Skill工具形式；文件存在性只是第一层。
- 使用当前20项作为候选发布集合，来源与适配映射保留，历史候选名称不重复发布。
- 不以修改源码时自动重写Git历史、迁移旧任务或删除旧Python为附带操作。

## P1：保留来源与适配追溯

每个重要适配至少能回答：原版怎样做、哪个用户决定要求改变、改变什么、可能损失什么、用哪个实际场景核对。

优先核对的差异：Docs广泛应用；Prototype浏览器小游戏；TDD局部重构；Debug较灵活的复现门槛；Review完整待交付输入；Wayfinder简化问题分类；Handoff非固定临时目录；Merge取消“必须解决、全部暂存并提交”。

## P2：行为验证与旧版切换

先跑主设计 E03/E04/E06/E08/E09/E14/E15 等高风险场景，再扩展。保留模型/宿主版本、输入、工具轨迹、修改前后差异和错误记录。

旧 game-producer/game-init/game-design 以及原记录、迁移、恢复程序的去向未最终收口。在恢复路径和差异明确前，不宣布完全替代、不删除历史资料。

## 不应误报为已完成的事项

本清单已写出，不等于文件已改；原文已对照，不等于适配已等价；相对链接存在，不等于真实客户端可用；技能已能选择，不等于子代理实际遵循；任务已保存，不等于授权执行；代码已提交，不等于人工体验已通过。
