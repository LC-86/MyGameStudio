# 升级、卸载与同名技能

升级插件、迁移用户项目资料、升级 Matt 基线是三件不同的事。
不要以“升级插件”为由自动改写所有游戏项目。

## 三种升级

| 动作 | 做什么 | 不做什么 |
| --- | --- | --- |
| 插件安装版本更新 | 换成新的完整插件包，再按客户端完成发现 | 不静默改用户设计、任务、代码、素材 |
| 用户项目资料结构迁移 | 经 `game-init` 列出清单，确认后才应用 | 不把隔离演示说成已完成真实客户端迁移 |
| 上游 Matt 基线升级 | 经 provenance 评估，确认后才采用钉住版本 | 不直接改成 `latest` |

2.0.2 的隔离 Codex CLI 升级（`remove` 后再 `add`）**已验证**。日常客户端升级未验证。0.18.0 曾在隔离 Codex 上实测同一命令；那是旧版本证据，不能单独当作 2.0.2 会话结论。

## 同名技能

本包包含 Matt 正式技能。若同一工作环境里已经有：

- Matt 原版技能
- skills.sh 或其他安装器复制的副本
- 旧版 MyGameStudio

先识别来源，保证**只有一个明确有效来源**。不要擅自覆盖或删除用户定制。
技能来源切换的合同在包内 `records/mgs_records.py` 的 `plan_safe_switch` / `apply_safe_switch`；隔离目录演示不等于已安装到真实客户端。

## 卸载

移除插件和保留游戏项目文档是不同选择。

- 默认：**不删除**用户设计、任务、代码或素材
- 只移除插件自己的安装副本与客户端登记
- 若项目里有 `docs/mygamestudio/`，那是项目资料，不是插件本体

各客户端的具体卸载命令以宿主文档为准。本环境未执行卸载。

Codex 隔离命令（2.0.2，Linux + CLI 0.154.0 已执行）：

```sh
codex plugin remove mygamestudio@personal --json
```

ZCode / Grok Build：从本地插件源或插件目录中移除对应安装副本后重启会话。未在真实客户端核对。

## 回滚

回滚插件：安装**匹配版本**的 Release 包与清单，不要混用不同版本的 tar 与 `package-manifest.txt`。
回滚项目资料：只通过已确认的切换/迁移回退接缝，且默认不丢弃新版新增成果。
