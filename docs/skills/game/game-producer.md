# Game-Producer

根据真实记录说明目标、进度、缺口和下一步建议，并按调用合同路由。

## 什么时候用

你想知道“现在做到哪了、缺什么、下一步该启动哪个入口”，而不是马上改设计或写代码。

## 什么时候不需要用

你已经明确要接入项目、讨论某一玩法或实现某一任务时，直接用对应入口。
不要指望本入口自动跑完 `to-spec` → `to-tickets` → `implement`。

## 开始前准备什么

项目最好已经接入，能从 `docs/mygamestudio/INDEX.md` 找到现行规格与任务。未接入时它应指出缺口，而不是编进度。

## 如何调用

```text
请使用 MyGameStudio 的 game-producer，只读检查当前项目。
根据真实记录说明当前目标、已完成和待完成任务、阻塞项以及下一步建议。
不要修改记录，也不要自动启动实现。
```

## 一次调用会做什么

读取阶段资料与真实任务记录，输出目标、进展、缺口、建议下一步。需要下游时给出入口名，由你启动用户专用技能。

## 会读取和修改什么

状态查询只读，不改文件。GitHub 模式下以远端 Issue 为准，本地草稿必须标明身份。
有单独授权的管理记录更新也不得扩大提交、推送或发版权限。

## 你会得到什么

一份基于记录的状态说明。缺项会按真实记录列出。旧的独立状态入口已并入本技能，不再使用 `game-status` 这个可执行名字。

## 怎样判断成功

- 没有编造完成度
- 没有自动调用 `implement` / `to-spec` / `to-tickets` / `wayfinder` 等用户专用入口
- 查询前后项目文件未改（只读请求时）

## 一个游戏开发示例

发布前问“最小闭环还缺什么”：应列出未关闭任务、缺少试玩记录或缺少运行入口，而不是直接开始改代码。

## 常见问题与限制

- 制作统筹按需调用 `game-init` / `game-design` 以及合同中的模型可调用技能，这不是“用户主动调用”
- 资源、构建、试玩由实际任务承担，不在本入口重新包装成独立公开技能

## 下一步通常用哪个技能

按缺口推荐：未接入则 `game-init`；玩法不清则 `game-design`；已有规格则由你调用 `to-tickets` 或 `implement`。
