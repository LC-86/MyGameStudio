# Game-Init

分析已有游戏并补齐接入 MyGameStudio 工作流仍缺的资料。

## 什么时候用

接手一个已有游戏仓库，或给尚未接入工作流的项目补文档与任务位置时。

## 什么时候不需要用

只想改一句文案、而且项目已经接入且资料仍有效时。不要用它代替 `game-design` 讨论玩法，也不要代替 `implement` 写代码。

## 开始前准备什么

- 已安装完整插件，能发现 `game-init`
- 明确项目根目录
- 想清楚任务记录用本地 Markdown 还是 GitHub Issues（每项目只选一种）
- 通用 tracker / 标签 / 领域文档准备调用 `setup-matt-pocock-skills`，本入口不代做

## 如何调用

用户显式选择本技能，或制作统筹在当前任务内按需调用。普通对话不应自行触发。

```text
请使用 MyGameStudio 的 game-init 分析当前游戏项目。
这一轮先只读，不修改文件。
请说明已有玩法、设计资料、工程与资源，以及接入工作流仍缺的内容。
列出建议复用、新增和需要我决定的事项，等我确认后再写入。
```

## 一次调用会做什么

先只读探查，归入现状类别，列出复用 / 新增 / 待决定。你确认前不写入。确认后只应用清单内条目。

## 会读取和修改什么

读取项目内已有设计、代码、资源与任务痕迹，以及包内阶段资料。
确认前不改游戏文件。确认后可写入接入资料指针，不覆盖仍有效的旧资料，不扩大提交或外部授权。

## 你会得到什么

接入清单、已知矛盾、仍缺项。不会把未执行的 setup 或验收写成完成。

## 怎样判断成功

- 指出实际读过的路径
- 只读阶段 git 状态或文件未改
- 待你决定的事项没有被擅自拍板

## 常见问题与限制

- GitHub 模式必须有明确到仓库的 issues-write 授权
- 不双向同步两套任务账本
- 技能来源切换的隔离演示 ≠ 真实客户端安装

## 下一步通常用哪个技能

`setup-matt-pocock-skills`（若通用配置未做）→ 需要时 `game-design` → 你主动调用 `to-spec`。

## 来源与本插件适配差异

本项目原创游戏入口。不替代 Matt 的 setup / 拆票 / 实现技能。
