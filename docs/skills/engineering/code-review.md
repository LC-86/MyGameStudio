# Code Review

对一份完整待审成果做 Standards 与 Spec 两轴评审。

## 什么时候用

实现完成后、提交前，或你要审查某段已有改动是否符合规格与仓库标准时。

## 什么时候不需要用

还没有待审内容。空的已提交差异不能拿来当“评审通过”。

## 开始前准备什么

基线（commit/分支/标签）、本次交付的路径范围、规格来源。无提交授权时，评审后工作仍保持未提交。

## 如何调用

由你选择本技能（模型也可在当前任务内调用；它不是制作统筹可用来代替你启动实现的入口）。

## 一次调用会做什么

捕获已提交、暂存、未暂存、新建与删除的适用成果，两轴消费同一内容版本，分别报告。不以获取标识为由创建提交。

## 会读取和修改什么

读取 diff 与规格/标准文档。评审本身不应借机提交。工作树在评审中途变化时要按新内容版本复核。

## 你会得到什么

Standards 与 Spec 两份发现，以及可核对的内容版本哈希。

## 怎样判断成功

待审范围完整；无关脏文件被排除；没有用空 HEAD 差异代替完整评审。

## 一个游戏开发示例

体力恢复功能：Spec 轴核对是否按已采纳恢复曲线实现；Standards 轴看是否违反仓库已有约定。试玩主观判断记在任务上。

## 常见问题与限制

缺少 issue-tracker 配置时应先 setup。包内捕获入口：`plugin/internal/review/pending_review.py`。

## 下一步通常用哪个技能

按评审结果修改后再实现，或在有授权时提交。

## 来源与本插件适配差异

上游只比较固定点到 HEAD 的适配已被改为完整待审捕获。
