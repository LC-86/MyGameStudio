# Implement

按规格或任务把工作做进当前工程。

## 什么时候用

范围已经写清，你准备改代码或必要资源，并接受检查时。

## 什么时候不需要用

玩法还没决定，或只想看进度。不要让制作统筹自动启动本技能。

## 开始前准备什么

任务或规格、允许修改的路径、以及是否授予提交权限。

## 如何调用

由你主动选择，并写明要做哪张票/哪份规格。

## 一次调用会做什么

按任务实现，优先走 `tdd` 约定接缝，结束前用 `code-review` 的方式检查。有提交授权才提交；否则留下未提交成果。

## 会读取和修改什么

读取阶段资料与任务范围，修改范围内的工程文件。不扩大到商店后台或未授权的 git 推送。

## 你会得到什么

可检查的实现。正式工程默认带最小闭环与运行入口；实际检查结果应记在任务上。

## 怎样判断成功

任务写明的操作能够实际运行或给出真实缺口；未授权时没有新的 git 提交。

## 一个游戏开发示例

实现体力随时间恢复：改规则与 HUD，启动游戏看一条体力从空到满的过程，记录所用版本与启动方式。

## 常见问题与限制

读取阶段资料不是开始制作。无替代工具时继续不受影响的工作，不默认安装付费软件或降低检查要求。

## 下一步通常用哪个技能

`code-review`；需要试玩判断时把结果记在任务上，而不是恢复已退役的独立试玩入口。
