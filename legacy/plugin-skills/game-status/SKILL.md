# Game-Status:项目状态检查

只读核对项目当前进度、阻塞、未验证与待人事项。本次检查不写入、不创建、不删除任何项目文件;同步管理记录是需要明确请求的后续动作,当前包未提供该入口。

## 包内依据(开始任何检查前读取)

本技能位于 `<插件根>/skills/game-status/`,包内材料在其上级目录:

- [管理技能合同](../../internal/contracts/management.md)中的 Game-Status 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md)**《共同执行规则》《写入与保障》**:业务入口共同约定与「按本次用途收窄写入范围」的唯一权威;本检查为只读模式,写入范围收窄为零
- [工作记录合同](../../internal/contracts/records.md)与[任务分流设计](../../internal/contracts/task-triage.md):任务记录与分流语义
- [工作结果模板](../../templates/work/result.md)**《结果字段》**:被核对的结果记录字段的唯一权威(读取与核验结果时参照)
- [writing-for-agents](../../internal/methods/writing-for-agents/SKILL.md):文档写入方法;仅当后续被明确要求写入管理记录时才需要读取,只读检查不加载

共同执行规则与结果字段以上述权威文件为准;本入口只做只读状态核对:不提交受控写入(写入通道见[受控写入协议](../../internal/protocols/gate-protocol.md)《受控写入协议》),也不执行任何越界探针。

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-status/SKILL.md`,再取其包根(上级两级)。

分类规则、输出结构与失败场景的详细判定见 [references/status-check.md](references/status-check.md);执行检查时读取。

## 步骤

1. 确定目标项目根:调用消息中给出的路径优先,否则使用当前工作目录。完成标准:单一明确的项目根,且不因资料缺失而改读其他目录。
2. 读取资料入口 `<项目根>/docs/mygamestudio/INDEX.md`。不存在时按 status-check.md 的"未接入"分支输出缺口报告并结束。
3. 按 INDEX 与协作配置(CONFIG)的指向读取项目约定(PROJECT)、设计基线与任务记录。完成标准:每个被引用位置要么实际读取,要么记为缺口,没有静默跳过。
4. 按 status-check.md 的分类规则逐项核对任务记录与实际成果证据。完成标准:每项分类都附文件路径级依据;记录缺失或依据不足的一律归入"未知/存疑",不当作完成。
5. 按 status-check.md 的报告结构输出状态报告。完成标准:报告覆盖当前目标、五类状态、基线核对、缺口与可接续工作,并声明本次为只读检查、列出实际读取的项目文件与包内检查规则(注明从安装位置读取)、以及未能读取的文件。

## 边界

- 只读。即使沙箱或工具允许写入,本次检查也不使用;发现项目资料需要更新时,作为"可接续工作"报告,不代为修改。
- 区分"记录声明"与"实际证据":没有证据支持的完成声明归入待验收或存疑。
- 需要人决定的事项原样保留,不替用户决定。
