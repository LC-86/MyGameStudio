# Implement GameStudio

完成用户本次指定的工作。沿用已经确认的设计与范围，
自主组织实现步骤，不重新设计需求，也不自动领取下一项工作。

开始前读取实际任务、必要依据、验收要求和项目约定，
并遵循[责任、分流与交接](../tasks-gamestudio/references/task-responsibility.md)。
确认目标身份、真实依赖、当前改动与允许操作范围。
对话已明确的小任务可以直接执行，不为开工补建无关文档。

在目标工程或约定的制作位置完成实际成果。
功能所需的代码、资源、内容、集成和反馈按本次范围一并处理；
独立资源或工程任务按自己的交付标准完成，不扩大成整套功能。
沿用项目资源管理规则，保留必要源版本与交接依据。

代码行为适合测试先行时，使用 [tdd-gamestudio](../tdd-gamestudio/SKILL.md) 的方法，
沿用已约定的测试入口。已有约定直接沿用；
确有缺口时提出必要建议，不把内部实现选择逐项交给用户。
宿主提供真实的技能调用能力时使用它；只有方法文件可读时，
按已安装路径取得正文和必要参考并使用，两者都不凭名称宣称已经执行。

实现过程中运行适用的类型检查、相关测试及工程内检查，
收尾执行项目要求的完整检查。非代码成果采用对应的检查方法，
不强套代码测试，也不把未运行项目写成通过。
工具或输入不足时，完成不受影响的工作并明确缺口，
不默默降低要求或假造成果。

代码改动收尾时使用 [review-gamestudio](../review-gamestudio/SKILL.md)。
评审使用本次完整待交付内容，包括相关未提交成果，
排除不属于当前任务的改动；不为取得版本标识强制提交。
两轴评审需要派发子代理时，按 [docs-gamestudio 的委派参考](../docs-gamestudio/references/delegation.md)
组织说明，给两个只读审查者同一份冻结材料和各自依据；
没有独立上下文能力时顺序自查并披露限制。
处理影响本次完成要求的发现，修改后复查受影响内容。
纯资源成果按任务中的专业标准检查。
依赖方法不可用时如实说明，不声称已经执行其评审或测试流程。

实现错误修实现；新的重要设计取舍先明确。
已采纳变化确需更新 GDD 或 spec 时，在已有文档授权内使用
[gdd-gamestudio](../gdd-gamestudio/SKILL.md) 或 [spec-gamestudio](../spec-gamestudio/SKILL.md)，
按 [文档分流与增量协作](../docs-gamestudio/references/document-routing.md) 判断归属；
不反向改写要求来掩盖实现偏差。

对照验收条目记录实际成果、检查与剩余问题。
这份记录会被下一个执行者或验收人读取，
按 [docs-gamestudio](../docs-gamestudio/SKILL.md) 的语义保真要求表达：
已实现、已检查、待人工判断分别写明，未运行的检查保持未运行。
可由 Agent 完成的部分自行完成；需要人判断的部分，
在输入准备好后按共享责任约定交接，保留未完成的人工条目。
全部完成条件满足且具有记录权限时，更新并结束当前任务；
没有权限时报告真实结果，不宣称已经修改记录。

只有已有授权明确涵盖时才提交、推送或执行其他外部动作，
并遵守其前置条件。提交成功不等于验收通过；
人工确认未完成时，不通过自动关闭关联绕过它。
无提交授权则保留未提交成果，不覆盖用户无关修改。
