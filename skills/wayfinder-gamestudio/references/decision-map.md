# 决策地图：用普通文档保留路线

这是编写参考，不是必填表。项目已有合适的资料索引就复用；只处理一个问题时通常无需地图。

## 地图的最少信息

- 目的：本次需要澄清到哪里，以及不追求什么。
- 已有结论：一句话概括，链接到权威决定、GDD 章节或证据。
- 明确问题：当前可以准确描述的问题、真实前提及必要的当前责任。
- 待展开范围：属于当前目的，但依赖上层选择、尚无法准确描述的问题方向。
- 排除范围：当前明确不做的事情，不随推进自动变成任务。

问题清楚但暂时不能解答，应当记为明确问题并标出阻塞；不要因为它尚无答案就全部塞进“待展开”。反过来，不把“后面可能需要成长”提前拆成商城、升级、签到等制作任务。

## 存储与拆分

先用一份简短地图或项目已有的未决设计部分。问题需要单独指派、引用大量证据或跨会话详细记录时，再开独立工单/Markdown，并在地图上引用。保留一份完整答案，地图只摘要。没有拆分的理由就不建一堆空文件。

已配置远端时沿用目标仓库/项目；不可访问不静默切到第二套现行本地账本。纯草案可先在当前对话交付，明确未发布或待确认状态。无既有布局时，建议一个项目内合理位置并将写入纳入当前范围。

使用工单原生关系表达已经确认的依赖；工具不支持时使用清晰正文引用，不声称创建了未建立的关系。已有配置足够则不重复 setup。地图的存在不要求新数据库、同步脚本或专用标签。

## 单个问题的记录示意

```markdown
# 一局结束后，哪些成果应该保留？

为何现在要决定：它会改变成长方式和重开规则。
前提：本次核心循环与体验目标已明确。
已有依据：相关设计段落、研究或原型版本。
待解决：当前具体取舍，不写成一组制作步骤。

# 结论或当前缺口

已采纳的答案与理由，或还缺哪项证据/人工判断。
实际结果的出处；明确取消、被否定或需要重开时的原因。
```

这只是示意。不创建固定状态字段，不把“探索完成”自动当作“假设成立”。版本标识来自实际资料，不为生成标识创建提交。

## 续接和分流

新会话先读地图，定位当前有条件推进的问题，再按需打开相关决定和材料。复查受影响版本与最新答复，不重读所有历史，也不凭旧摘要忽略已经变化的依据。

需要人的步骤只有在输入确实齐备时才交接；研究或制作的结果在准备阶段，不意味着可以直接请人验收。使用已有 ready-for-agent / ready-for-human 映射，具体责任在问题正文中说明，不再强制 HITL/AFK 或 research/prototype/grilling/task 标签。

任务关闭可能表示完成、取消或排除；依赖是否满足看实际结论。问题发生依赖环时，说明哪些决定相互牵连，考虑合并成一个有范围的讨论或采用明确获准的试验假设，不制造虚假的先后顺序。

## 变更与交接

更新影响当前路线的部分，保存旧依据和替代关系。新资料反驳旧决定时可以重新讨论；没有变化的结论继续使用。GDD 是现行设计，spec 是当前交付依据，地图是决策导航，三者不各自保存可独立修改的同一条完整规则。

如果 GDD 更新成功但 spec 更新失败，分别说明并回读后补缺项，不宣称整体已同步。若一个问题只产生事实而未产生新设计，不强制调用文档技能。已存在足够的 GDD/spec 时直接引用，收尾也不重新生成。

目的完成时留下可接续的依据与下一步建议，不能仅因任务数变为零就宣布无关键未知。没有决定的内容也许遗漏在地图之外；以当前目标的必要条件核对，而不是以文件数量结案。
