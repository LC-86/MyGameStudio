# Wayfinder GameStudio

找出通向当前游戏目标的路线，而不是把模糊构想提前拆成整套制作任务。地图帮助跨会话保留问题、依赖和依据；它不是关卡地图、项目总控或另一份 GDD。

地图和结论是供后续会话复用的正式资料，按技能名称取得 `writing-for-agents` 的写作方法组织，并按 [docs-gamestudio 的语义保真要求](../docs-gamestudio/references/semantic-fidelity.md)核对：指针带用途，候选、试验、已采纳、已实现、已验证各自保持身份。

## 明确目的与现状

利用当前对话、已有地图和项目资料，确认这次需要解决到什么程度、已有决定与排除范围。一个局部问题用访谈即可解决，或工作量虽大但要求已清楚时，不建立新地图，说明更直接的去向，不自动启动用户专用技能。

新目标先使用 [grilling-gamestudio](../grilling-gamestudio/SKILL.md) 与 [domain-gamestudio](../domain-gamestudio/SKILL.md) 澄清必要含义，再横向识别会影响目的的关键未知；目标已经明确就沿用。专业资料只用于发现相关问题，不因为题材或类型加入新系统。

## 建立或续接最小地图

按[决策地图](references/decision-map.md)维护目的、已有决定的摘要与引用、可明确的问题及真实依赖、尚不能具体提问的范围，以及明确不做的内容。能清楚表达的问题可以先记下，即使暂被其他问题阻塞；只有连问题边界尚不清楚的内容才留在待展开范围。

沿用项目已有工单或本地文档位置。先以短索引组织，确需独立交接或材料较长时再拆问题记录；一段完整答案只在一个权威位置维护。已有 GDD 未决部分足以承载时可复用，不为本技能造第二本账。

名称表达问题，标识与链接辅助定位。向用户说明“要决定什么、为什么影响目标”，不输出一墙编号。记录目的和关键关系即可，不强制图形、固定字段、额外类型标签或精确 token 配额。没有写入条件时交付对话草案并说明未保存。

## 推进当前关键问题

用户指定问题时核对前提，未指定时由 Agent 选择当前有条件推进、最能降低重大不确定或解锁后续讨论的问题，简述选择理由。优先处理如果错误就会推翻大量后续工作的假设，不凭编号先后或为了给每种方法分配任务来选择。

根据当前缺口使用已有方法，不新增强制任务类型：

- 缺事实或案例：使用 [research-gamestudio](../research-gamestudio/SKILL.md)，按问题选择深度、复用现有工具，不引入 pplx／专项 API 或默认付费接口。
- 缺目标或取舍：使用 [grilling-gamestudio](../grilling-gamestudio/SKILL.md)，必要时由 [domain-gamestudio](../domain-gamestudio/SKILL.md) 校准概念；不调用用户专用的组合入口来绕过调用边界。
- 必须实际操作才能判断：已有成果可用就复用；本次已授权制作实验时使用 [prototype-gamestudio](../prototype-gamestudio/SKILL.md)，玩法验证默认交付可玩的浏览器小游戏；没有制作授权就返回具体验证提议，不自动开工。
- 只差访问、材料或指定人的体验：完成可自主承担的准备，交接一个明确行动。保留人的实际判断，不以模拟反馈代替。

游戏问题的选择与反例见[游戏决策](references/game-decisions.md)。同一问题可以组合研究、讨论和原型；方法的使用不等于问题已解决。工具缺失只阻塞依赖它的部分，不能假造结果。

默认聚焦一个关键问题及必要的关联澄清，按自然决策边界更新和交接；不硬性规定每会话只能解决一题，也不把“继续”解释为无人监督跑完整张地图。有真实子代理能力且当前范围允许时，可按[委派参考](../docs-gamestudio/references/delegation.md)派发互不依赖的事实调查，给接收方当前问题和必要资料；当前负责者统一写地图，接收方不递归委派同题。没有该能力时在当前会话完成并披露限制。

## 留下结果并更新路线

记录实际依据、已经采纳的答案或尚未解决的缺口。原型已可玩但需要的体验尚未发生、研究报告已写好但关键证据不足，都不算原问题已解决。被否定的方案、主动排除的范围和成功解决的问题分开说明，不能把“关闭”一律当作依赖满足。

每形成明确结论，就重新检查相关依赖与后续问题。新证据可以使旧问题无需继续或要求重开旧决定；保留变化理由与引用，不静默抹掉旧证据，也不重做无关分支。

在已有文档授权内，按 [文档分流与增量协作](../docs-gamestudio/references/document-routing.md) 将已采纳设计交给 [gdd-gamestudio](../gdd-gamestudio/SKILL.md)，将当前具体交付或验证要求交给 [spec-gamestudio](../spec-gamestudio/SKILL.md)。地图只保留摘要和出处，不重复全文，不修改一句话讨论入口。保持候选、试验、已采纳、已实现、已验证各自含义。

## 在目的达到时交接

当会影响本次目的的关键选择已明确，且下一步无需暗中猜测重要决定时，可以结束这张地图；已明确且不影响当前目标的后续细节不必穷尽。需要的关键验证仍缺失时，标明暂停或未完成，不用列出未决项冒充已经理清路线。

回读实际保存内容，说明这轮解决了什么、现行依据在哪里，以及唯一最有价值的下一步。没有必要每次重读全部历史或重写 GDD/spec。路线清楚不等于游戏制作完成；拆票与实现由用户发起，不自动使用 `tasks-gamestudio` 或 `implement-gamestudio` 创建和执行整套制作任务。

## 范围与责任

按项目已有的 `ready-for-agent`、`ready-for-human` 及正文责任分流；标签只表示当前由谁推进，不等于授予权限或最终验收。具体准备、证据和人工交接遵循已确认的任务责任约定。将决策问题放到工单中时，明确它回答什么，不让只看标签的旧执行器把它当成正式功能制作。

只在用户实际批准的项目、文档、研究和实验范围内执行。地图 Notes 是范围的记录，不是凭据；Agent 不得通过修改自己的 Notes 扩大授权。保留已有成果，提交、推送、公开发布、删除历史、安装或付费按原有权限另行处理；只读请求不写入。
