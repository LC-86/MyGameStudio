# Merge GameStudio

解决当前冲突，保留与已确认目标相符的修改。冲突标记消失、结果已验证和 Git 操作完成，是不同结论。

1. **确认现场与范围。** 读取实际操作状态、相关提交、基线、未合并条目和已有暂存及工作区修改。没有进行中的 merge/rebase 或用户只问冲突含义时，说明情况，不创建一次操作。确认本次允许解决哪些内容，是否包含暂存和继续操作；已有明确授权直接沿用。

2. **理解双方意图。** 从共同基线、实际冲突文件、提交说明、关联任务和已确认新决定追溯原因。文档与代码不一致时披露差异，不按时间、新旧或 ours/theirs 的字面含义选边；rebase 中尤其核对实际提交身份。

3. **按内容解决。** 兼容的目标尽量保留；无法同时成立的重要规则，由已有明确目标决定，仍有分歧就呈现差异并请求最小必要决定。涉及场景、源资产、资源身份、LFS 或生成文件时，读取[游戏冲突参考](references/game-conflicts.md)。保留必要的双方版本；无法可靠处理的内容保持未解决，不用任取一边制造成功。

4. **验证组合结果。** 检查未合并条目及解决后的相关整体内容，运行当前允许且适用的检查。根据影响核对规则、场景、资源引用和运行表现，不能仅搜索冲突符号便宣称通过。保留原有问题、环境失败和本次合并引入问题的区别；大范围无关修复交回原任务。原有有效测试不因冲突被删掉。

5. **按授权结束或交接。** 只暂存本次应处理的路径；在授权包含继续操作且暂存区内容均属于本次操作时，完成当前 merge 或逐次继续既有 rebase。已有他人暂存内容会进入提交时先暂停，不自行反暂存或一并提交。继续操作可能产生提交，须遵守原授权前提。没有权限或仍有缺口就保留现场并准确报告。用户要求取消时，先核对恢复风险，在相应授权内处理，不把“永不 abort”当成原则。

不为解决冲突自动清理、丢弃或覆盖无关文件，不自动 skip 提交、reset、强推或修改全局配置。合并后的钩子、构建与测试脚本按其来源及当前权限处理，外部贡献不自动获得网络、密钥或部署权限。

返回已解决项、保留或舍弃意图及理由、实际检查、当前 Git 状态和未决项。这份结论会被调用方和后续会话读取，按技能名称取得 `writing-for-agents` 的写作方法，并按 [docs-gamestudio 的语义保真要求](../docs-gamestudio/references/semantic-fidelity.md)表达：已经解决、保留双方版本、仍未解决和检查未运行分别写明，不把建议或意图写成已执行的操作。人工体验、分支合并和代码评审不能互相代替；不自行改变任务验收结论或扩大到下一项工作。
