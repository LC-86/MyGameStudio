# 原型形态与必要保真度

这是选择实验形态的参考，不是原型类型登记表、游戏方法全集或必做流程。只使用能帮助当前问题的部分。保真度指：与答案有因果关系的条件需要保留到什么程度，不等于所有画面都做精美。

## 默认：用浏览器小游戏回答玩法问题

验证游戏玩法时，交付的是实际可玩的浏览器小游戏，不是一页对玩法的说明。HTML 是载体；是否是游戏，取决于玩家是否在执行目标玩法、规则是否处理实际输入、结果是否影响下一次行动。参数按钮和数字面板不能替代玩法，但卡牌、文字或经营游戏的界面操作本身可以就是玩法。

例如：接水果需要真实掉落和位置判断，不是“接住”按钮加分；闪避需要实际危险、输入窗口和受击或避开结果，不是切换免伤开关；推箱子需要玩家尝试移动和解题，不是点击展示几个预设状态。以上仅为示例，不授权向项目添加相应机制。

最小成果包含当前问题需要的可识别对象、实际规则和反馈。优先使用 SVG 或程序化二维美术，角色、道具和环境的轮廓、层次和状态要有一致含义。简洁的几何图形若足以表达玩法可以使用，但不能把影响目标识别的美术删掉后要求用户想象。SVG 可以是素材格式，渲染由已有或合适技术承担，不强制每个对象都是 DOM 节点。

开始界面简洁，主要视野用于游戏。短提示说明怎么操作；长说明、对照配置与调试信息按需展开。提供与验证相关的状态反馈、动作变化和必要音效，避免无关特效干扰判断。没有胜负的自由玩法不被强加倒计时、生命或关卡结算。

## 载体与必要例外

先用一句话指出当前缺少的证据，已有可用成果足够就复用。浏览器优先用于方便用户体验，不意味着把所有已有引擎场景重新移植，也不意味着原型验证了目标引擎的全部行为。

- 规则、状态、经济关系：若目的是体验这套机制，应让玩家实际选择并承受结果；仅要核对状态、公式或数据关系时，小型模拟可以是明确例外。模拟结果不能直接外推玩家长期体验。
- 操作、物理、镜头与核心交互：优先做可玩的浏览器场景，保留输入与时序；关键三维关系使用必要三维表达。问题依赖特定引擎或设备时使用相应环境，不能把二维 SVG 或桌面鼠标结论当成三维或触控验证。
- UI 布局与交互：在实际玩法或代表性游戏状态中体验。只有当问题明确限于静态视觉比较时，可视稿才足够；游戏菜单可以是 DOM，但通用仪表盘不是默认产品。
- 美术、动画、音频与可读性：选择相关镜头、背景、节奏和混音。单张截图不能验证动画节奏，资源预览不能证明游戏内正确接入。被研究的关键表现不能随便省略。
- 技术可行性与性能：样机保留相关真实接口、负载与目标条件。浏览器是方便试验的载体，不是对其他运行时的兼容与性能保证。缺少条件时说明局部结论，不能用假数据宣布正式环境可行。

每个问题只需足够的单个原型或有意义的小组，不把以上视角变成固定分支问卷。

## 易运行的交付

简单且可以可靠自包含时，交付 HTML 内嵌代码、样式和 SVG。确需现有库、模块或外部资源时，提供完整依赖和实际检查过的启动方式；不默认依赖未经说明的 CDN，不虚构在线链接，不让用户自行拼装缺失文件。使用支持的预览入口或小型本地运行方式即可，不自动引入登录、数据库和正式部署。

输出时区分已经检查的浏览器、输入与视口条件。自包含文件不等于所有浏览器都已测试；打包成功不等于实际运行。触控题需要相应设备或明确限制。音频采用用户交互后启用和静音安排，声音失败时核心玩法仍应可以体验；具体行为以当前实际浏览器为准。

## 多方案与参数比较

只有需要在候选之间判断时才增加变体。每个变体应回答真实差异，不凑数量；差异可以是操作、规则、信息组织或用户确实在比较的视觉方向，并非颜色改变永远没有价值。

为比较保持重要共同条件，明确改变的因素。若方案本身同时改变了多个要素，就报告组合差异，不把观察武断归因于某一个因素。需要时用相同初始状态、输入素材、代表性内容或交替体验顺序减少干扰；方法随问题选择，不另造完整统计实验框架。

参数控件只有帮助快速体验差异时才提供。范围和默认值来自已确认要求或明确标记的试验设定，不为了有控件而做通用数值编辑器。控制台、状态面板和调试覆盖层按需可隐藏，避免它们自身改变观察。

## 位置、数据和成本

优先复用已有足够的成果；新制作的浏览器小游戏使用项目已获准的可撤回实验位置及现有约定。新建测试场景、使用分支或工程副本都只是选择；没有授权就不能擅自切换分支、复制私密资料或覆盖共享文件。现有工程不可用时，只搭建回答问题所需的最小环境，并公开这一选择限制了哪些结论。

不默认接入生产账号、真实购买、玩家存档和线上写操作。测试持久化等必须接触相应能力时，使用隔离数据与已有许可，而不是写一句“原型不持久化”后忽略本次验证目标。

候选文件留在制作区。重要原型版本、源文件和依赖按既有版本与备份约定保留；需要工程运行的输入不能被错误忽略。压缩包或原型分支不是无限素材库；不默认将所有候选和中间导出推送到远端。

## 避免答案已经被简化掉

“最小”不能删掉决定答案的因素：研究命中识别时不能只保留一个没有反馈的数值变化；研究界面交互时不能只交静态效果图；研究多人同步时不能把另一名玩家换成永远正确的结果再宣称同步可行。

当最低限度所需条件仍无法获得，交付的是局部验证或待验证原型，不是已经证明了原设计。证据不足时可解释下一项最小验证需要，不通过多做无关功能掩盖缺口。
