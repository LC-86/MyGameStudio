# Ask GameStudio

用户不需要记住所有技能。判断他现在最应该使用哪个技能，完成哪一件事。

只提供下一步建议。为判断进行必要的只读查看，不调用下游技能，不开始实现、修改项目或发布任务。

## 看清当前处境

从当前对话中的目标、已作出的决定、正在处理的工作和最近的结果开始。用户只调用技能名称时，直接利用这些信息，不要求重新描述背景。

目标以用户当前说明为准；对影响推荐的完成状态、阻塞和执行条件，依据现有成果与检查记录判断。区分计划、尝试、已完成和未验证。

只查看会改变推荐的资料，例如用户指定的任务、相关规格、当前改动或最近的检查结果。已有信息足够就停止查看，不为选技能盘点整个项目、读取全部历史或启动检查任务。

## 选择一个技能和一件事

默认从当前已安装的 MyGameStudio 技能中选择，遵循项目明确的技能来源约定。先使用当前环境提供的技能说明；有缺口时再查看已安装的技能目录（完整安装时与本技能同级），并按需读取相关技能正文。读取正文是了解能力，不是启动该技能。

使用实际名称和已确认的调用方式。候选技能是否适用，由它的实际能力、前提和边界决定，不凭名字猜测。文件存在不等于当前宿主可调用；未确认可用、已停用或仅在草案中的技能，不当作可直接使用的入口。

用户入口只在用户明确请求相应工作时启动。这条边界写在描述与正文里，并在 Claude Code、Grok Build、DSH 与 Codex 内由宿主调用控制强制；ZCode 与 Qoder 没有宿主级开关，靠这条指令层约定。推荐用户入口时说明它需要由用户发起，不代替用户启动，也不因为推荐了就当作已经获得执行授权。

围绕当前目标，选择现在有条件推进、最能解除真实阻塞或形成必要成果的一件事，再匹配最直接的技能。多个候选都合适时，依据目标相关性、前提是否满足和工作量是否适当作出一个选择，不把候选列表交回用户。

按当前处境判断，而不是按固定流水线：

- 已确认的内容直接沿用。明确的小任务可以进入实现，不为补齐流程重新设计、写规格或拆票。
- 区分缺事实、缺决定和缺实现：调查解决事实问题，讨论解决取舍问题，实现解决已明确的工作。
- 尚未实际检查的成果不算验证通过；已发现的失败也不靠重复写完成报告解决。
- 当前工作尚未完成且原技能仍适合时，推荐继续使用该技能，不为了“下一步”强行换技能。
- 一件事可以包含完成它所必需的内部步骤，但不扩展成多个阶段、整套项目计划或多个独立任务。

直接推荐承担实际工作的技能，不推荐本技能或另一个导航技能继续选路。

## 给出可行动的答案

默认只输出以下四项，使用用户的语言：

**下一步：** 使用 `<技能实际名称>`，完成 `<当前具体的一件事>`。

**原因：** 用一两句话说明当前事实为什么支持这一步。

**完成标志：** 说明这一步应得到的成果或可观察的检查结果。

**可直接发送：** 写一段用户可以直接提交给 Agent 的调用指令，包含该技能、当前任务、必要的已有引用和范围。只引用已知的任务、路径或链接，不虚构名称、参数或权限。

这段指令会进入另一个上下文执行，接收方没有当前对话。按技能名称取得 `writing-for-agents` 的写作方法表达；无法取得时说明具体缺口和受影响的工作，只继续不依赖它的部分，不模仿缺失的方法；派发说明按 [docs-gamestudio 的委派参考](../docs-gamestudio/references/delegation.md)逐项交代目标、依据与版本、允许范围、完成证据和受阻处理，字段按本次需要取舍，引用给准确路径。只读查阅方法即可，不借此开始写入项目或启动下游工作。

答案落到用户当前的工作，不只解释技能能做什么。不展示其他候选、后续路线、完整技能目录或项目状态报告。推荐完成后停止，不代替用户执行，也不追加执行确认。

## 无法直接推荐时

只有缺失信息确实会改变选择、且无法通过允许的只读查看获得时，才问一个最关键的问题。问需要澄清的目标或事实，不让用户自己选择技能。

没有合适的可用技能，或眼下只能由用户完成试玩、作出决定或提供访问条件时，直接说明这一点，并指出唯一的下一步行动，不硬套技能、不推荐安装一批工具。用户目标已经完成且没有新的目标时，说明无需继续调用技能，不创造新工作。

无法访问的资料或无法确认的技能状态如实说明，不把未查到当作不存在，不把推测写成已确认事实。
