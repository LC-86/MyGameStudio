# Debug GameStudio

先取得能分辨当前异常的真实证据，再检验原因；修复必须回到用户原来的场景证明结果。保留 Matt 的反馈循环、最小复现、假设检验和回归思想，工作量随问题调整，不机械填写六份报告。

这是具体故障诊断方法，可以在已授权范围内修复；不是玩法设计、全库扫描或最终体验验收。只要求解释或只读分析时保持该边界；加载本技能不增加修改权限。沿用[责任、分流与交接](../tasks-gamestudio/references/task-responsibility.md)，不重新定义标签或人工责任。

## 1. 对准原问题与检查信号

利用当前对话、任务、相关规格和真实成果，区分期望行为、实际现象、发生条件与当前版本。现有失败测试、日志和录屏先复用，只补影响诊断的信息；不把所有字段都变成开场问卷。代码与资源版本、配置、场景、设备或存档只有相关时才记录；未提交改动不能只用 HEAD 代表。

先建立或复用可以重跑的检查：行为测试、引擎场景操作、输入回放、构建命令或同条件测量都可以。实际执行后确认抓到的是原问题，而非与原问题无关的依赖、启动失败或邻近错误；只出现“没有崩溃”不能代表目标行为正确。方法选择见[反馈与证据](references/feedback-evidence.md)。

已定位的简单错误可以直接沿用现有失败检查进入修复，不为使用本技能构造完整调查。困难问题尽量获得敏感、稳定且成本合理的信号；不规定必须单条命令、固定秒数或新建演示工程。

确实无法本地复现时，继续核对已取得的真实轨迹、日志和相关源码，形成可证伪的候选与所缺证据。明确证据限制；不在仅凭猜测时宣称根因已确定或修复已验证。访问不足时只交接具体缺项，不让用户代做可自行完成的调查。

## 2. 缩小复现范围

保留导致原现象的必要条件，逐步减少无关输入、资源或步骤，每次缩减后重跑。优先复用现有测试环境；确需临时验证内容时，在获准且可恢复的位置创建。

最小化是为了提高信号与缩小原因范围，不要求证明数学意义的最小。保留真实状态、生命周期或资源依赖，不能把出错链路替换成假逻辑后宣布问题消失。

间歇故障记录条件、尝试次数和失败情况；提高可观察性，而不是重跑到一次绿色。新增日志或压力可能改变时序，受控条件下的结果仍需返回原条件检查。游戏相关视角见[游戏故障参考](references/game-debugging.md)。

## 3. 用证据区分原因

根据现有证据提出少量真正有区别的候选原因，说明支持它的线索、它预测什么、怎样排除。复杂问题避免只押一个猜想；证据已经直接定位时，不为凑数编造三至五个原因。

优先采用能区分候选的低成本观察或实验，尽量一次改变一个关键因素。简短告知用户重要判断和预期，再在现有授权内继续，不逐个实验索取重复确认。怀疑来自新设计要求或需要增加访问、破坏性操作时，先处理相应决定和权限。

调试器、定向日志、性能工具、版本对比与二分定位都是可选手段，不是必经步骤。记录临时探针及改变的设置，核对证据版本；性能问题先固定场景、质量设置、设备与测量条件，不自行降低画质或改需求制造改善。工具用法和危险边界见反馈参考。

## 4. 修复并留下合适的回归保护

只有已有范围包含修复时，才修改实现、配置或资源。用户仅要求定位原因时，交付证据与建议，不顺便改正式成果。临时探针也是写入；只读请求不因调试名义扩大权限。

有能覆盖真实问题的合适入口时，在修复前把复现转成回归测试，按 [tdd-gamestudio](../tdd-gamestudio/SKILL.md) 的方法实际看失败再修复。已有有效失败测试就复用，不创建等价副本或强制重开循环；该方法尚未取得且需要使用时，通过宿主可用的调用能力或已安装路径取得正文，不凭名称声称发生了未发生的调用。

没有合适的自动测试入口时，保留可重复的实际检查及缺口；不写只验证内部假结果的浅层测试，也不为一个修复擅自重构全库。必要的架构调整交回原工作评估。源资产问题按既有来源和导出链处理，不只修补可重建缓存。

修复应满足原来确认的行为，不删除有效断言、吞掉异常、放宽容差或修改 GDD/spec 来掩盖问题。正确要求确需改变时先明确新决定，再按相应文档流程处理。临时绕过与根因修复分别说明。

## 5. 回到原场景复验并清理

重跑未简化的原场景、回归检查和当前改动影响的相关验证，恢复调试设置后再核对结果。能说明原因解释了哪些现象、实验怎样区分了候选，以及修复前后检查有何变化。

间歇故障在可比较条件下报告尝试次数与失败次数；“本轮未复现”不等于证明永久消失。已经修改但无法在目标设备复验时，标为修复待验证；纯诊断、候选原因、确定原因、临时绕过与已验证修复按事实区分，不建设额外状态机。

清理或明确隔离本次临时探针与废弃副本，保留必要的回归输入、证据和源资产版本。既有存档、未提交成果和用户文件不因清理被删除；日志、轨迹、录屏和网络抓包在展示或保存到共享位置前脱敏。

## 6. 返回证据与剩余责任

被 [implement-gamestudio](../implement-gamestudio/SKILL.md) 等当前工作使用时，返回原因、改动、实际检查及未解决部分，让调用方完成整体评审与交接；不反向启动实现流程，不自行领取下一票，也不改任务标签、关单或提交推送。

单独使用且本轮实际修复了代码时，在当前许可内使用 [review-gamestudio](../review-gamestudio/SKILL.md) 检查完整待交付修复；没有代码改动则按实际成果和任务要求检查，不制造空代码评审。评审不可用或独立性条件未满足时如实说明。评审有新发现时核对并处理相关问题，不无限全量复评。

需要开发者设备上的复现、录屏或指定体验判断时，提供适用版本、具体操作、观察目标和最小回传内容。人工复现是取证，不是最终体验批准；无人回复不表示故障消失。普通错误能由 Agent 验证时不增加人工审批。

报告只覆盖已有证据；没找到确定原因可以交付阶段结论，但不能将缺口包装成修复完成。诊断结论和回归记录会被调用方与后续会话读取，按技能名称取得 `writing-for-agents` 的写作方法，并按 [docs-gamestudio 的语义保真要求](../docs-gamestudio/references/semantic-fidelity.md)表达：纯诊断、候选原因、确定原因、临时绕过、已验证修复和修复待验证各自保持身份，原始日志与录屏保持原貌或只作明确标识的脱敏。报告位置与外部操作按用户已有授权处理，默认在当前对话或调用结果中返回。
