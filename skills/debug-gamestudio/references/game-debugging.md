# 游戏故障的按需观察视角

本文件引导选择取证方向，不是故障类型清单、必做测试集或游戏框架。只阅读会帮助区分当前候选原因的部分，检查真实项目与对应引擎版本；常见问题不等于已经确认的根因。

## 先分清“有缺陷”与“想改变设计”

按已确认规则，死亡后永久解锁消失，是可调查的实现偏差。当前规则明确扣除某类进度，但用户觉得惩罚太重，是设计取舍；先理解是否要改变要求，不能以 debug 的名义改正式规则。只有笼统“手感不对”时，先用最少的问题明确可观察现象；已经有明显延迟或错误触发就调查它，不重做整体策划。

## 生命周期、事件和持久状态

针对首次进入正常、重开后异常、连续返回叠加等现象，按实际链路观察对象创建/销毁、订阅/解除、共享状态重置和异步结果是否跨过当前场景或会话。不要只在干净首次启动下检查。观察一个真实输入到底产生了几个有效处理者和状态变化，而不是仅检查代码里写没写解除订阅。

对象池、存档和加载涉及旧状态时，保留触发问题的相关状态。不能以清空所有存档来“证明修好”。存档用已获准的副本，若项目存档包含账号或个人信息，缩减并脱敏；若确需迁移，保留恢复方式和授权边界。

## 时间、物理与输入

针对暂停后恢复错误、不同帧率下异常或偶发穿透，识别当前使用的时间来源、物理更新、输入采样、变换写入与碰撞配置。把这些当作候选关系调查，不预设任何引擎的固定执行顺序。

在真实问题路径上观察操作与结果。把运动逻辑替换成必然正确的测试函数，只能验证假设模型；修复仍须回到原场景。控制帧率或增加延迟可以帮助取证，但恢复实际条件后要复验；不能仅靠改变速度或扩大碰撞体掩盖已确认的行为要求。

## UI、动画、声音与资源链

区分底层状态是否已改变、显示是否刷新、资源是否被引用、场景实际是否触发。画面有按钮不等于输入事件到达；文件存在不等于加载的是正确版本；资源预览正常不等于游戏内使用正常。

截图可以说明可见现象，交互和时序需要相应的输入或运行证据；声音问题需要可播放结果或合适测量，不能用截图代替。二进制资源和外部源文件需要对应真实内容，LFS 指针不能代替资源本体。

检查相关源版本、导出、导入设置、资源身份和构建包含情况。真正错误位于源资产或导入约定时，按项目源与导出链修复；不把改缓存或临时构建目录当作持久修复，也不批量删除整个导入缓存来代替定位。

## 编辑器、构建与设备差异

问题只出现在某个构建或设备上时，固定原环境所需输入、版本和条件。编辑器测试可以缩小范围，但不自动覆盖发布构建、触摸输入、不同分辨率或具体设备。缺少设备时明确交接所需采集操作，不宣称已经远程验证。

性能诊断关联当前场景、实际资源、CPU/GPU/内存或加载链，按现有工具选择有区分力的指标。引擎和平台资料用对应版本的一手来源；不在知识库中写死所有项目统一的帧率、面数、贴图或内存阈值。

## 网络与异步（仅当项目存在）

当问题涉及网络或并发，区分输入、消息、超时、重试和状态版本的关系。可以在获准的测试环境重放请求或模拟延迟，但不能重放到真实付费、账号或玩家数据接口来冒险取证。离线单机问题不因为参考中有此段就引入网络测试。

## 手段不是目标

无需每次生成新原型、安装新调试软件或调用所有游戏工具。复用能覆盖原问题的现有入口；小型临时脚本或场景只在获准、确有必要时制作，并明确保留/清理位置。它们是本任务的工具，不成为 MyGameStudio 强制运行时。

## 示例：重开后奖励重复

以下是说明方法的虚构案例，不是已运行结果。

已确认规则：一次有效拾取只结算一次。现象：首次进入正常，重开后同一次拾取出现重复结算。复现要包含重开及必要状态，不能只调用奖励函数一次。

可以比较输入/碰撞是否重复、结算处理者是否重复、消费状态是否错误重置等真正有区别的候选。假设某次取证确实显示一个事件被多个遗留处理者响应，才根据实际生命周期修复；不能凭“重复结算很像重复订阅”直接确定原因。

回归检查覆盖进入、重开、再次拾取，修复后回到原工程场景，核对单次结算及相关界面反馈；必要时增加连续重开，以检查问题是否再次积累。若只有可疑代码而未取得这些证据，应报告候选原因及未验证范围。
