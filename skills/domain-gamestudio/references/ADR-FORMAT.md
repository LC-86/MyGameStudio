# 重要决策写法

仅当选择难以逆转、未来缺少背景会被误解、又确有真实取舍时单独记录。已有设计资料已经记录同一理由时直接复用。不是每次小改动、调参或词义确认都生成 ADR。

最小形式是标题和一个短段落：背景、已确认决定、理由。非显然的后果和被否决的备选确有价值时才补充。

```markdown
# 单局不提供中途恢复

为保持独立短局的体验，本项目只保存跨局解锁，不恢复中断时的局内状态。
这意味着退出后需要重新开始；相关进度保存和引导应保持一致。
```

示例不是本项目既定要求。拟议内容标明尚待采纳；当前实现与体验验证状态另行表达。

沿用现有目录和编号，没有约定时才参考 docs/adr/0001-简短标题.md。只在有实际内容时创建目录。新决定替代旧决定时注明相关记录，不把旧记录改得像从未发生；写入前核对已有用户修改。
