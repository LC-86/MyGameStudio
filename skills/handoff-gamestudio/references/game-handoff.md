# 游戏工作的交接参考

适用：下一步依赖可玩版本、工程状态、源资产、输入与存档、设备或人的实际体验。以下是选择信息的视角，不是每次必填的表格；纯策划讨论无需列完整资源清单。

## 用途决定携带内容

先说下一会话要接着讨论、制作、调试还是体验。交接的是接收者继续这项工作需要的背景，不是作者全部活动的总结。实际交接意图不明确且会影响内容/访问时，只询问必要部分。

正式规则引用 GDD/spec 或实际采纳出处，留存未落盘的重要条件与否定要求。不要为了缩短，把“死亡结束当前一局、永久解锁保留、临时能力清空”弱化成“失败后可以继续”。新需求、暂定值和实现观察各保留身份；发现冲突就注明依据，不在交接中替项目决策。

## 同一份成果，而不仅是同一个名字

按需要记录工程根或仓库身份、代码提交/分支的实际状态、原型或构建位置、源资产及导出版本。使用已有身份即可，不为交接创建提交、专用哈希或资产数据库。

有暂存、未暂存、新建或未上传资源时明确列出影响下一步的部分；分支名/提交号只描述相应已提交内容。没有携带这些实际文件，另一个环境不能被描述为已经取得最新工作。需要补丁或资源导出时提出最小转交事项，只有另有明确授权才执行，不自动复制整个工作区。

实际运行状态如编辑器未保存的场景、浏览器内存里的关卡状态、临时种子或调试条件，只有被检查过才记录；无法观察则说明未核对。手写描述不能代替保存的工程或可回放输入。

## 怎样回到同一个场景

依据现有说明记录已知启动方式、版本、目标场景及关键输入；调试时保留复现条件、已尝试的方法与结果；体验时说明需要观察的行为。使用已实际采用的命令，未运行过的建议标明未验证，不为编写交接顺便启动长构建或重新测试整个项目。

浏览器小游戏需要说明哪一份 HTML/游戏包、是否需要服务器、外部依赖和已测试的输入/设备。原机器的预览地址不证明其他机器可达；截图和录屏是辅助证据，不是可玩的游戏文件。桌面验证不是触控验证，静态预览不是交互验证。

## 源资产与备份

引用当前源版本、工程导出版本及必要的依赖取得方式。按 setup 已有约定区分 Git/LFS、工程外制作区和备份；文档中的位置不是备份已完成的证明，不承诺接收方自动获取外置素材。

仅记录本次需要的素材；大录屏、全量候选和缓存不嵌入 Markdown，也不默认上传。路径含秘密、个人标识或签名令牌时，使用安全的稳定定位与最小必要说明，不把凭据复制给下一个会话。

## 验证与人工责任

分别记录已经做过的检查、对应版本及证据、未检查部分，以及仍由指定人决定的体验或取舍。Agent 自检、开发者实际试玩、用户接受与正式交付是不同事实。

沿用任务里的责任和下一执行方；需要人判断时写清楚谁、要看哪个版本、判断什么。没有回复不是同意，“继续做”也不是接受所有体验结果。本技能不更新标签或完成勾选；只有需要把这项工作带到另一上下文时，才额外产生交接说明。

## 接收可达性和局部快照

对每个影响继续工作的引用，说明已验证源端可达、目标端待确认、材料缺失或访问受限中的实际情况，不伪称完成远端验证。相对路径说明基准根；跨机器不把本机绝对路径当作对方现成的目录。

无法让接收方立即访问某份原始资料时，优先指出需要传递的文件或权限。确需保留短摘录时，在授权与内容限制内注明出处、时间与“交接时快照”，只摘影响下一步的部分；不复制整本 GDD，也不把摘录变成新的现行规格。

## 建议输出形态

一份短说明可自然覆盖“继续目标、当前状态、依据与输入、未决与责任、建议技能”。章节按需要取舍。已有项目文件足够时，直接引用，让接收者先核对当前版本再读取细节。

“建议技能”提供实际名称及用途；目标端未安装或调用方式未确认则明确说明，不安装或擅自替换。推荐用户专用入口不是已启动该入口；需要时由用户在新会话主动发出相应调用。接收方不需要重新运行 handoff 才能读文件，否则会变成反复交接。

交接笔记是带时间范围的便携摘要，不是永久真相。原文档已经变化时核对差异，只重问影响下一步的关键冲突；不盲信旧摘要，也不以“全部重新问一遍”代替续接。任务结束后的保留按项目约定处理，本技能不自动清理。
