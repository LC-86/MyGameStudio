# TDD GameStudio

围绕已明确的行为，一次写一个能暴露缺口的测试，再实现足以使它通过的代码。测试应在以后行为回归时继续有效，不是给已经写好的实现盖一个通过章。

## 在约定的接缝验证行为

沿用当前任务、spec、项目术语和已有测试约定。明确要观察的行为、**接缝**与预期结果。接缝是观察行为而不必伸到内部去的那个公开边界：调用方或玩家能触达的真实行为接口。它不等于只能从完整 UI 测试，也不包括仅为测试暴露的内部细节。测试写在接缝上，不写在内部实现上。

范围和接缝已约定就直接执行。在已授权的实现判断范围内选择已有合适接缝，不逐个测试请求确认；需要新增接缝、引入明显成本或改变验收范围时，再用可观察的场景说明取舍并确认。没有足够依据时不臆造新架构，缺口只阻塞受影响的部分。接缝本身该放在哪里、接口应该暴露什么，属于 `codebase-gamestudio` 的词汇与判断范围。

对公共行为和测试质量的例子，读取 [tests.md](references/tests.md)；涉及时间、随机数、文件或外部系统替身时，读取 [mocking.md](references/mocking.md)；涉及游戏循环、状态恢复或资源依赖时，读取 [游戏测试参考](references/game-testing.md)。

## 一次一个红绿循环

1. 选一个当前需要新增、修复或防止回归的行为。预期值来自已确认规则、独立算例或明确的验收依据，不复制待测函数的计算来构造答案。
2. 编写一个聚焦该行为的测试并实际运行，确认失败来自目标行为的缺口。依赖缺失、语法或启动错误先处理，不能单凭这些失败宣称测试已能捕获目标错误。
3. 实现本轮需要的最小正确行为，再运行测试使其通过。不同相关断言可以共同验证一个行为，不机械限制为只有一行断言。
4. 运行受影响的已有检查；保持行为不变且测试通过时可以做必要的局部整理。更大范围的架构改造交回原任务评估，不借 TDD 扩大范围。
5. 根据已确认要求选择下一行为，重复上述过程。可以先列出少量测试意图，但不预写整套想象中的测试、随后再一次性实现。

已有正确行为补回归测试时，第一次可能已经通过：如实标为覆盖补充，不伪造红灯，不为证明流程破坏正式代码。必要时可在获准隔离验证中检查测试对已知错误是否敏感，但不把这种检查设置为每轮必做的新流程。

## 测试要能真的发现错误

通过真实公开行为操作和观察结果，避免测试私有字段、内部调用次数或实现步骤。若公开协议本来规定顺序或次数，可以测试该协议，不把协议误当成内部细节。只断言错误未抛出、资源文件存在或配置常量等于自身，不能替代任务要求的实际行为检查。

控制影响判断的时间、随机来源和初始状态；各测试独立准备输入并恢复使用过的状态。替身用于隔离外部条件，不把正在验证的规则或引擎机制替换成必然成功的假结果。

改实现来满足真实要求，不删有效断言、悄悄改预期、扩大容差或重复运行直到碰巧通过。要求本身确需改变时交回当前任务确认，并说明对测试的影响。

## 交付本次可验证的部分

使用项目实际可用、版本匹配的测试方式，不默认安装新的框架或创建演示游戏。不能运行时交付代码与明确的未验证状态，不声称完成红绿循环。边做边写最小实现属于本方法的范围；仅被要求写测试或只读检查时，不扩大修改权限。

报告本次验证了哪些行为、运行入口与实际结果、相关修改和未覆盖部分，然后返回使用它的任务。这份结果记录会被实现或验收流程读取，按技能名称取得 `writing-for-agents` 的写作方法，并按 [docs-gamestudio 的语义保真要求](../docs-gamestudio/references/semantic-fidelity.md)表达：已运行、通过、未覆盖和未运行分别写明，不把覆盖补充写成新增行为已验证。

测试通过不等于完整功能、游戏表现或体验验收通过。需要工程内集成检查或指定人的判断时，交回实现流程，沿用[责任、分流与交接](../tasks-gamestudio/references/task-responsibility.md)，不代替人确认。本技能不自主更改任务标签、关单、提交、推送或开始下一任务。
