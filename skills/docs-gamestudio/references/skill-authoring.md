# 技能与项目规则写作

编写或修订 `SKILL.md`、按需参考、项目入口规则（`AGENTS.md` / `CLAUDE.md`）时读取。通用写作杠杆在主文件里；这里只处理技能这一种文档的特有决定。

## 标准 frontmatter

本技能库只使用 Agent Skills 的标准字段，不添加宿主专属开关。

- `name`：与技能目录名一致，小写加连字符。
- `description`：技能的顶层上下文指针，常驻加载。写清适用情境、触发分支和必要边界，不承诺当前无法提供的工具。指针写法的全部规则适用：引导词前置，一个分支一个触发词，删掉正文已经承担的身份说明。
- `license`：随技能分发的许可，单独安装时这一份就是接收方能看到的全部许可信息。
- `compatibility`、`metadata`：确有需要时使用，例如记录上游来源与署名。不用于伪造能力声明。

不使用 `disable-model-invocation`、`allow_implicit_invocation` 或任何自定义调用开关，也不携带 `agents/<宿主>.yaml` 一类的专属元数据。原因见下一节。

## 用户入口与按需方法是行为边界

本技能库把技能分成两类：用户明确请求相应工作时才启动的**用户入口**，以及在当前任务与授权适用时由 Agent 组合使用的**按需方法**。

这是指令层约定，写在 `description` 和正文里，靠 Agent 阅读并遵守。纯标准技能文本不具备跨宿主的强制调用隔离能力：不能保证某个宿主不会自行选中一个用户入口，也不能保证某个 Agent 不会在未被请求时开始一个新阶段。发现宿主无法强制控制时如实披露，不重建宿主专属适配层来弥补。

因此边界要写在会被读到的地方。用户入口的 `description` 说明它对应哪一类用户请求；正文说明启动条件和不做什么。按需方法说明它在什么任务与授权下适用，以及不适用时保持安静。把边界只写在一份从不被加载的仓库根 README 里，等于没有写。

## 技能之间怎样引用

调用方式保持中性。宿主提供真实的技能调用能力时使用它；没有同名调用工具但方法文件可读时，按已安装路径取得正文和必要参考并使用。不假设宿主一定存在某个固定名称的调用工具，也不臆造标准里不存在的字段或依赖解析机制。

区分四种动作，报告时不能混用：**读取成果**（读一份现行 GDD，不启动维护它的技能）、**使用方法**（同一 Agent 取得方法后继续工作）、**委派工作**（创建独立上下文，见[子代理委派](delegation.md)）、**推荐下一步**（提示用户使用某个入口，不实际启动）。技能名称出现在正文里，不证明它已经安装，也不证明它已经执行。

跨技能引用共用资料时，指向拥有它的那一份，并说明找不到时的行为。共用资料的所有者：共同写作与文档分流归 `docs-gamestudio`，人机责任与验收交接归 `tasks-gamestudio`。完整安装后这些技能位于同级目录；选择安装时缺少的依赖按 `docs/dependencies.md` 给出的组合补齐。缺少必需方法或参考时说明受影响的能力，保留可独立完成的部分，不凭名称模仿后宣称完成，也不擅自联网安装。

## 结构决定

一份技能原则上是 `SKILL.md`，需要时附 `references/`、小型 `templates/` 和许可通知。没有需要就不凑空目录。脚本是允许的，但不是每项方法的前置条件。

按分支披露：每次执行都要用的核心方法放正文，只对部分问题适用的材料放按需参考。每个引用说明它是什么、何时需要读取。避免多层目录跳转后才看到关键内容，也避免为了压缩行数把关键条件藏进参考。

同一含义只在一处维护。技能正文不复制项目规则，项目规则不复制技能正文；易变的环境事实指向权威配置，不反复抄写。源文档、用户要求与已有格式具有优先约束，不为了整齐给所有技能套同一种章节模板。

## 许可与署名

改编自上游方法的技能保留其许可与署名，单独安装时也要能被看到：技能目录内的许可通知加上 frontmatter 的 `license`。仓库根的 `LICENSE` 和 `THIRD_PARTY_NOTICES.md` 不会随单个技能安装，不能作为唯一的许可来源。历史版本号、来源原名和许可内容允许原样保留，不做无差别全库替换。

## 验证层次

可以分别检查，前一层通过不等于后一层通过：

1. frontmatter 与目录结构是否合规。
2. 包内引用、路径、技能名称和许可通知是否真实可达。
3. 具体场景的人工走查。
4. 宿主实际发现与调用。
5. 实际产物与副作用。

行为验证要核对：该触发时能否触发；不该触发时是否安静；资料能否找到；没有授权时是否停止写入；未完成的人工项是否被保留。按实际发生的检查报告结果，不承诺零误触发。当前 Agent 在对话中推演“应该怎么做”只是走查，不标为真实模型行为测试；静态字符串检查也不替代行为验证。
