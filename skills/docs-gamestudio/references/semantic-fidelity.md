# 语义保真

改写、整理、翻译或摘要一份已有资料时读取。共同写作方法 `writing-for-agents` 负责信息层级、指针措辞、完成标准与剪枝；本文件只负责改写前后含义是否等价。

## 逐项等价

改写前后逐项核对，任一项变化都属于失真：

| 项 | 保持什么 |
|---|---|
| 数字与单位 | 数值、单位、精度和取值范围不变，不四舍五入成更好看的数 |
| 顺序 | 步骤、优先级和先后的依赖关系不变 |
| 条件 | 触发条件、前提和判定标准不变 |
| 例外与排除项 | 例外、排除项和不适用的边界不被并进主规则 |
| 责任 | 谁执行、谁确认、谁审批的身份不变，不把责任转移给读者或 Agent |
| 确认状态 | 用户已确认、待确认和从未确认保持原状，不在整理中默认通过 |
| 原始证据 | 证据不被摘要顶替或润色改意 |

原文含糊且会影响含义时，指出这里需要一个决定，不在润色中悄悄补上答案。

## 身份不升级也不合并

助手建议、试验值、已采纳设计、已实现、已验证是不同身份，分别表达，不因整理而升级或合并；候选不升成采纳，未测的不写成已验证，建议不写成决定，计划不写成执行结果。若原规则本就明确，按原文补全推导属于保真；若原规则并未确定，那是一条修改建议，要按建议提出。

## 证据与原始材料

原始日志、截图、命令输出和录屏是证据，保持原貌或只作明确标识的脱敏。围绕它们的摘要和结论使用写作方法；为了可读性改掉原始事实属于伪造。

## 游戏领域的边界

游戏领域知识是观察视角。整理参考时不把某类游戏的常见做法写成所有项目的强制规则，也不把单个项目的决定沉淀成通用要求。

## 核对方式

对关键指令走查一个适用情境、一个不适用情境，以及按需的失败或人工交接情境。检查真实路径、技能名称、引用可达性和调用声明；仅文本走查或格式检查不报告为真实模型行为测试。没有观察到收益时，不把「更短」或「少用否定句」宣传成必然更可靠。
