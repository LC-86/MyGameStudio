# 子代理委派

派发子代理就是创建一个新的执行上下文。这里是本技能库唯一的委派方法说明：主代理派发前要提供什么、接收方默认不具备什么、结果怎样核对。

## 上下文边界是否真实，取决于宿主

派发子代理会创建一个新的执行上下文，但**它是否真的与父会话隔离，是宿主属性，不是派发动作本身的属性**。

非 fork 的普通子代理通常不会获得父会话的对话历史、已读资料、已加载方法和已经形成的判断；父代理取得过一份方法，不等于子代理拥有它。但也有宿主的派发默认继承父历史，例如 Codex 的 `spawn_agent` 取 `fork_turns=all` 时，接收方看得见前面的轮次。

所以派发前先核实当前宿主怎样处理历史继承。核实不了就按不隔离对待：把材料照常给全，同时**披露**限制，不要声称接收方处在独立上下文里。任务把「独立评审」「无背景复现」当条件时，这一点决定条件是否真的满足；条件不满足就如实说明，不自行免除。

这条边界也可以被利用：把后续步骤藏在边界之后，只在真实边界上有效。同上下文内的调用把后续步骤留在窗口里，什么也没有清除；一次交接，或一次确实不继承历史的派发，才真正清除。需要防止抢跑时先确认这一点成立，否则派发并不比「再强调一遍」更有效。

技能是方法资料，子代理是执行上下文，两者不一一对应。一个子代理可以使用多份方法，一份方法也可以由当前 Agent 直接使用而不派发。

## 派发前组织这些内容

以下是检查视角，不是必填标题。短任务几句话就够；复杂任务用正文加准确、可访问的引用。

- **本次目标**：要回答什么或要产出什么，以及它服务于哪个决定。
- **来源与版本**：依据是哪份资料、哪个提交、哪个任务或哪次讨论；存在未提交内容时不能只用分支名代表。
- **可访问输入**：实际给出的路径、正文或数据。写在说明里却没提供的材料，等于没有提供。
- **允许范围**：可读还是可写，可写到哪里，是否允许运行会产生副作用的检查。
- **自主空间**：哪些选择由接收方决定，哪些必须带回来问。
- **完成证据**：怎样算做完，需要留下什么可核对的结果。
- **返回格式**：回到主代理时交什么，包括无法完成的部分怎样表达。
- **受阻处理**：材料缺失、权限不足或工具失败时做什么，而不是猜着继续。

接收方的方法和工具必须真实可用。要求它按某份方法工作时，把方法正文或可访问路径一起给出；只写方法名称是让接收方凭名字模仿。要求它运行某个命令时，先确认该命令在接收端存在。

派发格式示例，不是真实任务，实际派发时替换为确实提供的材料：

> 只检查所附宝箱成果是否满足本次规格，不修改代码、资源或任务。关键要求是首次发奖、重复开启不再次发奖，以及约定动画已实际接入。依据为所附规格和固定的本次成果版本，不从实现推导新要求。请直接检查，不重新启动双轴评审或继续派发。每项发现给出对应要求、位置或场景、证据和影响；不能观察的内容单独列出。开发者的最终体验仍待其本人确认。完成后返回主代理；材料缺失则说明缺口，不编造通过结果。

## 不递归派发

接收方直接完成分配给它的那一部分，然后把结果交回。

评审子代理完成被分配的那一轴，不重新启动整套双轴评审。研究子代理返回结论与来源，不把同一题目再派一次。事实调查子代理交回查到的内容，不据此自行采纳设计或开始制作。

需要再分工时由主代理决定，并重新按上面的检查视角组织说明。层层转发会让每一层都丢失一点范围与依据。

## 没有子代理能力时

当前环境不支持独立上下文、后台执行或并行派发时，由当前 Agent 完成其中适合的工作，并标注独立性限制。任务明确要求独立审查而条件不具备时，说明该条件仍未满足，不把顺序自查报告成独立评审。

不虚构后台任务、不承诺不存在的并行、不把推演当成实际执行。只有确实启动并取回结果的委派才报告为已执行。

## 收回结果后核对

子代理说“完成”不是验收依据。主代理核对：

- 工作是否覆盖了原目标，还是只覆盖了好做的部分。
- 声称存在或修改的文件是否真实存在，内容与描述是否一致。
- 给出的依据能否支撑结论；引用是否真的可达，版本是否对得上。
- 未完成项、未验证项和缺口是否被隐去或改写成通过。
- 是否越过了写入边界、人工判断或操作授权。
- 原始证据是否被润色改意。

发现偏差时，指出具体差异并要求补做或自行修正，不把结果原样复制进交付报告。工具边界能用宿主限制表达时用限制表达；写在派发说明里的边界不替代真实权限，运行会写缓存或存档的检查要使用获准的隔离环境。
