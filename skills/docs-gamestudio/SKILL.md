# Docs GameStudio

把已经确定的意图写成 Agent 能找到、理解、按范围执行并核对的内容。方法是本技能库的共同写作参考：包装形式随文档类型变化，写法不变，因为 Agent 每次都走同一个过程，而不是产出同一份文本。

专业技能决定写什么、写到什么范围、实际更新哪个文件；本方法保证这些内容在表达中不失真。它不重新决定玩法、不替代任务拆分或评审方法、不包办文件操作，也不成为所有文档的审批岗位。文档中的命令是待编写内容，编辑一份文档不等于执行其中的操作。

## 取得方法的时机

开始一项正式写作或一次派发前，在当前上下文取得相关方法。已经取得且仍然有效时直接沿用：一组任务不需要每张票重新取得，逐轮更新同一份 GDD 也不需要每段重载。

新的子代理上下文重新取得它需要的部分，父代理取得过不构成子代理已经拥有。本方法不递归调用自己，也不默认派发一个写作代理再派发一个审稿代理。

普通回答、已经明确的勾选、小型路径更正，为此启动完整改写流程属于浪费。只读导航类技能可以查阅本方法以写出可直接发送的指令，但不借此开启下游写入。

## 信息层级与两种负载

文档由两种内容构成：**步骤**（Agent 按序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者自由混合。核心决定是每段内容放在**信息层级**的哪一级：

1. **正文步骤**：Agent 要做什么，按什么顺序。
2. **正文参考**：同文件内按需查阅。一组平级规则并列是合理安排，不是坏味道。
3. **披露参考**：推到独立文件，由上下文指针触达，指针触发时才载入。

每份文档和指针都花费两种预算之一。**上下文负载**是常驻材料对 Agent 窗口的开销：项目规则里的一行、技能描述，无论是否触发都在花费 token 和注意力。**认知负载**是对人的开销：存在哪些文档、何时该取哪一份，人是索引。认知负载不需要最小化，它是人保留主导权的代价，花在真正需要人判断的地方。只经指针触达的材料逃开上下文负载，代价是指针自身那一行；完全没有指针的材料全部压在认知负载上。

**上下文指针**是留在上下文里、指向外部材料并编码触达条件的引用。技能描述是指针，项目规则里点名一份文档的那一行也是同一种对象。决定 Agent 何时、多可靠地触达材料的是**指针的措辞**，不是它的目标。必需材料挂在措辞含糊的指针后面是一个触发不稳缺陷：先改措辞，改不动再把材料内联。

指针做两件事：说明材料是什么，列出应当触发它的**分支**（分支是文档处理的一个独立情形，不同执行会走不同路径）。常驻指针的每个词每轮都在花费，因此要比正文更狠地剪：**引导词前置**，触发工作在指针里完成；**一个分支一个触发词**，把同一分支换说法写两遍合并掉，只留真正不同的分支；**删掉正文已经承担的身份说明**。

下推太少，顶部臃肿；下推太多，藏起 Agent 真正需要的材料。**按需披露**就是沿层级下移以保护层级，它首先不是省 token 的手段。分支是最干净的披露判据：每个分支都要用的内联，只有部分分支触达的放到指针后面。文档有步骤时，本该披露的正文参考会把步骤埋掉，让注意力变成掷硬币。**就近集中**是文件内的另一半：层级决定一段内容放在多深，就近集中决定它旁边放什么。把一个概念的定义、规则和例外放在同一标题下，读一处就带出相邻内容；分散则把一个含义碎片化到多处。**冗长堆积**是这里的失效模式：即使每行都有效且唯一，文档仍然太长，注意力在多余部分被摊薄。解药是层级：把参考披露到指针后，按分支或顺序切分，让每条路径只承担自己需要的内容。

## 完成标准与引导词

每个步骤都终止于一个**完成标准**，即告诉 Agent 工作已经做完的条件。两个属性使它成为杠杆。

**明确度**：Agent 能否分辨做完与没做完。含糊的边界（“已经理解”）招致**提前完成**——在真正做完之前结束这一步，注意力滑向“已完成”的状态。后面可见的步骤（**后续步骤**）提供拉力，完成标准的明确度提供阻力。按顺序防御：先收紧边界，这是局部且便宜的；只有当边界确实无法再明确、且你观察到抢跑时，才通过切分顺序把后续步骤藏起来。藏起来只在**真实上下文边界**上有效：同上下文内的调用把后续步骤留在窗口里，什么也没有清除；一次交接，或一次确实不继承父历史的派发，才真正清除。派发是否隔离由宿主决定（有的宿主默认把父轮次一起带过去），所以要用这个杠杆时先核实当前宿主，核实不了就按没有隔离对待，并在结果里披露。

**要求度**：这一步要求多少。“每个被修改的模型都已交代”会逼出彻底的工作，“产出一份变更清单”不会。要求度驱动**必要功课**，即 Agent 在工作内部自己挖的部分，它藏在措辞里而不是写成独立步骤；它也不限于步骤：“每条规则都已应用”同样约束一整片平级参考，这就是纯参考文档仍能携带穷尽标准的方式。最强的完成标准既可核对又穷尽。

**引导词**是已经存在于模型预训练中的紧凑概念，Agent 在运行文档时用它思考。作为词元重复，而不是作为句子重复，它积累出一个分布式定义，用最少的词元锚定一整片行为，因为它调用模型已有的先验。自己造词也可以，但要先定义清楚：造出来的词不调用先验，你要用定义 token 付掉预训练词免费给你的东西，所以先找现成的词。

引导词锚定两次。在正文里锚定**执行**：每次出现该词，Agent 都伸手去拿同一种行为；在平级参考里，它把注意力聚焦到一类要查找的东西上。在指针里锚定**触达**：当同一个词同时活在提示、文档和代码里，Agent 会把这套共享语言连到材料上，触达更可靠。主动寻找可以用引导词重构的地方：在三处分别写出的同一组属性、花一整句话去指一个概念的指针，都在等着坍缩成一个词元。“快、确定、低开销”收成**紧**；“你相信其失败的循环”收成**红**，把一个模糊的门槛变成一个二值可观察状态。

**否定**是这个杠杆旁边的失效模式：靠禁止来引导会把被禁行为拖进上下文，使它更可用而不是更不可用。“别想大象”，于是满是大象；否定是个弱修饰词，被强激活的概念冲过去，禁令有一半读成了做这件事的指令。写**正向**目标（“注释写一行”），被禁的那种就从未被说出口。只有无法正向表述的硬护栏才配得上一条禁令，即便如此也要配上正向目标，让注意力落在该做什么上。

## 剪枝

每个含义保留**唯一权威来源**：一个权威位置，改行为就是一处编辑。**重复**（同一含义出现在多处）花费维护和 token，还把这个含义在层级上的排名抬到超过它的真实位置。引导词是它有意为之的反面：重复词元，从不重复含义。

**环境**也是权威来源：构建脚本、配置文件、目录布局、`--help` 输出。重述环境的文档是一份**缓存**，即一次查询的副本，只有当查询昂贵时才值回它的负载。缓存 Agent 看一眼查不到的东西：没写下来的约定、一个选择背后的理由、配置不会承认的坑。一次打开文件、一条命令就能查到的，留给环境，那里不会过期。

逐行检查**相关性**：这一行还影响文档要做的事吗？一行失去相关性有两种方式，从未影响过任务（纯粹的说明，或本该披露的分支），或随着它描述的行为和世界变化而过期。没有剪枝纪律，文档的默认命运是**沉积**：过期内容层层淤积，因为添加感觉安全、删除感觉危险，直到你必须钻透它们才能找到还活着的部分。

逐句搜**空指令**：模型默认就会遵守的指令，付出负载却什么也没说。判据是它相对默认行为是否改变了什么，这个判据是相对模型的，不是相对读者的：两个人争论一句是不是空指令，其实是在争论默认行为是什么，靠运行文档而不是靠辩论来定。不合格就删掉整句，而不是修词。这个判据同样给引导词打分：一个弱到打不过默认行为的词（Agent 本来还算仔细时写“要仔细”）是空指令，修法是换一个更强的词，不是换一种技巧。

## 语义保真

改写前后逐项核对：数字、单位、条件、顺序、例外、排除项、确认状态和责任是否等价。助手建议、试验值、已采纳设计、已实现、已验证是五种不同身份，分别表达，不因整理而升级或合并。原始日志、截图、命令输出和录屏是证据，保持原貌或只作明确标识的脱敏；围绕它们的摘要和结论使用写作方法，为了可读性改掉原始事实属于伪造。

原文含糊且会影响含义时，指出这里需要一个决定，不在润色中悄悄补上答案。若原规则本就明确，把“Agent 自检后可以关单”补写成“存在指定人工验收项时先完成 Agent 条目并交接，人工确认前保持该项未完成”属于保真；若原规则并未确定，它是一条修改建议，要按建议提出。

游戏领域知识是观察视角。整理参考时不把某类游戏的常见做法写成所有项目的强制规则，也不把单个项目的决定沉淀成通用要求。

对关键指令走查一个适用情境、一个不适用情境，以及按需的失败或人工交接情境。检查真实路径、技能名称、引用可达性和调用声明；仅文本走查或格式检查不报告为真实模型行为测试。没有观察到收益时，不把“更短”或“少用否定句”宣传成必然更可靠。

## 委派与产出方

需要创建独立执行上下文时，先按[子代理委派](references/delegation.md)组织派发说明，并记住父代理加载过的方法不会自动出现在子代理上下文里。

编写或修订技能、项目规则和按需参考时，读取[技能与规则写作](references/skill-authoring.md)。判断一段内容归 GDD、spec、术语表还是任务票，以及增量落盘与停止条件时，读取[文档分流与增量协作](references/document-routing.md)，该约定由本技能拥有，其他技能按已安装位置引用。

各产出方的重点检查：

| 产出方 | 重点 |
|---|---|
| GDD / spec | 已采纳、候选、试验值、实现事实与验证事实分开；条件、单位、例外和排除项保留 |
| 任务票 | 新执行者能否独立看懂目标、输入、依赖、验收与交接，而不是“按之前讨论做” |
| 术语与决策记录 | 定义足以区分概念；规则和数值没有塞进词表 |
| 评审 / 研究 / 诊断 / 测试 | 结论与证据对应，推测与实际结果分开；派发说明完整 |
| 原型 | 问题、运行入口、试验条件、观察结果与采纳状态不混淆 |
| 交接 / 导航 / 决策地图 | 指针带用途；版本与访问缺口没有被摘要抹掉 |
| 结构设计 / 冲突处理 | 建议与已执行分开，未做的步骤不写成已完成 |

## 边界与返回

只修改授权目标，保留用户无关内容和原有许可署名。编写工作不增加权限：不改全局规则、不动已安装的其他技能库、不借文档名义扩大操作范围。发现其他文件需要同步时报告具体位置，在原授权内处理。

交付最小改写、重要语义变化和待确认项，并附实际检查结果。被其他技能使用时返回原工作，不把整篇重写当成必经步骤。
