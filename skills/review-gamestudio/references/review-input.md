# 取得完整且一致的评审材料

先说明“审哪一份”，再读差异。此文件是 Agent 的取材方法，不是强制脚本或不可绕过的门禁。

## 目标与基线分开

比较基线说明变化从哪里开始；目标说明实际交付哪一份内容。用户给定提交或 PR 时解析并记录实际 SHA，不把可移动分支名当作永久版本。显式指定与分支尖端直接比较，和从共同祖先比较是两种意图，不能悄悄互换。

通过实现入口评审时，沿用调用方已固定的起点和任务范围，并检查范围内的当前完整成果。只给 HEAD 而工作区还有修改，无法唯一指代成果。

没有 Git 的资源目录也可以审指定版本；无旧版本就核对当前要求，注明不能比较历史，不要求先初始化仓库。

## 按真实目标收集

Git 已提交差异、暂存区、工作区和未跟踪文件分别确认，再组织成实际待交付的成果。对同一路径要区分 HEAD、暂存版与工作区版本：审暂存提交就看暂存内容；审工作区最终成果就看对应最终版本，并标出其他状态。不能简单拼接多份差异当作一份最终文件，也不能把暂存但在工作区撤销的改动吞掉。

`git diff <base>...HEAD` 只用于相应已提交的比较，并不自动包含未提交和未跟踪内容；`git diff` 与 `--cached` 也各有自己的观察对象。具体命令查当前 Git 帮助，避免为了“看见新文件”执行 git add。状态和文件列举用于发现输入，读取具体内容才形成审查依据。

对新建文件读取完整内容；对删除项检查相关引用和行为影响；对重命名区分路径变化与内容变化。已被项目忽略的缓存不是待提交成果，但外部或被忽略的源资产若是明确交付物，应在获准范围内通过实际版本取得；不全盘扫描用户素材库。

只审本次成果。工作区中他人的改动不因可见就归本次任务；无法区分同一文件的重叠工作时暂停相关结论，保留双方内容。PR 审查不自动包含本地其他改动。

## 二进制与外部内容

二进制差异只告诉你发生变化，不直接揭示其正确性。LFS 指针只是定位信息，不是模型、图片或声音的实际数据。根据已授权环境取得相应实际对象，用已有工具检查；不可取得则披露缺口，不自动下载庞大资产集或以额外联网绕过权限。

必要时核对资源版本、源文件依赖、导入设置和相关场景引用。外部源资产使用明确版本或内容指纹，不能以“最新版”与另一份测试记录默认对应。

## 两轴一致性

将两轴实际要审的内容、范围、比较基线和规范/规格引用保持一致。小型文本可传同一份已捕获内容；大型资源可引用稳定的版本或经核对的副本。不需要强制统一 JSON 格式或产生持久数据库。

在已有许可内，使用现有版本记录、必要的校验和或临时材料固定目标。记录只有时间戳或 HEAD 时，不要声称已证明未提交工作完全不变。无法取得一致输入就披露，不假装快照原子化。

评审期间目标、要求或规范发生变化，重新定位受影响内容。已核对且未改变的证据可复用；原版本上的缺陷或通过判断不能直接贴到新版本。

## 非破坏性原则

采集不要求提交、暂存、checkout、stash 或修改业务文件。验证命令仍可能产生输出或副作用；默认复用已有可靠证据，需要执行时限定在已有授权和合适测试环境内。不会因称为“review”就获得外部调用、安装、费用或写真实数据的权限。
