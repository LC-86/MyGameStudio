# Review GameStudio

对同一份确定的成果，分别回答：**Standards，是否遵守适用规范；Spec，是否完成已确认要求。** 两轴独立检查、分别报告，不用平均分或一个笼统“通过”掩盖另一轴的问题。

这是评审方法，不是全库架构扫描、完整测试执行器或游戏总验收。范围来自当前任务；按照[责任、分流与交接](../tasks-gamestudio/references/task-responsibility.md)判断哪些条件可由 Agent 验证，哪些仍属于指定人的决定。

两轴说明和评审结论都是交给别人使用的正式内容，按 [docs-gamestudio](../docs-gamestudio/SKILL.md) 的写作方法组织：结论与证据对应，推测与实际结果分开，未能检查的部分保持缺口身份。

## 1. 固定评审对象

沿用用户或调用方给定的比较基线、任务范围和目标版本。必要信息已经明确就直接使用；只有无法从已有资料确定且会改变范围时才澄清。独立资源可以按指定版本对照要求评审，没有旧版时说明无法比较，不虚构 Git 基线。

读取[评审输入](references/review-input.md)，取得该目标实际包含的内容。实现收尾默认检查本次完整待交付成果，包含适用的已提交、暂存、未暂存、新建、删除及资源变化；明确要求只审某个提交、PR 或暂存区时，遵循该范围。排除他人的无关改动，同一路径的不同版本不能混成同一成果。

用已有提交、版本或必要的内容指纹标明实际评审对象；存在未提交内容时不能只记 HEAD。两轴使用同一份材料和依据版本，评审中有变化就暂停相关结论并重新核对。未跟踪文件、二进制与外部源资产需要取得对应真实内容；不能用空的已提交差异或 LFS 指针代替完整成果，也不为取得标识提交、暂存或切换工作区。

范围内没有实际成果就报告无可审变化。仅部分材料不可访问时，继续能够支持结论的部分，并将缺口明确列出。

## 2. 找到两轴依据

Standards：读取项目相关工程、资源、UI 或内容规范。代码部分同时采用[代码审查基线](references/standards.md)，项目适用约定优先；启发式风险不是硬性违规，不编造全行业统一阈值。

Spec：优先使用明确指定的任务与规格、相关 GDD 以及本轮已采纳变更，保留其适用范围与出处。规格是文档角色，不要求必须存在特定文件；已确认对话也可成为依据。新版要求与旧基线冲突而采纳关系不清时披露冲突，不擅自选择，更不改写 GDD/spec 使其符合成果。

不能从实现反推需求，也不把知识库建议当作已采纳要求。部分要求不可得就标出哪些无法评审；完全无要求依据时跳过 Spec 轴并说明原因，不宣称该轴通过。缺少项目规范时，代码可做明确标注的基线风险检查，不能把它包装成项目规范合规结论。

## 3. 分别评审

Standards 检查实际规范违背和有实质影响的维护风险；Spec 检查遗漏、部分实现、错误行为和未经要求的范围扩张。代码、资源、界面和游戏内表现按当前交付需要一起检查，专业视角见[游戏成果评审](references/game-review.md)，不用知识库扩充需求或另开审查类型。

有独立子代理能力时，按 [委派参考](../docs-gamestudio/references/delegation.md) 准备派发说明，将[两轴评审说明](references/axis-briefs.md)分别交给两个只读审查者，提供同一份冻结材料、各自依据及必要工具权限，并明确它们直接完成被分配的一轴即可。子代理不递归使用本方法、不继续分派或修改成果。收回结果后核对实际文件、依据、覆盖和剩余问题，不原样复制“全部完成”。

不支持独立子代理时可顺序自查，但说明没有独立上下文；任务明确要求独立审查时，该条件仍未满足，不把顺序自查报告成独立评审。

每项发现说明依据、成果位置或场景、实际观察与影响。区分已经证实的问题和需要验证的风险；推断不冒充实测。核对已有测试与运行证据的版本和覆盖，只在已有许可及非破坏性条件下补充必要检查。运行可能写入缓存、存档或调用外部服务，需使用合适的测试环境；不能为评审默认修改真实项目或用户数据。

工具已经报告的格式或类型错误可以引用汇总，不重复制造人工发现；不能因“有工具负责”就把实际失败漏掉。截图只支持能观察到的视觉结论，静态代码不证明实际手感，资源预览不证明游戏集成。无法完成的验证保留缺口。

## 4. 核对发现并返回

汇总前回看发现引用的规则与证据，纠正错误定位、夸大的影响和被误认的新旧问题；不能为了让实现通过而撤掉有依据的发现。范围外旧问题单独说明，不将其伪装成本次新增缺陷。

分别输出 Standards 和 Spec。各轴说明实际覆盖、已证实问题、必要风险与未能检查部分；没有发现时使用“在已检查范围内未发现问题”，缺依据或材料时标明未评审或部分评审。同一根因涉及两轴时相互引用，不用重复计数制造多个独立问题。

结尾只补充重要验证缺口与待人工条件。报告完成不等于成果通过；两轴均无已知问题，也不能覆盖尚未执行的检查或指定人的验收。没有人工要求、依据和证据充分时不额外制造审批。

返回发现与复查范围给调用方。实现者负责修复、自检、必要的再次评审、标签和关单；本方法不启动 implement-gamestudio 或 tdd-gamestudio 去修改成果，不改变 GDD/spec、不自动提交、推送、发布报告或关单。单独使用时默认在对话中交付，获准的报告保存另按范围执行。

修复后只复查受影响结论及必要关联，不因已修一个问题就推断全体通过，也不反复全量重评追求永远“零建议”。重要要求仍未满足时如实报告，不设固定轮数作为通过捷径。
