# 示例：接入并准备修改已有游戏

## 背景

仓库样例 **星雾漂流**（`samples/nebula-drift/`）是任务票 05 的技术夹具：已有浏览器小游戏代码、旧设计笔记和简易任务，尚未接入 MyGameStudio 目录。内容是虚构项目，不是某位用户的真实游戏。

样例 README 里的“当前请求”是：先只读分析，沿用已有任务和文档，标出实现与旧文档的矛盾，不要自作主张改设计或代码。

## 前置条件

- 已安装完整 2.0.1 插件（本示例**未**在真实客户端执行）
- 工作目录指向 `samples/nebula-drift/` 的副本，避免改脏测试夹具
- 这一轮选择 `game-init`，且声明只读

## 可复制调用文案

```text
请使用 MyGameStudio 的 game-init 分析当前游戏项目。

这一轮先只读，不修改文件。
请说明已有玩法、设计资料、工程与资源，以及接入工作流仍缺的内容。
列出建议复用、新增和需要我决定的事项，等我确认后再写入。
```

若接下来要改玩法，在分析完成后再开一轮 `game-design`，不要在同一轮既接入又改规格。

## 预期行为（示意）

助手应当能读到例如：

- `src/` 中的实际操作方式
- `docs/DESIGN_NOTES.md` 等已有文档
- `tasks/` 里的旧任务格式
- 实现与旧文档不一致之处（夹具有意包含“仅方向键/单次推进”与代码行为的矛盾）

然后给出：建议复用的文件、建议新增的 MyGameStudio 指针、必须由你决定的矛盾项。
**只读阶段不应修改样例文件。**

下面不是本环境实测日志，只是示意结构：

## 验证点

- 工作副本在只读轮后与分析前一致
- 报告区分“代码事实 / 文档声称 / 未验证”
- 没有把 `setup-matt-pocock-skills` 或接入写入标成已经完成
- 没有调用 `implement`
