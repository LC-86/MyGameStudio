# 示例：最小玩法闭环

## 背景

你已经能说出当前一局在玩什么（例如：90 秒内收集星尘、躲避障碍、时间到结算）。现在要把“还算好玩的一小段”变成可检查的工程工作，而不是先做完所有系统。

本页不附带新的游戏工程。它只提供调用顺序。预期输出为示意。

## 前置条件

- 完整插件已安装（2.0.1 真实客户端在本整理中未验证）
- 项目已完成或即将完成 `game-init` 接入
- 你知道这一轮**不**授权自动提交

## 可复制调用文案

讨论：

```text
请使用 MyGameStudio 的 game-design。
当前闭环是：一局限时收集，碰到障碍扣分，时间结束结算。
请只围绕这一段讨论必要规则与反馈，列出取舍。不要写正式规格，不要编码。
```

你拍板后整理规格（你主动调用）：

```text
请使用 to-spec，把刚才已采纳的最小闭环规则整理成规格。
未采纳的扩展玩法不要写进去。
```

范围仍大时拆票（你主动调用）：

```text
请使用 to-tickets，把这份最小闭环拆成可实际运行检查的任务。
每张票写明起始条件、操作、反馈和检查方法。
```

实现（你主动调用）：

```text
请使用 implement 实现当前可开工的第一张可玩任务。
没有提交授权，请保留未提交成果。完成后说明如何启动以及你实际检查了什么。
```

进度（只读）：

```text
请使用 game-producer 只读检查：最小闭环还缺哪张票、有没有运行入口和检查记录。
不要开始实现。
```

## 预期行为（示意）

- `game-design` 不会把“以后再做的公会系统”塞进当前闭环
- `to-spec` 只包含你点头的规则
- `implement` 给出启动方式（例如打开某个 HTML 或运行某个命令）以及实际看到的结果
- 没有运行记录时，`game-producer` 不得写“已验收”

## 验证点

- 用户专用入口都由你启动
- 无提交授权时没有新的提交
- 可玩要求停留在最小闭环，而不是全游戏内容生产
