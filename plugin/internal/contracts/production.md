# 制作技能合同

运行任一入口前采用[共同合同](common.md)。本组默认由制作实现承担;原型用途复用能力时沿原角色范围执行。

## Game-Implement

- 输入:当前任务、游戏及技术基线、材料、依赖、执行与验收约定。
- 工作:选择本任务需要的专业技能,组织独立工作,集成结果并完成约定验证及审查;反馈影响设计或范围的问题。
- 输出:本次可交付成果、必要技术设计变化、集成与验证记录。
- 写入:已授权的技术设计、正式工程与资源、专业工作记录。
- 完成:本任务实际成果满足约定;需人的事项明确等待,不接管整个项目的目标或排期。

## Game-Code

- 输入:所需行为、技术约定、现有工程、可用检查与允许修改范围。
- 工作:必要时形成或细化技术设计,实施代码变更,选择匹配风险的测试;适用时采用行为层测试驱动方法。
- 输出:代码、必要技术设计更新、运行或检查证据及遗留问题。
- 写入:获准的技术文档和代码;产品要求变化回到对应设计与统筹流程。
- 完成:约定行为得到实际验证,必要独立审查完成;未运行的检查明确列出。

## Game-Art

- 输入:当前视觉要求、用途、参考、必要尺寸或格式、输出位置和可用能力。
- 工作:按任务生成、编辑或整理图像、模型、动画、特效等资源;核对所需规格和接入情况。
- 输出:实际资源、来源或生成依据、使用信息、预览与验证结果。
- 写入:本次允许的视觉资源或原型区及记录。
- 完成:资源存在且满足已约定可核验要求;需要人的审美判断有实际反馈或保留待验收。

## Game-Audio

- 输入:声音用途、体验意图、参考、必要格式或时长、输出位置及可用能力。
- 工作:按任务制作、编辑、选择或整理音频,检查可播放性与相关规格,准备接入信息。
- 输出:实际音频、来源或生成依据、播放或接入方式与检查结果。
- 写入:本次允许的音频资源区及记录。
- 完成:实际音频与约定相符;缺少制作或验证能力时交付明确缺口,不能把提示词或说明当成已完成音频。

## Game-Build

- 输入:指定成果或工程版本、当前构建与运行约定、目标格式及可用环境。
- 工作:从项目实际配置读取运行方式,构建、导出或运行,收集日志与产物信息,检查本次约定。
- 输出:实际构建或导出产物、运行入口、验证记录与缺口。
- 写入:获准的构建输出、必要工程配置和记录;约定变化同步技术设计。
- 完成:产物与所称版本对应,约定检查有结果。上传、发布等外部动作另按用户相应授权执行。

专业产物可直接制作,也可由 Game-Implement 组织;依赖和修改范围允许时并行,集成责任必须明确。

## 包内说明

当前包不再把 Game-Implement、Game-Code、Game-Art、Game-Audio、Game-Build 作为公开技能入口。可玩任务拆分、资源接入、运行检查与反馈去向接到 Matt `to-tickets` / `implement` / `prototype` / `code-review`，公开接缝为 `records/mgs_records.py` 的 `plan_playable_delivery` / `apply_playable_delivery` / `record_playable_result`。上列旧合同保留专业产物语义，供任务字段引用，不恢复独立入口。普通工作使用宿主和项目已有工具，不经 mgs-gate。旧入口去向见[旧入口与 gate 去向](../game/retired-entries.md)。
