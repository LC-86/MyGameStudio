# 工作记录与任务后端合同

> 包内适配版(mygamestudio 0.1.0,任务票 01)。来源:插件设计仓库 `.scratch/mygamestudio-framework/contracts/records.md`。本版仅把指向未随包设计文档的链接改为文字引用,语义与设计一致;文件指纹与来源见包内 `provenance/manifest.md`。

本合同定义逻辑记录,各后端提供相同含义。角色职责、标签语义与进度判断分别采用[共同合同](common.md)和[分流规则](task-triage.md)。

## 任务最少信息

| 字段 | 含义 |
| --- | --- |
| 身份与标题 | 后端中的稳定身份、人可读名称;排序变化不重命名身份 |
| 当前目标 | 本轮目标及所属项目目标引用 |
| 基线引用 | 文档或设计条目、采用版本、必要的内容指纹或快照引用 |
| 分流 | 五类 triage 状态之一 |
| 执行责任 | Agent 或 Human,以及具体专业角色或责任者 |
| 验收方式 | 所需检查、独立审查和人工判断,附完成标准或引用 |
| 进度 | 待执行、执行中、待验收、已完成,以及必要的暂停或不再执行说明 |
| 依赖 | 真正影响开工的任务或输入 |
| 请求与结果 | 工作请求、实际成果与证据、遗留事项及后续影响 |
| 起始条件、操作、反馈、成果、检查责任 | 可玩功能任务的可演示窄路径;独立资源任务另记文件级完成条件与游戏内接入责任 |

任务字段中的角色、权限描述与完成声明是记录,不是自行授权或通过验收的凭证。运行保障与实际证据分别核对。

可玩拆票与交付的公开接缝是 `mgs_records.plan_playable_delivery` / `apply_playable_delivery` / `record_playable_result`。结果简记实际版本、启动方式和检查范围。约定试玩尚未发生时保持等待,关闭不自动等于已验收。

现行规格正文保存当前有效规则,不与任务进度混写。本地 Markdown 以整体设计文件及追加历史为规格来源;GitHub Issues 以规格 Issue 正文及评论为规格来源。讨论记录、试验值与未发布草稿不是现行规格。正式版本设计快照是归档,经 `mgs_records.plan_design_snapshot` / `apply_design_snapshot` / `read_design_snapshots` 另存完整内容;整体设计入口提供版本索引。历史快照不参与现行内容同步,也不进入任务列表。

本地 Markdown 旧项目的完整资料迁移公开接缝是 `mgs_records.plan_local_material_migration` / `apply_local_material_migration` / `read_local_material_migration`。GitHub 旧项目的完整资料迁移公开接缝是 `mgs_records.plan_github_material_migration` / `apply_github_material_migration` / `read_github_material_migration`。转换覆盖现行与历史规格、决定、全部任务、结果与证据索引,保留旧原件与身份对应;GitHub 目标恢复原生父子和阻塞关系。成果先处于待切换,旧资料仍为现行来源。只创建任务或附旧链接不算完整。gate 历史留存且不是新版权限。每项目只走所选 tracker 的入口。普通工作不经 mgs-gate。

## 本地 Markdown 后端

默认 work/<任务身份>/task.md 保存工作请求与当前任务状态;专业执行结果按需要单独放在该任务的 results/,实际证据放在 evidence/ 或使用引用。小任务允许在一个记录中分段保存,但并行写入仍由一名执行者协调。

本地写入走记录接口(`mgs_records.create_task` 等),普通工作不经 mgs-gate。分流写在「当前分流」,生命周期写在「进度」与「关闭原因」,认领写在「认领」,父子与阻塞写在工作请求字段。关闭必须注明完成、不再执行或已有成果覆盖,关闭不自动等于验证通过。重叠且无法区分的改动保留双方成果并暂停覆盖。

统筹维护请求、安排和当前状态;专业执行者保存自己的结果与证据。记录越大时按工作阶段或执行实例拆分,正文保持一处维护。

## GitHub Issues 后端

Issue 身份对应工作项;正文承载当前任务说明或规格引用,评论或相应附件承载结果与证据。五类分流用配置后的标签;执行责任、验收方式及细粒度进度保存在任务说明或规范化记录中,不扩成一套无关标签。

优先使用可用的原生父子及阻塞关系;后端不提供所需关系时采用明确且可解析的引用约定。关闭 Issue 不自动等于验证通过,需区分完成、不再执行和已有成果覆盖等原因。

本地尚未发布的基线可以供本机执行者引用,但必须标明资料位置和版本;不能声称远端执行者已可访问。准备远端交接时确认引用可达,发布资料仍需对应授权。

## 后端接口

提供读取、列出待处理项、创建、更新任务安排、追加结果、设置关系与分流、回读验证等逻辑操作。调用方只使用配置后的接口,不硬编码 .scratch/、work/ 或 GitHub。

创建或修改远端记录前核对明确的仓库及操作授权。仅选择 GitHub 后端不等于批准任意远端写入。结果不确定时用返回身份或请求关联回读实际状态,避免重复创建。

## 版本与恢复

有效要求实质变化时递增其逻辑版本。内容指纹用于发现手工修改或版本号未同步的情况;指纹变化先检查实际影响,格式修正不自动触发需求重审。正式版本设计快照按游戏版本与设计修订另存,不把设计版本写成交付标签。

请求、结果、审查与人工反馈都关联实际采用的版本。恢复时读取当前配置、任务、基线与实际成果,再处理剩余工作;缓存或旧完成标记不能替代当前核对。

## 记录与来源

每个原始观察或决定保留出处。已采纳要求进入对应当前基线;研究、讨论和替代关系保存历史。人工验收引用实际反馈,Agent 的推测或自报不作为人的验收结果。
