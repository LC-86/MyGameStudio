# 游戏专业资料：按工作阶段读取

本文件是游戏专业要求的唯一索引。各入口只指向这里，不复制一份平行清单。

**读取资料不是开始制作。** 打开本索引或其中链接，只为当前阶段补齐要求；不会因此启动讨论、拆票、实现、提交或发版。

后续票会扩充 GitHub 接入等专业行为。本索引是阶段要求的唯一副本。

## 当前阶段如何选

从项目已有地图 Notes、规格、任务和适用标准里标明的阶段引用进入；没有标明时，按本次被调用的入口选择下一节。

## 统筹与状态（Game-Producer）

读取：当前目标、进展、缺口、建议下一步。只读查询不改记录。

- 通用路由、拆票、实现、评审：用 Matt 原技能，见 [调用合同](invocation.md)
- 游戏目标与缺口：项目整体设计入口与任务记录。接入后从 `docs/mygamestudio/INDEX.md` 读取现行位置；未接入时先走 Game-Init

## 项目接入（Game-Init）

读取：已有游戏的有效设计、工程、资源，以及接入工作流仍缺的资料。

- 选择本地 Markdown 后，Game-Init 分析、建立指针、维护现行任务；GitHub Issues 接入见后续票
- 通用分流标签与领域文档布局：开发者调用 `setup-matt-pocock-skills`，本入口不另维护同义配置流程
- 游戏侧补齐指向本索引的短指针，以及现有项目中仍有效的设计/工程/资源位置；接入后项目 `docs/mygamestudio/INDEX.md` 是现行资料入口

**读取资料不是开始制作。**

## 设计讨论（Game-Design）

读取：当前闭环的玩法、数值与体验问题。

- 局部讨论复用 `grilling` 与 `domain-modeling`
- 大型不清晰路线：提示开发者主动调用 `wayfinder`，不自动串调
- 规格汇总、拆票、实现分别由 `to-spec`、`to-tickets`、`implement` 承担

## 规格（Matt `to-spec`）

读取：已采纳规则、当前闭环的可执行要求、未采纳想法保持原状。地图 Notes 与规格正文携带本阶段引用。

## 任务（Matt `to-tickets` / `implement`）

读取：交付范围、集成与检查责任、当前功能需要的资源与验证。任务记录携带本阶段引用。无提交授权时 `implement` 保留未提交成果。

## 评审与标准（Matt `code-review` 及适用标准）

读取：同一份待交付成果的 Standards 与 Spec。适用标准文档携带本阶段引用。

## 专业模块（按当前闭环按需打开）

未服务当前目标的模块不是必填清单。需要时再读：玩家体验、规则与数值、成长经济、关卡内容叙事、操作界面引导、美术动画声音、技术设备性能、持久状态恢复、商业化发行运营。
