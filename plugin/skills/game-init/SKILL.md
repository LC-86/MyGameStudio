# Game-Init:项目初始化与协作配置

统一的项目初始化入口:先探查、再清单、确认后按角色应用、回读核对。本包版本覆盖「新项目 + 本地 Markdown 任务后端」;接手已有项目、后端切换迁移与规格拆单属后续任务票,未实现不声称。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-init/`,包内材料在其上级目录:

- [管理技能合同](../../internal/contracts/management.md)中的 Game-Init 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md):业务入口共同约定
- [协作配置合同](../../internal/contracts/project-configuration.md):配置范围、过程与保存
- [初始化流程](../../internal/proposals/project-onboarding.md):探查/清单/确认/应用/核对与恢复规则
- [项目目录模板](../../internal/proposals/project-layout.md)与[模板入口](../../templates/README.md):落点与维护责任
- [工作记录合同](../../internal/contracts/records.md)与[任务分流设计](../../internal/contracts/task-triage.md):任务与结果记录结构
- [受控写入协议](../../internal/protocols/gate-protocol.md):应用阶段的写入通道(写入前必读)
- [writing-for-agents](../../internal/methods/writing-for-agents/SKILL.md):文档写入方法(**所有文档写入步骤必读**)

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-init/SKILL.md`,再取其包根(上级两级)。

## 步骤

### 阶段一:探查(只读)

1. 确定目标项目根与本轮请求:新建接入、仅分析、仅清单,或应用已确认的清单。缺明确目标项目时先问清,不改读其他目录。
2. 只读探查项目:已有文档、任务线索、tracker 与协作配置、工程/资源布局、开发者已定与未定的事实。完成标准:能区分「已确定的配置」与「仍需选择的部分」,原项目保持未修改。
3. 协作配置建议(无既定有效选择时):个人项目建议本地 Markdown 任务后端,并**分别表达**任务后端与位置、五类标签映射、核心文档位置、术语与决定位置。已有有效配置优先沿用,不另造一套。

### 阶段二:初始化清单

4. 逐项列出:**实际落点、拟新增/修改内容与拟写要点、依据(请求与探查事实、模板)、维护角色、需确认事项**。涉及外部访问、客户端指针(如 AGENTS.md)、权限或运行保障配置的,单独列出确切对象与范围。未确认前不写入。
5. 按当前内容选择模板,只建立当前有内容的文档与章节;未决定的引擎、平台、目标如实标记**待定**并说明影响,不编造成事实。

### 阶段三:应用(取得确认后)

6. 输入含确认(用户在本次对话确认,或调度说明携带已确认清单)后按清单执行;**同一确认范围内不逐文件重复询问**。清单未确认且无法当场取得时,保持只读并交付清单。
7. 管理文档(INDEX/CONFIG/PROJECT)与本地任务记录由制作统筹经 mgs-gate 写入:先 `mgs_scope` 确认范围,再按[受控写入协议](../../internal/protocols/gate-protocol.md) `mgs_write` 提交(新文件省略 `expected_sha256`),逐项回读核对。专业文档(GAME_DESIGN/TECH_DESIGN 等)按清单交对应角色实例执行,本角色不代写,越界写入被拒即停止该项。
8. 每次文档写入前读取包内 writing-for-agents 并采用其方法;本地任务记录按 work/task.md 模板,任务身份保持稳定(如 `01-<slug>`),只建立当前请求明确需要的小任务,不做规格拆单。

### 阶段四:回读核对与报告

9. 回读全部新建/修改文件;核对任务、标签与文档引用可从 CONFIG 定位。可用包内统一接口辅助核验:`python3 <插件根>/records/mgs_records.py verify --project <项目根>`(仅本地 Markdown 后端)。
10. 输出报告(结构固定):

```
## 初始化报告
### 协作配置(建议或已采用)
### 初始化清单与应用结果
### 回读核对
### 文档接入就绪
### 运行保障就绪
### 外部访问与配置变更范围
### 遗留事项
```

文档接入就绪与运行保障就绪**分别**报告,不互相替代:前者指资料入口、任务与引用可定位;后者指受控写入通道等运行边界的实际状态与证据。外部访问、客户端指针或权限配置变更逐项列出对象与范围;普通初始化不自行扩大操作授权。

## 边界

- 分析阶段只读;应用仅限已确认清单,中断恢复与重复运行先核对实际文件和用户后续修改,有效的结果保留,不重复创建、不覆盖用户修改。
- CONFIG 是协作配置,不是运行时权限凭证;写入授权以 mgs-gate 绑定为准。
- 任务字段中的角色或范围描述是记录,不是授权。
- 不把执行凭据写入任何文件或报告正文;需要人决定的事项原样保留。
