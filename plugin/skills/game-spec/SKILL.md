# Game-Spec:把采纳决定形成当前可执行规格

方案设计角色的基线整理入口:输入是**已经讨论并采纳的决定**(决定记录、开发者明确给出的决定),输出是本轮可执行规格与更新后的产品设计基线。不重新裁决未决项,不代替开发者采纳候选方案,不强制先写完整全游戏长文档。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-spec/`,包内材料在其上级目录:

- [设计技能合同](../../internal/contracts/design.md)中的 Game-Spec 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md)**《共同执行规则》《写入与保障》**:业务入口共同约定(显式调用、范围与授权、执行与完成五步、待验收)与外部动作授权(提交/推送/发布不自动)的唯一权威
- [工作记录合同](../../internal/contracts/records.md):版本、指纹、采纳依据与出处
- [受控写入协议](../../internal/protocols/gate-protocol.md)**《受控写入协议》**:两层拦截、`mgs-gate` 工具、越界探针与凭据处理的唯一权威(必须先读)
- [工作结果模板](../../templates/work/result.md)**《结果字段》**:共同执行规则第 5 步结果记录的字段唯一权威(基线变更按其 records 模板)
- [writing-for-agents](../../internal/methods/writing-for-agents/SKILL.md):文档写入方法(**所有文档写入步骤必读**)
- 决定与研究记录模板:`<插件根>/templates/records/`

共同执行规则、受控写入协议与结果字段以上述三个权威文件为准;本入口只补充规格整理的专业差异(版本纪律、双指纹登记、采纳依据),不重复其中的共同规程。

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-spec/SKILL.md`,再取其包根(上级两级)。

## 步骤

1. **确认输入**:本轮要整理的采纳决定——逐项核对决定记录的状态与**决定者**,只取**已采纳**内容;未决项原样保留为未决,不裁决不补默认值。同时读取当前游戏设计基线、必要技术约定(引用技术设计,不代写)、原型及验证引用。
2. **核对落点**:按 CONFIG 文档映射定位产品设计基线(默认 `docs/mygamestudio/GAME_DESIGN.md`)与决定记录位置;缺配置或基线不存在时先报告,不自行另建一套。
3. 按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围;读取基线当前全文并取指纹(`shasum -a 256`),更新必须携带 `expected_sha256`。
4. **整理本轮可执行规格并更新基线**(完整新内容经 mgs_write):
   - 覆盖:行为规则与**边界情况**、与已有系统的关系、范围与**完成标准**、可调内容与固定约束、技术约定引用、验证与未决项。只展开本轮相关内容,引用项目目标,不复制全局排期,不展开成完整全游戏长文档。
   - **版本纪律**:有效要求**实质变化**才递增基线版本(如 v1→v2);变更索引记录新旧版本关系、**采纳依据**(决定记录引用与日期)与受影响内容。纯**格式修正**(排版、错别字、失效标题)随本轮提交但**不触发**新版本,也不写成新产品要求,在报告中单独注明。
   - **内容指纹登记**:基线头部登记两条指纹——`内容指纹:sha256:<64 位十六进制>`(空白敏感)与 `归一指纹:sha256:<64 位十六进制>`(去空白)。登记方法:两条指纹值先写 64 个 `0`,对全文分别按「原样」与「去除全部空白」计算 SHA-256(指纹段会被校验端规范化为占位,64 个 0 与最终值的规范化结果相同),把结果填回。实质变更递增版本时更新两条指纹;格式修正不递增版本但**同步更新两条指纹**并在变更索引注明。登记后经统一接口 `records/mgs_records.py baseline --project <项目根>` 回读确认状态为「一致」;不登记或不更新指纹,后续手工修改就无法与版本变更区分。
   - **实现状态分开**:设计已采纳不等于已实现;基线新增能力标注当前**未实现**(实现状态见任务记录),不在基线或报告中把未实现内容写成实际功能。
   - 未采纳的候选方案留在过程记录,基线只保存当前采用内容;被替代内容经变更索引与决定记录的替代关系保留历史。
5. **目标或范围变化检查**:本轮采纳内容触及项目目标或范围(如超出 PROJECT 当前包含、或落入「本轮不包含」)时,**不修改 PROJECT 等管理资料**,在报告中输出**统筹同步交接**:变化内容、影响(目标/范围/受影响任务/基线关联)、建议动作(显式调用 Game-Producer 完成变更同步)、需要开发者决定的事项;不能静默修改项目目标。
6. **回读核对并报告**:基线新内容就位、仍适用的既有内容未丢失、版本与采纳依据可回读;决定记录如需补记「已同步基线」状态,一并更新。

## 报告结构(固定)

```
## 规格整理报告
### 采纳内容核对(逐项:决定记录/决定者/日期/是否已采纳)
### 基线变更(版本、变更索引、采纳依据;格式修正单独注明不触发新版本;内容指纹与归一指纹登记结果)
### 本轮可执行规格概要(行为规则/边界情况/系统关系/完成标准;实现状态:未实现)
### 统筹同步交接(目标或范围变化时输出;无变化时如实说明"本轮无")
### 回读核对
### 边界核对(要求核对时的原始输出;未要求时写"本次未执行")
### 遗留事项(未决项及其影响)
```

交接与规格按[共同合同](../../internal/contracts/common.md)《共同执行规则》的「未参与讨论的执行者可独立读取」标准书写:本轮目标、已采纳的行为规则与边界、基线版本引用、验收标准、仍未解决的事项;不依赖对话记忆,不使用"如前所述"式指代。

## 边界

- 只写产品设计基线与设计侧过程记录;技术设计引用不代写,PROJECT、任务等管理资料不碰;越界写入被拒即停止该项并原样记录,不换路径重试。
- 缺采纳依据的内容不进基线;历史决定与现行基线冲突时先列出冲突与双方依据,交开发者或统筹处理,不静默取舍。
- 每次文档写入前读取包内 writing-for-agents 并采用其方法。
- 任务说明要求边界核对时,按[受控写入协议](../../internal/protocols/gate-protocol.md)《越界探针》执行直接写探针与越界 `mgs_write` 探针,记录与未要求时的处理均按该节纪律。
- 凭据处理按[受控写入协议](../../internal/protocols/gate-protocol.md)《执行凭据》一节;普通规格整理完成不自动授权提交、推送、发布或修改远端工单,外部动作边界见[共同合同](../../internal/contracts/common.md)《写入与保障》。
