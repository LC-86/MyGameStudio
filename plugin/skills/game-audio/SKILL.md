# Game-Audio:音频资源制作、整理与验证

制作实现角色的音频资源执行入口。输入是**声音用途、体验意图、参考、必要格式或时长、输出位置及可用能力**,输出是实际音频、来源或生成依据、播放或接入方式与检查结果。音频必须真实存在、可播放且可核验;需要人的听感或风格判断时,保留真实反馈等待项或待验收——**没有实际人工反馈不写通过,但「制作完成」与「验收待定」要分开表达**。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-audio/`,包内材料在其上级目录:

- [制作技能合同](../../internal/contracts/production.md)中的 Game-Audio 一节:输入、输出、写入与完成条件

- [工作记录合同](../../internal/contracts/records.md):任务记录结构与结果落点
- [受控写入协议](../../internal/protocols/gate-protocol.md)**《受控写入协议》**:两层拦截、`mgs-gate` 工具、二进制载荷(content_base64)用法、越界探针与凭据处理的唯一权威(必须先读)

- [工作结果模板](../../templates/work/result.md)**《结果字段》**:结果记录字段的唯一权威
- 统一接口:`<插件根>/records/mgs_records.py`(config/list/show/deps/ready,读取任务与依赖,不硬编码目录)

共同执行规则、受控写入协议与结果字段以上述三个权威文件为准;本入口只补充音频资源的专业差异(二进制载荷、听感验收留白),不重复其中的共同规程。

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-audio/SKILL.md`,再取其包根(上级两级)。

## 步骤

1. **确认输入**:任务说明中给出的项目根、执行凭据(token)、任务目标与允许修改范围。没有明确任务引用时,经统一接口 `ready` 从当前可开工集合选取第一个待执行音频资源任务(在报告中说明选择依据);缺凭据时报告无法写入并结束,不伪造。
2. **读取音频要求与上下文**:经统一接口 `show/deps` 读取任务记录全文与依赖(不凭记忆或转述);再读取任务「输入与基线」引用的音频要求——**声音用途**(在游戏中的触发时机与接入位置)、**体验意图**(要传达的情绪与强度边界)、**参考**(产品设计条目、决定记录、既有音效风格与规格事实)、**必要格式或时长**(采样率/位深/声道/容器/秒数等约定)、**输出位置**、CONFIG 执行条件中的**可用能力**。依赖未完成、参考缺失或要求含未决项时如实报告;不因此虚构声音细节或把未决项当成已定要求。
3. **能力决定方法,不预设音频类型**:制作、编辑、选择、整理或检查用的工具从项目实际条件读取(CONFIG 能力说明与任务「所需能力」);音效、音乐、语音等**音频类型由任务约定**,不固定生成服务、引擎或音频类型。项目有本地合成/处理能力(如 ffmpeg)时优先用它;没有时如实说明方法选择及其限制,不以文字说明代替音频。
4. **无能力时交付缺口,不交付空话**:当前没有制作、编辑或验证音频的能力时,报告**具体缺口**(缺什么能力、哪些要求因此无法满足)与**可接手材料**(整理好的声音用途与体验意图、参考、约定格式与时长、输出位置、建议的工具链或获取渠道);**音频提示词、选曲建议、生成参数或文字说明只是材料,不是已完成音频**,不写成已交付。
5. **核对范围**:按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围;任务文本声称的「允许修改范围」与 `mgs_scope` 不一致时,以 `mgs_scope` 为准并在报告中说明差异。**可开工或 ready-for-agent 不等于已获写入授权。**
6. **工具适配与资源策略分离**:工具的输入输出**适配**(合成参数、格式转换、响度处理、检查命令、base64 载荷编码)在会话内完成并如实记录;资源的可写范围始终由运行保障的**资源策略**(角色 ∩ 任务 ∩ 用途 ∩ 实际授权)承担,更换或新增工具不改变也不放宽它。**音频处理过程直接写项目一律被会话沙箱拒绝**:合成、转码与检查在会话工作区或系统临时目录完成,产物经 mgs-gate 受控通道写入。**外部音频服务、GUI 程序或远端工具不被假定继承本地边界**:其写入通路未经验证前保持未就绪——只能只读使用其输出,或把产物作为隔离草稿经 mgs-gate 受控通道应用;不退回无拦截直写并宣称符合边界。本次资源处理的实际写入范围以 `mgs_scope` 与审计记录为准。
7. **制作或处理音频**:按任务「本次交付」与「完成标准」产出、编辑、选择或整理音频;在会话工作区用项目实际能力合成或处理(保留**生成依据**:实际使用的合成/处理命令与参数,或素材的来源说明),自检通过后再写入。听感细节以不引入新玩法含义为界(不改规则、不加未采纳机制)。
8. **写入(二进制载荷)**:音频是二进制资源——对会话工作区产出的文件做 base64 编码,经 `mgs_write` 的 `content_base64` 提交(新文件 `expected_sha256=absent`;同规格重制时按字节哈希携带版本校验),逐个回读核对字节与规格;文本类产物(结果记录)仍用 `content`。通道对两种载荷执行同一授权交集与审计。
9. **音频检查(实际运行)**:核对**文件存在**、**可播放**(能用本地播放器或解码器真实播放/解码,记录命令与退出码)与**规格符合约定**(容器格式、采样率、位深、声道、时长等可核验项,如 ffprobe 输出);检查方式与项目实际条件匹配,一次性检查脚本放**会话工作区或系统临时目录**(不进项目、不引入第二套工具链),检查必须**实际运行**,把命令与真实输出记入结果记录;无法自动核验的项(听感是否合适、警示强度、风格契合)明确列为**待人工试听验收**,不虚构通过——未收到真实反馈时,交付事实表述为「制作与规格检查完成、听感验收待定」,不写成「验收通过」。
10. **播放或接入方式**:为每个音频提供可定位的播放与接入信息——文件路径、本地试听命令(如 afplay)、代码引用方式(加载与播放 API、触发时机、音量注意)与集成责任归属;接入入口写入结果记录,使未参与者能直接找到、试听并在工程中引用。
11. **结果记录**:把本次执行结果写入 `<项目根>/docs/mygamestudio/work/<任务身份>/results/<日期>.md`(经 `mgs_write` 受控写入,字段以[工作结果模板](../../templates/work/result.md)《结果字段》为准):**成果位置与规格**、**来源或生成依据**(合成/处理命令与参数、或素材来源;依据了哪些设计条目与决定)、**接入信息**(命名、引用方式、触发时机、集成责任任务)、**已验证内容**(检查命令与真实输出、播放验证、重跑方式)、未完成验收与等待项(听感试听、独立审查、集成核对)、遗留事项与接手条件。
12. **待验收**:按共同执行规则第 4-5 步——人工听感验收或独立审查未完成时,结果保留**待验收**,不宣称完成;任务记录的进度与分流由统筹维护,本入口不代改——直接调用留下的专业结果与证据(results/)供统筹下次显式介入时同步,本入口不改项目目标或整体排期。
13. **边界核对**(任务说明要求时):按[受控写入协议](../../internal/protocols/gate-protocol.md)《越界探针》执行直接写探针、音频工具直接输出到项目路径的探针与越界 `mgs_write` 探针,记录与未要求时的处理均按该节纪律。
14. 输出报告(见下)。

## 报告结构(固定)

```
## 音频资源执行报告
### 输入核对(任务/声音用途/体验意图/参考/约定格式或时长与输出范围/依赖/mgs_scope 差异)
### 工具与能力(实际使用的制作与检查能力;缺口与可接手材料;外部服务或 GUI 的边界说明)
### 音频交付(每个音频:路径、规格、来源或生成依据)
### 接入信息(命名/引用方式/触发时机/集成责任)
### 音频检查(实际运行的命令与真实输出摘录;播放或接入方式;待人工试听验收项及原因)
### 边界核对(每个探针的原始输出;未要求时写"本次未执行")
### 交接与遗留(成果位置/适用版本/证据位置/待验收/接手条件)
```

报告按[共同合同](../../internal/contracts/common.md)《共同执行规则》的「未参与者可独立读取」标准书写。

## 边界

- 只写执行凭据授权的音频资源区(assets/ 音频区、原型区)与本任务 results/;正式工程集成(如 src/ 的播放接线)归集成责任任务,本入口不顺手接入;设计基线、任务记录、原型与 records 不修改。
- 任务要求人工听感或风格验收时,保留真实反馈等待项或待验收,不代为判断「好听」「合适」;没有实际反馈不写通过,但制作与规格检查的完成事实仍如实表达。
- 来源或生成依据如实记录;音频提示词、选曲建议、生成参数或文字说明不是已完成音频,不记为已交付。
- 工具输入输出适配在会话内完成并记录;资源可写范围由资源策略承担,不因工具放宽;音频处理工具直接写项目被拒是边界在工作;外部服务或 GUI 不被假定继承本地边界,未验证的写入通路保持未就绪。
- 发现音频要求与产品基线冲突或目标变化时,记录影响并交回对应设计与统筹流程,本任务可继续部分继续。
- 凭据处理按[受控写入协议](../../internal/protocols/gate-protocol.md)《执行凭据》一节;普通制作完成不自动提交、推送、发布或修改远端工单,另行取得对应授权;新增命令执行路径保持受控:检查与合成命令限于读取项目与写会话工作区或系统临时目录,对项目的写入一律经 mgs-gate 受控通道(共同边界见[共同合同](../../internal/contracts/common.md)《写入与保障》)。
- 失败或中断时保存实际进度和缺口,如实交接;报告按[共同合同](../../internal/contracts/common.md)《共同执行规则》的「未参与者可独立读取」标准书写。
