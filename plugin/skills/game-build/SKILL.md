# Game-Build:构建、运行与导出

制作实现角色的构建执行入口。输入是**指定成果或工程版本、当前构建与运行约定、目标格式及可用环境**,输出是实际构建或导出产物、运行入口、验证记录与缺口。产物必须与所称版本对应、入口可启动、检查有真实结果;**只存在文件不等于本次构建成功**。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-build/`,包内材料在其上级目录:

- [制作技能合同](../../internal/contracts/production.md)中的 Game-Build 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md):业务入口共同约定(含执行与完成五步)
- [工作记录合同](../../internal/contracts/records.md):任务记录结构与结果落点
- [受控写入协议](../../internal/protocols/gate-protocol.md):两层拦截、mgs-gate 工具、文本与 base64 二进制载荷用法与写入步骤(必须先读)
- [writing-for-agents](../../internal/methods/writing-for-agents/SKILL.md):文档写入方法(写结果记录前必读)
- [工作结果模板](../../templates/work/result.md):结果记录字段参考

## 步骤

1. **确认输入**:任务说明中给出的项目根、执行凭据(token)、任务目标与允许修改范围。没有明确任务引用时,经统一接口 `ready` 从当前可开工集合选取第一个待执行构建任务(在报告中说明选择依据);缺凭据时报告无法写入并结束,不伪造。
2. **读取构建与运行约定**:经统一接口 `show/deps` 读取任务记录全文与依赖(不凭记忆或转述);再读取任务「输入与基线」引用的约定——**指定成果或工程版本**(构建对象与源版本)、技术设计中的**构建与导出约定**(产物目录、入口、组装或工具方式、版本对应与运行检查方式)、CONFIG 执行条件中的**可用环境**(本机可用的构建、服务与检查能力)。依赖未完成、约定缺失或要求含未决项时如实报告;不因此虚构构建方式或把未决项当成已定约定。
3. **从项目实际配置确定方式,不硬编码平台**:构建、导出与运行方式**从项目实际配置读取**(技术设计的构建约定、CONFIG 执行条件与任务「所需能力」),并明确**输出格式及环境**(静态网页目录、可执行包或其他项目约定形态;运行环境如现代浏览器、本地解释器)。**不硬编码某个引擎或发布平台**——组装复制、专用构建工具或导出管线由项目约定决定,不在本入口内假设;样例项目的构建选择不成为框架默认方式。项目尚无构建约定时,报告缺口并把约定问题交回制作实现的技术设计与统筹流程,不擅自发明约定并当成项目约定执行。
4. **缺能力或缺依赖时交付缺口,不交付空话**:缺少构建、运行或检查所需的依赖、工具或环境时,报告**具体缺口**(缺什么、哪些要求因此无法满足)与**可接手材料**(整理好的构建对象版本、目标格式、建议的构建方式与环境要求);提示词、构建计划或未执行的命令只是材料,**不是构建产物**。
5. **核对范围**:按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围;任务文本声称的「允许修改范围」与 `mgs_scope` 不一致时,以 `mgs_scope` 为准并在报告中说明差异。**可开工或 ready-for-agent 不等于已获写入授权。**
6. **构建脚本与子进程在已验证边界内工作**:构建、组装、打包或导出用的脚本及其**子进程**在**会话工作区或系统临时目录**运行,对项目**只读**;**直接写项目一律被会话沙箱拒绝**(构建工具的输出也不例外),不尝试绕过。产物在会话工作区成型、自检通过后经 `mgs_write` 写入**获准的构建输出区**(文本产物用 `content`,二进制产物用 `content_base64`,更新已有产物携带 `expected_sha256`),逐个回读核对。工具的输入输出**适配**(参数、路径布局、载荷编码)在会话内完成并如实记录;可写范围始终由运行保障的**资源策略**(角色 ∩ 任务 ∩ 用途 ∩ 实际授权)承担,更换或新增工具不改变也不放宽它。**外部构建服务、发布工具链或 GUI 不被假定继承本地边界**:未经验证的写入通路保持未就绪。构建过程需要调整工程配置或构建约定时,变更经 `mgs_write` 写入获准的技术设计并**保留技术依据**(为什么变、对应哪个要求);约定变化同步技术设计,不静默偏离。
7. **产物与源成果版本对应**:构建完成后核对并登记每个产物文件与其源文件的**版本对应**(如 SHA-256 哈希对照)及源成果版本(工程文件当前版本、所依据的任务成果);产物内容与本次源版本核对一致才算**本次构建成功**——**失败、缺依赖、入口不可用或产物区只有旧产物(与当前源版本不对应)时如实报告,不把存在文件等同于本次构建成功**。
8. **运行检查(实际运行)**:按约定**启动约定入口**(浏览器直接打开、本地静态服务或项目约定的其他方式),能自动核验的项**实际运行**并记录命令与真实输出——入口可达(如本地静态服务取回入口页与脚本)、引用可解析(入口引用的本地文件都存在于产物区且内容一致)、无头冒烟(如 node DOM 桩加载产物脚本,核对初始化与核心行为可观察);日志与退出码记入结果记录。一次性检查脚本放**会话工作区或系统临时目录**(不进项目、不引入第二套工具链)。无法自动核验的项(真实手感、体验流畅度)**列待人工试玩验收**,不以自动检查替代;入口不可用或运行失败时如实报告,不虚构通过。
9. **外部动作边界**:普通构建**不自行上传、签名发布、部署或购买服务**,也不自动提交、推送或修改远端工单;需要这些外部动作时,在结果记录与报告中**列明准确目标**(上传到哪里、发布什么版本)并等待用户对应授权,不代为执行。
10. **结果记录**:把本次执行结果写入 `<项目根>/docs/mygamestudio/work/<任务身份>/results/<日期>.md`(经 `mgs_write`,按[工作结果模板](../../templates/work/result.md)字段):**产物位置与清单**(入口、文件列表)、**版本对应**(产物↔源文件哈希对照、源成果版本)、**构建方式与命令**(实际执行的组装/构建命令与日志摘录)、**运行入口与检查证据**(启动方式、命令与真实输出、重跑方式)、**缺口与等待项**(未完成验收、待外部动作清单、遗留事项与接手条件)。
11. **待验收与结果读取**:任务约定的独立审查或人工试玩未完成时,结果保留**待验收**,不宣称完成;本入口**不启动完整试玩流程**(归 Game-Playtest 与人工验收),交付的专业结果(产物、入口、版本对应、检查证据)供统筹同步、Review 独立审查、Playtest 试玩与后续集成任务读取。任务记录的进度与分流归统筹维护,本入口不代改——直接调用留下的结果与证据(results/)供统筹下次显式介入时同步,本入口不改项目目标或整体排期。
12. **边界核对**(任务说明要求时):按给定清单执行直接写探针、构建工具直写项目探针与越界 `mgs_write` 探针,原样记录退出码、错误信息与工具返回,不尝试绕过或换路径重试。
13. 输出报告(见下)。

## 报告结构(固定)

```
## 构建运行执行报告
### 输入核对(任务/指定成果或工程版本/构建与运行约定/目标格式与环境/依赖/mgs_scope 差异)
### 构建与运行方式(来自项目实际配置的确定结果与依据;缺口与可接手材料;外部服务边界说明)
### 构建交付(产物位置与清单;每个产物与源文件的版本对应;构建命令与日志摘录)
### 运行入口(启动方式;实际运行的检查与真实输出摘录;待人工试玩验收项及原因)
### 外部动作(需要且未执行的外部动作及准确目标;无则写"无")
### 边界核对(每个探针的原始输出;未要求时写"本次未执行")
### 交接与遗留(成果位置/适用版本/证据位置/待验收/接手条件)
```

报告按「未参与者可独立读取」标准书写,引用实际任务身份与基线版本,不依赖对话记忆。

## 边界

- 只写执行凭据授权的**获准构建输出区**(如 build/)、获准的技术设计(约定变化时)与本任务 results/;不修改 src/、assets/ 源文件、设计基线、原型与其他任务记录——正式工程集成归集成责任任务。
- 构建脚本及其子进程在已验证边界内工作:会话工作区或系统临时目录运行、对项目只读,输出只写获准位置;产物经 mgs-gate 受控通道进入项目;构建工具直接写项目被拒是边界在工作。
- 产物必须与所称源版本对应;只有旧产物、入口不可用或检查失败时如实报告,不把存在文件等同于本次构建成功。
- 普通构建不自动上传、签名发布、部署、提交推送、购买服务或修改远端工单;需要外部动作时列明准确目标并等待对应授权。
- 不启动完整试玩流程;交付可读取的专业结果,体验判断留给真实试玩与人工验收。
- 工具输入输出适配在会话内完成并记录;资源可写范围由资源策略承担,不因工具放宽;外部构建服务或 GUI 不被假定继承本地边界,未验证的写入通路保持未就绪。
- 发现构建约定与产品基线冲突或目标变化时,记录影响并交回对应设计与统筹流程,不自行降低要求。
- 不把执行凭据写入任何文件或报告正文。
- 失败或中断时保存实际进度和缺口,如实交接。
