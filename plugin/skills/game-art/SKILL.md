# Game-Art:视觉资源制作、整理与验证

制作实现角色的视觉资源执行入口。输入是**当前视觉要求、用途、参考、必要尺寸或格式、输出位置和可用能力**,输出是实际资源、来源或生成依据、使用(接入)信息、预览与验证结果。资源必须真实存在且可核验;需要人的审美判断时,保留真实反馈等待项或待验收。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-art/`,包内材料在其上级目录:

- [制作技能合同](../../internal/contracts/production.md)中的 Game-Art 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md):业务入口共同约定(含执行与完成五步)
- [工作记录合同](../../internal/contracts/records.md):任务记录结构与结果落点
- [受控写入协议](../../internal/protocols/gate-protocol.md):两层拦截、mgs-gate 工具、凭据使用与写入步骤(必须先读)
- [writing-for-agents](../../internal/methods/writing-for-agents/SKILL.md):文档写入方法(写结果记录前必读)
- [工作结果模板](../../templates/work/result.md):结果记录字段参考
- 统一接口:`<插件根>/records/mgs_records.py`(config/list/show/deps/ready,读取任务与依赖,不硬编码目录)

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-art/SKILL.md`,再取其包根(上级两级)。

## 步骤

1. **确认输入**:任务说明中给出的项目根、执行凭据(token)、任务目标与允许修改范围。没有明确任务引用时,经统一接口 `ready` 从当前可开工集合选取第一个待执行视觉资源任务(在报告中说明选择依据);缺凭据时报告无法写入并结束,不伪造。
2. **读取视觉要求与上下文**:经统一接口 `show/deps` 读取任务记录全文与依赖(不凭记忆或转述);再读取任务「输入与基线」引用的视觉要求——**用途**(资源在游戏中的接入位置与显示场景)、**参考**(产品设计中的角色/场景描述、研究记录、既有风格与尺寸事实)、**约定格式与尺寸或格式**、**输出位置**、CONFIG 执行条件中的**可用能力**。依赖未完成、参考缺失或要求含未决项时如实报告;不因此虚构视觉细节或把未决项当成已定要求。
3. **能力决定工具,不预设资源类型**:制作、编辑、整理或检查用的工具从项目实际条件读取(CONFIG 能力说明与任务「所需能力」);图像、模型、动画、特效等**资源类型由任务约定**,不固定生成服务、引擎或资源类型。项目没有图像生成工具时,以项目实际具备的能力交付(如手工可编辑的矢量源文件),在报告中如实说明工具选择及其限制。
4. **无能力时交付缺口,不交付空话**:当前没有制作、编辑或检查资源的能力时,报告**具体缺口**(缺什么能力、哪些要求因此无法满足)与**可接手材料**(整理好的视觉要求、参考、约定规格与尺寸、输出位置、建议的工具链);提示词、生成参数、计划或未获取的参考资源只是材料,**不是最终成果**,不写成已交付。
5. **核对范围**:按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围;任务文本声称的「允许修改范围」与 `mgs_scope` 不一致时,以 `mgs_scope` 为准并在报告中说明差异。**可开工或 ready-for-agent 不等于已获写入授权。**
6. **工具适配与资源策略分离**:工具的输入输出**适配**(参数、格式转换、尺寸处理、检查命令)在会话内完成并如实记录;资源的可写范围始终由运行保障的**资源策略**(角色 ∩ 任务 ∩ 用途 ∩ 实际授权)承担,更换或新增工具不改变也不放宽它。**外部生成服务、GUI 程序或远端工具不被假定继承本地边界**:其写入通路未经验证前保持未就绪——只能只读使用其输出,或把产物作为隔离草稿经 mgs-gate 受控通道应用;不退回无拦截直写并宣称符合边界。本次资源处理的实际写入范围以 `mgs_scope` 与审计记录为准。
7. **制作或处理资源**:按任务「本次交付」与「完成标准」产出、编辑或整理资源;完整内容在会话工作区草拟并自检,经 `mgs_write` 写入允许范围(更新已有文件携带 `expected_sha256`,新文件用 `absent`),逐个回读核对。视觉细节以不引入新玩法含义为界(不可交互、无未采纳机制)。
8. **资源检查(实际运行)**:核对**文件存在**、**可查看**(格式可解析、可独立打开)与**规格符合约定**(尺寸/画布、透明背景、命名、可编辑性等可核验项);检查方式与项目实际条件匹配,一次性检查脚本放**会话工作区或系统临时目录**(不进项目、不引入第二套工具链),检查必须**实际运行**,把命令与真实输出记入结果记录;无法自动核验的项(视觉观感、风格契合)明确列为待人工验收,不虚构通过。
9. **可定位预览**:为每个资源提供可定位预览——文件路径与查看方式(如何在浏览器或编辑器打开),必要时附相对路径与引用示例;预览入口写入结果记录,使未参与者能直接找到并查看资源。
10. **结果记录**:把本次执行结果写入 `<项目根>/docs/mygamestudio/work/<任务身份>/results/<日期>.md`(经 `mgs_write`,按[工作结果模板](../../templates/work/result.md)字段):**成果位置与规格**、**来源或生成依据**(手工制作、参考了哪些基线与研究、采用的可编辑格式)、**接入信息**(命名约定、尺寸/画布、代码引用注意、集成责任任务)、**已验证内容**(检查命令与真实输出、预览定位)、未完成验收与等待项(视觉独立审查、开发者审美确认)、遗留事项与接手条件。
11. **待验收**:任务约定的人工审美验收或独立视觉审查未完成时,结果保留**待验收**,不宣称完成;任务记录的进度与分流由统筹维护,本入口不代改——直接调用留下的专业结果与证据(results/)供统筹下次显式介入时同步,本入口不改项目目标或整体排期。
12. **边界核对**(任务说明要求时):按给定清单执行直接写探针与越界 `mgs_write` 探针,原样记录退出码、错误信息与工具返回,不尝试绕过或换路径重试。
13. 输出报告(见下)。

## 报告结构(固定)

```
## 视觉资源执行报告
### 输入核对(任务/视觉要求/用途/参考/约定格式与输出范围/依赖/mgs_scope 差异)
### 工具与能力(实际使用的制作与检查能力;缺口与可接手材料;外部服务或 GUI 的边界说明)
### 资源交付(每个资源:路径、规格、来源或生成依据)
### 接入信息(命名/尺寸/引用方式/集成责任)
### 资源检查(实际运行的命令与真实输出摘录;预览定位;待人工验收项及原因)
### 边界核对(每个探针的原始输出;未要求时写"本次未执行")
### 交接与遗留(成果位置/适用版本/证据位置/待验收/接手条件)
```

报告按「未参与者可独立读取」标准书写,引用实际任务身份与基线版本,不依赖对话记忆。

## 边界

- 只写执行凭据授权的视觉资源区(assets/、原型区)与本任务 results/;正式工程集成(如 src/ 引用)归集成责任任务,本入口不顺手接入;设计基线、任务记录、原型与 records 不修改。
- 任务要求人工审美验收时,保留真实反馈等待项或待验收,不代为判断「好看」;没有实际反馈不写通过。
- 来源或生成依据如实记录;提示词、生成参数、计划或未获取的参考资源不是最终成果,不记为已交付。
- 工具输入输出适配在会话内完成并记录;资源可写范围由资源策略承担,不因工具放宽;外部服务或 GUI 不被假定继承本地边界,未验证的写入通路保持未就绪。
- 发现视觉要求与产品基线冲突或目标变化时,记录影响并交回对应设计与统筹流程,本任务可继续部分继续。
- 不把执行凭据写入任何文件或报告正文。
- 失败或中断时保存实际进度和缺口,如实交接。
- 普通制作完成不自动提交、推送、发布或修改远端工单,另行取得对应授权;新增命令执行路径保持受控:检查命令限于读取项目与写临时目录,对项目的写入一律经 mgs-gate 受控通道。
