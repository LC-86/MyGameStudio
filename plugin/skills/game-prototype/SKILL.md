# Game-Prototype:隔离设计原型(最小入口)

方案设计角色的原型执行入口,以原型用途(purpose=prototype)运行:可写范围收窄到隔离原型区。本最小入口覆盖:读取验证问题、在原型区实现、记录结论、边界核对。完整原型工作流待后续任务票补齐。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-prototype/`,包内材料在其上级目录:

- [设计技能合同](../../internal/contracts/design.md)中的 Game-Prototype 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md):业务入口共同约定
- [受控写入协议](../../internal/protocols/gate-protocol.md):两层拦截、mgs-gate 工具、凭据使用与写入步骤(必须先读)

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-prototype/SKILL.md`,再取其包根(上级两级)。

## 步骤

1. 确认输入:任务说明中给出的项目根、执行凭据(token)、要验证的设计问题与原型范围。缺凭据时报告无法写入并结束,不伪造。
2. 读取当前约定与被验证问题的相关设计资料。
3. 按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围(注意原型用途会比角色范围更窄)。
4. 在会话工作区草拟原型文件,`mgs_write` 写入原型区(如 `<项目根>/prototypes/<任务>/`),回读核对;可在会话工作区运行原型自检。
5. 结论记录:把实验结论与未决事项写入原型区记录文件(同样经 `mgs_write`)。
6. 边界核对(任务说明要求时):按给定清单执行直接写探针与越界 `mgs_write` 探针,原样记录退出码、错误信息与工具返回,不尝试绕过或换路径重试。
7. 输出报告(见下)。

## 报告结构(固定)

```
## 原型执行报告
### 原型写入与结论
(每次 mgs_write 的目标、decision、rule_stage、回读核对结果;以及验证问题的当前结论)
### 边界核对
(每个探针的原始输出;未要求时写"本次未执行")
### 遗留事项
```

## 边界

- 原型用途只写隔离原型区;正式工程集成归制作实现,设计基线更新归设计流程,越界写入会被受控通道拒绝,拒绝即停止该项尝试。
- 原型可运行不等于正式产品已经实现;结论以实际证据为准。
- 不把执行凭据写入任何文件或报告正文。
- 需要人试玩判断的事项保留待人反馈。
