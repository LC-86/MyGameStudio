# Game-Code:代码任务(最小入口)

制作实现角色的代码执行入口。本最小入口覆盖:读取任务与基线、在授权范围内修改代码、写结果记录、边界核对。完整技术设计与测试体系待后续任务票补齐。

## 包内依据(开始任何工作前读取)

本技能位于 `<插件根>/skills/game-code/`,包内材料在其上级目录:

- [制作技能合同](../../internal/contracts/production.md)中的 Game-Code 一节:输入、输出、写入与完成条件
- [共同合同](../../internal/contracts/common.md):业务入口共同约定
- [受控写入协议](../../internal/protocols/gate-protocol.md):两层拦截、mgs-gate 工具、凭据使用与写入步骤(必须先读)
- [工作记录合同](../../internal/contracts/records.md):结果记录结构

若当前上下文没有给出技能安装位置,在 `$CODEX_HOME` 下定位 `skills/game-code/SKILL.md`,再取其包根(上级两级)。

## 步骤

1. 确认输入:任务说明中给出的项目根、执行凭据(token)、任务目标与允许修改范围。缺凭据时报告无法写入并结束,不伪造。
2. 读取任务记录与相关基线:任务文件、技术设计、目标代码文件现状。
3. 按[受控写入协议](../../internal/protocols/gate-protocol.md)调用 `mgs_scope` 确认可写范围;任务文本声称的范围与 `mgs_scope` 不一致时,以 `mgs_scope` 为准并在报告中说明。
4. 在会话工作区草拟完整新内容(可先在本地试运行检查),`mgs_write` 提交(更新已有文件携带 `expected_sha256`),回读核对。
5. 结果记录:把本次执行摘要写入 `<项目根>/docs/mygamestudio/work/<任务>/results/<日期>.md`(同样经 `mgs_write`)。
6. 边界核对(任务说明要求时):按给定清单执行直接写探针与越界 `mgs_write` 探针,原样记录退出码、错误信息与工具返回,不尝试绕过或换路径重试。
7. 输出报告(见下)。

## 报告结构(固定)

```
## 专业执行报告
### 合法写入与回读
(每次 mgs_write 的目标、decision、rule_stage、回读核对结果;以及执行过的检查)
### 边界核对
(每个探针的原始输出;未要求时写"本次未执行")
### 遗留事项
```

## 边界

- 只写执行凭据授权的技术文件与结果记录;产品要求或设计文件需要变化时,在报告中提出并回到统筹/设计流程,不代为修改。
- 发现任务描述与实际工程冲突时记录冲突,继续可完成部分。
- 不把执行凭据写入任何文件或报告正文。
- 需要人决定的事项原样保留。
