# 海鸥干扰(俯冲抢贝壳)

状态:已采纳。日期:2026-09-08。维护角色:方案设计。

## 问题与条件

开发者想加入海鸥干扰,三个问题没想清:触发频率、被抢贝壳去向、能否吓走。经质询轮(事实调查见 records/research-2026-09-08-gull-facts.md)收敛后,开发者逐条给出决定。约束:不改变 60 秒总时长与结算方式。

## 选项与决定

- 触发频率:候选 A 每周期固定一次 / B 当前周期连续拾取满 5 枚后至多一次 / C 全程随机低概率。开发者(本人,2026-09-08 对话回答第 1 条)决定采用 B:与玩法节奏挂钩,避免纯随机的挫败感。
- 被抢贝壳去向:候选 A 永久丢失 / B 掉落俯冲点附近、3 秒内可捡回、超时永久丢失 / C 掉落且永久可捡。开发者(回答第 2 条)决定采用 B:保留追回的紧张,又不无限惩罚。
- 吓走/反击:候选 A 本轮不做,海鸥不可交互 / B 可投掷小石子赶走。开发者(回答第 3 条)决定采用 A:控制本轮范围。
- 出现预警:候选 A 出现前约 1 秒预警提示 / B 无预警直接俯冲。**未决**——开发者(回答第 4 条)尚未决定,不作为已采纳内容;决定前验收标准不覆盖预警行为。

以上各条决定者均为开发者本人(2026-09-08 对话回答,逐条对应编号),非助手建议。

## 影响与同步

- 已同步 GAME_DESIGN v2(2026-09-08 规格整理轮;连击决定一并纳入)。
- 范围变化:海鸥属干扰单位,原 PROJECT「本轮不包含」列有干扰生物;开发者(回答第 5 条)接受其进入本轮范围,需要**统筹同步**由 Game-Producer 完成变更同步,不由本入口修改 PROJECT。
- 未决项(出现预警)在 GAME_DESIGN v2「验证与未决项」保留;可借隔离原型提供体验通道辅助决定,但不代替决定。
