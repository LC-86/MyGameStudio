# 任务票 10 验收手册:完成一个视觉资源任务

复现入口:`./run.sh`(约 3 次真实模型调用,消耗额度;默认环境根 `/tmp/mygamestudio-accept-10`,可传参覆盖)。另需本机 `python3`(资源结构检查与验收侧复核;只读项目、只写会话工作区)。

## 验收目标

验证 Game-Art 视觉资源专业入口在真实 codex 会话中的行为,覆盖票面六条验收标准:读取当前视觉要求、用途、参考、约定格式与输出范围且工具由已有项目条件决定(不固定生成服务、引擎或资源类型)、独立任务样例经实际可用能力产出资源并验证存在/可查看/规格符合约定且提供可定位预览、记录来源或生成依据与接入信息和已验证内容且人工审美验收保留等待项、工具输入输出适配与角色资源策略分离且实际写入范围得到验证(服务或 GUI 不被假定继承本地边界)、无能力时报告缺口与可接手材料(不把提示词、计划或未获取资源当最终成果)、直接调用留下专业结果与证据供统筹下次同步且自身不改项目目标或整体排期。

## 环境与机制(沿用票 02-09)

- 隔离 `HOME`/`CODEX_HOME` 于 /tmp,`auth.json` 为指向真实凭据的符号链接;隔离 HOME 无 `.agents/skills`。
- 受保护区在仓库 `.tmp/accept-10/`(gitignored):项目副本 + 运行保障运行根。workspace-write 沙箱只放开会话工作区与 /tmp,项目写入全部经 mgs-gate。
- 角色资源策略:**与票 09 逐字节相同的 policy-spec**(implement = TECH_DESIGN + src/** + assets/** + work/*/results/**)。本票只新增技能入口(工具用法),不改资源策略——这正是「工具输入输出适配与角色资源策略分离」的实证:技能与检查工具变化,资源边界不动,策略 SHA-256 全程一致。
- 实例:W1 视觉资源执行实例(任务 06-gull-sprite,授 `assets/**` 与 06 的 `results/**`——不含 src,集成归 05);W2 统筹实例(任务 10-art-delivery-sync,授 `work/**`)。每轮结束 release-instance 释放占用。
- 能力决定工具(票面标准 1):06 任务记录与 CONFIG v2 已声明「项目没有图像生成工具,本任务以手工可编辑 SVG 源文件交付」;调度说明按此要求不引入外部生成服务或 GUI。SVG 是该项目的事实选择,不是框架默认资源类型。

## 已知边界(如实声明)

- 视觉「好不好看」属人工审美验收:本票只验证结构/规格检查有真实证据、审美与视觉独立审查**保留待验收**(W2 不代验收);视觉审查入口属票 13(Game-Review),开发者审美确认属票 14 试玩范畴。
- 本票样例用 SVG 矢量源文件(项目实际条件决定),**不代表框架默认资源类型或生成服务**;其他资源类型(位图、模型、动画)未在本票验证。
- W1 未使用外部生成服务或 GUI(项目无此能力):「服务或 GUI 不被假定继承本地边界」由技能正文纪律承载并在 W1 报告声明,未做真实外部服务写入通路测试(属后续票的外部能力验收)。
- 标准 5(无能力时报告缺口与可接手材料):本票样例有能力(手工 SVG + python 检查),该纪律写入技能正文(步骤 4)与静态测试概念清单,未在真实轮触发缺口分支;后续票(如音频任务)若能力缺失将真实走该分支。
- 06 交付后 05-gull-swoop 仍阻塞(等待 04-shell-combo 与 06 验收);资源到正式工程的引用集成归 05,本票未集成、未修改 src。
- `run.sh` 依赖本机已登录 codex 凭据(符号链接);换机器需先 `codex login`。codex exec 0.151.0 不解析 `$` 提及,验收走 app-server 通路。
- 检查针对结果语义而非逐字匹配;轮次内的具体措辞、SVG 具体画法与命名由模型基于真实基线产出(run.sh 只核验结构事实与纪律语义)。
