### 候选方案与取舍(助手建议明确标注)

❓ **Q1 — 被抢贝壳的去向**：海鸥成功俯冲时采用哪种后果？

- A 永久丢失：直接从 `shellCount` 扣一；规则清楚、风险明确、实现最小，但可能显得不可挽回。
- B 掉在原地：计数减一并生成可重新拾取的贝壳；形成追抢路线选择，但需定义位置、拾取时机和消失条件。
- C 海鸥携带：成功吓走后返还，否则离场时永久丢失；戏剧性与因果最强，但会把“去向”绑定到驱赶机制并扩大状态复杂度。
- **助手建议（不是开发者决定）**：选 B；它保留干扰压力，又继续服务“再多捡一枚”的核心体验，而不是只做负向扣分。
- 边界场景请同时决定：`shellCount` 为 0 时，海鸥是取消俯冲，还是仍演出但不造成损失？

❓ **Q2 — 玩家能否吓走海鸥**：希望海鸥是必须承受的风险，还是可主动应对的威胁？

- A 不能吓走：玩家只靠走位或接受损失；规则最简，但随机惩罚的公平感最弱。
- B 用现有移动躲避：俯冲前给出预警，玩家移出目标区域即可避开；无需新增按键，但必须定义预警和命中范围。
- C 增加专用驱赶键：操作意图最明确，但扩展输入并增加玩家同时移动、驱赶时的冲突规则。
- **助手建议（不是开发者决定）**：选 B；利用既有方向键形成可读的躲避挑战，最符合当前轻量单文件范围。
- 边界场景请同时决定：预警出现时玩家已经贴近画布边缘，是否仍保证存在可逃离路径？

- “多久来一次”的具体数值暂不进入本轮前沿：有效惩罚强度取决于 Q1 的损失可逆性及 Q2 的反制能力；现在定频率会依赖尚未作出的决定。
- 后续前沿预计包括：触发模型与频率、首次出现保护期、连续触发冷却、60 秒结束时的处理，以及海鸥与已采纳连击规则的关系。
