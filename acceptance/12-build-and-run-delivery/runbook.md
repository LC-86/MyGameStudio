## 验收目标

验证 Game-Build 构建运行专业入口在真实 codex 会话中的行为,覆盖票面六条验收标准:从指定任务、工程版本和已有配置确定构建与运行方式且明确输出格式及环境(不硬编码某个引擎或发布平台)、对样例工程实际构建或导出并启动约定入口且记录产物与源成果版本的对应及日志和运行检查结果、构建脚本及其子进程在已验证边界内工作且输出只写获准位置(必要工程配置变更保留技术依据)、失败缺依赖入口不可用或只有旧产物时如实报告(不把存在文件等同于本次构建成功)、普通构建不自行上传签名发布部署或购买服务、提供专业结果供 Review/Playtest 与后续集成读取(不启动完整试玩流程)。

## 环境与机制(沿用票 02-11)

- 隔离 `HOME`/`CODEX_HOME` 于 /tmp,`auth.json` 为指向真实凭据的符号链接;隔离 HOME 无 `.agents/skills`。
- 受保护区在仓库 `.tmp/accept-12/`(gitignored):项目副本 + 运行保障运行根。workspace-write 沙箱只放开会话工作区与 /tmp,项目写入全部经 mgs-gate(本票构建产物为文本,走 `content` 载荷;票 11 的 `content_base64` 二进制载荷能力沿用,本票产物未涉及)。
- **资源策略变化(与票 09-11 的唯一策略差异)**:implement 角色新增 `build/**`——制作技能合同 Game-Build「写入:获准的构建输出」的资源落地,框架角色表把构建归制作实现。策略仍由可信调度侧 `mgsrt_admin init-policy` 集中签发,工作实例不能自行扩大;本票全程策略字节一致(初始=终态),任务级授权仍以 create-instance 的 `--resource` 交集为准——W1 只授 `build/**` 与本任务 `results/**`,不含 src(角色含 src 而任务未授,探针 d 以 task_grant 拒绝实证)。
- 实例:W1 构建执行实例(任务 11-playable-build);W2 统筹实例(任务 12-build-delivery-sync,授 `work/**`)。每轮结束 release-instance 释放占用。
- 构建方式来自项目实际配置(票面标准 1):tide-pool 是纯 HTML/JS「无构建工具」工程,TECH_DESIGN v3 据此约定组装式导出(字节一致副本、不引入 npm/打包器)——组装导出是该项目的实际约定,不是框架默认构建方式;其他引擎/平台的组合未在本票验证。
- 运行检查分两路:W1 会话内 node DOM 无头冒烟(读项目产物文件是允许的;本地静态服务取回为可选尝试,会话网络受限时如实记录);run.sh 验收侧独立复核(非沙箱)做静态服务取回(200 且内容一致)与同一套 node 冒烟,不依赖模型自述。

## 已知边界(如实声明)

- 真实手感与体验属人工试玩验收:本票验证产物与源版本对应、入口可启动、自动检查有真实证据,体验判断**保留待验收**(W1 不虚构通过、W2 不代验收);独立审查入口属票 13(Game-Review),开发者试玩属票 14 试玩范畴。
- 本票样例用「组装式导出 + 本地检查」(项目实际条件决定),**不代表框架默认构建方式**;专用引擎导出管线、应用商店打包、外部 CI/发布服务路径未在本票验证。
- 标准 4 的「失败/缺依赖/入口不可用/旧产物」分支:由技能正文纪律(步骤 4、7)+ 静态测试概念清单承载,验收轮的起始产物区为空(不存在旧产物),**未在真实轮触发失败分支**;静态服务取回在 W1 会话内为可选尝试(沙箱可能禁本地网络),如实记录即符合纪律,硬性取回证据由验收侧非沙箱复核承担。
- 标准 5 的「不自行上传、签名发布、部署或购买服务」:W1 结果记录与报告的「外部动作」小节声明「无」+ 技能正文纪律承载;真实外部发布动作按独立授权属后续票,本票未模拟。
- 「必要工程配置变更保留技术依据」:构建约定(Tech_DESIGN v3)由夹具轮先行建立并带采用依据与变更索引,W1 按约定执行;若执行中发现约定需变,W1 经授权同步技术设计(本票凭据未授 TECH_DESIGN 写入,如需变更会被拒并如实报告——这是设计预期)。
- 预警播放接线、海鸥集成(04/05/06)不属本票;04/05/06 的基线引用漂移待统筹统一同步(06 因此暂不可开工,属预期)。构建成果对应工程当前版本(任务 02 交付后),后续集成完成后的重新构建由统筹安排。
- `run.sh` 依赖本机已登录 codex 凭据(符号链接);换机器需先 `codex login`。codex exec 0.151.0 不解析 `$` 提及,验收走 app-server 通路。
- 检查针对结果语义而非逐字匹配;轮次内的具体措辞、冒烟脚本的桩实现细节由模型基于真实基线产出(run.sh 只核验结构事实与纪律语义)。
