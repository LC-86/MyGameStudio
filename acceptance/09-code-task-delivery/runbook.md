# 任务票 09 验收手册:完成一个代码任务并交接实际结果

复现入口:`./run.sh`(约 4 次真实模型调用,消耗额度;默认环境根 `/tmp/mygamestudio-accept-09`,可传参覆盖)。另需本机 `node`(行为检查的执行环境;只读项目、只写会话工作区)。

## 验收目标

验证 Game-Implement 组织入口与 Game-Code 完整工作流在真实 codex 会话中的行为,覆盖票面六条验收标准:读取实际任务/基线/工程/依赖并核对允许修改范围(实现方法来自项目实际配置,不成为框架默认引擎)、必要技术设计由制作实现维护且规格冲突记录影响交回、样例中实际修改并集成代码并运行匹配风险的行为检查、组织本任务专业工作与结果交接且未实现入口不伪装、待验收保留不虚构通过、失败/中断保留进度与缺口且普通实现不自动提交推送发布。

## 起始状态(两层夹具覆盖,不改样例本体)

- 基底:`samples/tide-pool/`(保持 v1,票 06/07/08 验收可复现,静态测试双向核对)。
- 第一层:`acceptance/08-spec-to-local-tasks/fixtures/`(票 06 成果 GAME_DESIGN v2、PROJECT v2、CONFIG v2、海鸥决定与研究、原型交付 prototypes/gull-window/)。
- 第二层(本票新增):`acceptance/09-code-task-delivery/fixtures/`——票 08 真实拆单产物(02-09 任务记录与 03 的拆单结果,取自 08 验收终态,未改动)与开发者「开工当前代码任务」请求(README)。
- 统一接口 ready 起始输出:可开工 = 02-tide-timer、06-gull-sprite;04-shell-combo 等待 02(接续位置真实)。

## 环境与机制(沿用票 02-08)

- 隔离 `HOME`/`CODEX_HOME` 于 /tmp,`auth.json` 为指向真实凭据的符号链接;隔离 HOME 无 `.agents/skills`。
- 受保护区在仓库 `.tmp/accept-09/`(gitignored):项目副本 + 运行保障运行根。workspace-write 沙箱只放开会话工作区与 /tmp,项目写入全部经 mgs-gate。
- 角色资源策略:producer=管理资料+`work/**`;design=GAME_DESIGN+records/**+prototypes/**;**implement=TECH_DESIGN+`src/**`+`assets/**`+`work/*/results/**`**(专业执行结果与证据归执行者写,任务记录 task.md 仍归统筹——对应《工作记录合同》「统筹维护请求、安排和当前状态;专业执行者保存自己的结果与证据」,与票 02 的实现角色范围一致)。
- 实例:W1 组织实例(任务 02-tide-timer,仅授 TECH_DESIGN——组织轮不改代码);W2 执行实例(同任务,授 src 两文件+TECH_DESIGN+02 的 results);W3 统筹实例(任务 09-delivery-sync,授 work/**)。每轮结束 release-instance 释放占用(同资源先后写入不冲突)。

## 已知边界(如实声明)

- 组织轮与执行轮由同一实现角色下的两个实例先后承担(任务相同、授权不同);「选择专业技能」在单实例内以明确安排表达,代码路径真实交由 Game-Code 入口执行,未发生视觉/音频/构建专业实例的真实委派(Game-Art/Audio/Build 入口未实现,W1 如实声明)。
- 独立审查(Game-Review)与开发者试玩(Game-Playtest)入口未实现:本票验证的是结果**保留待验收**且不虚构通过,审查与试玩本身属票 13/14。
- 行为检查是一次性脚本(会话工作区),按 TECH_DESIGN「无自动化测试框架」的约定不进项目;证据(命令+输出)落 02 的 results 供复现(W4 已只读重跑确认)。
- 「一段时间未拾取」等规格留白属 04 的任务;本票 02 无规格留白,刷新差异(设计说持续刷新、工程只开局 6 枚)作为真实缺口交回统筹,属票 15+ 的处理范围。
- **基线漂移残留(run1 实况)**:组织轮把 TECH_DESIGN 升到 v2 后,02/04/05 任务记录的「输入与基线」仍引用 v1——统一接口 `ready` 如实报告漂移(接口按票 08 语义正确工作);W3 只按提示同步 02 的进度字段,未改其基线引用。该残留交由统筹下轮同步任务记录(02/04/05 的 TECH_DESIGN 引用、PROJECT v2 的 02 安排行),不虚构为已一致。
- W4 交接核对另发现:03 的拆单结果(票 08 产物)中 mgs_scope 绑定任务写作 08-gull-round-plan(运行时任务标识),与记录身份 03-gull-round-plan 不一致——票 08 遗留的记录观察,本票不改。
- 失败/中断的进度保存纪律写入两个技能正文并由结果记录结构承载;本票未模拟真实中断(受控中断矩阵项属票 15),W2 中首次写入末尾换行不一致时以 expected_sha256 精确重同步是进度保护的实际演示。
- `run.sh` 依赖本机已登录 codex 凭据(符号链接)与本机 node;换机器需先 `codex login`。codex exec 0.151.0 不解析 `$` 提及,验收走 app-server 通路。
- 检查针对结果语义而非逐字匹配;轮次内的具体措辞、实现命名、检查脚本形态由模型基于真实基线产出。
