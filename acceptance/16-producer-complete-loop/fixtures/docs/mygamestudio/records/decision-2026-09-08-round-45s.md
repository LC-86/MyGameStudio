# 缩短回合并参数化追回窗口

状态:已采纳。日期:2026-09-08。维护角色:方案设计。决定者:开发者。

## 问题与条件

开发者在试玩布景之后明确提出目标变化:缩短单轮潮汐时长,并把固定追回窗口改为可调参数。该变化不是纠错;原 60 秒成果与原型参数记录继续作为原版本事实,不自动满足新目标。统筹影响检查确认变化触及 GAME_DESIGN v3 的回合时长与固定追回窗口规则,并识别 04、05、08 的既有基线漂移与重核需要。

## 选项与决定

- 回合时长:开发者决定由 60 秒改为 45 秒;潮汐倒计时结束即结算与不判负规则保持不变。
- 被抢贝壳追回窗口:开发者决定由固定 3 秒改为可调参数;基准值仍为 3 秒,由制作实现维护的技术设计以命名参数登记,后续按手感调整时不散落代码字面量。
- 以上两项均由开发者于 2026-09-08 明确决定并已采纳;技术参数的具体名称与落点留给制作实现,本记录不裁决未决项。

## 影响与同步

- 产品设计基线由 GAME_DESIGN v3 递增为 v4;当前规则、可执行规格、验收标准、固定/可调边界与实现状态同步更新。
- 目标与范围已经由统筹影响检查同步至 PROJECT v3;04-shell-combo、05-gull-swoop、08-gull-playtest 已改为 needs-triage,等待 GAME_DESIGN v4 后重核。
- 02-tide-timer 与 11-playable-build 的 60 秒成果及相关 evidence 保留为原版本事实,不自动满足 GAME_DESIGN v4;是否重做、如何重排由统筹安排。
- TECH_DESIGN v3 仍登记 60 秒固定产品规则,且尚未登记追回窗口的命名参数;制作实现需在统筹重核后同步技术设计与实现。
- 实现状态:45 秒回合与追回窗口参数化均未实现,以任务记录为准。

## 替代关系

本决定替代 GAME_DESIGN v3 中“60 秒潮汐倒计时”与“固定 3 秒追回窗口”的现行要求;旧要求及其成果继续保留原版本历史含义。未采纳候选与其他未决项维持原记录状态。
