# 13: 建立共享客户端并接通标准事件场景

**What to build:** 标准事件验收场景使用共享客户端完成请求、等待和证据输出，旧客户端仍可支撑尚未迁移的场景。

**Blocked by:** 10 按行为组织包与场景验收检查

**Status:** ready-for-agent

**Spec:** [MyGameStudio 全插件分阶段架构重构 v1](../spec.md) · User Stories 35, 36, 37, 38, 40

**Verification mapping:** 按本票所属阶段的验收集合

- [ ] 完成共享客户端的实际请求响应、事件等待、输出与进程结束路径，并迁入现有三个逐字节同类的标准事件场景（原 02、17、18）。
- [ ] 共享实现对每条新输入只解码一次并分发，普通完成、失败、超时和事件筛选维持原语义。
- [ ] 现有场景命令参数、身份、证据内容与退出码保持；未迁移场景继续沿旧实现通过。
- [ ] 用受控进程或回放 adapter 检验完整调用，旧与新标准场景在相同输入下的可观察结果一致。
- [ ] 复测一千条固定事件的轮询计数，证明旧事件不反复解码；不把操作量改善宣称为模型或网络端到端倍数。

**依赖理由：** 依赖 10 可独立运行的场景与包验证方式，采用 expand：新旧并存，先接通一族完整场景。
