# 依赖分发方案

状态：分发策略已由用户在 Q31 确认采用；具体技能清单与依赖版本由 Skill 划分决定。

## 分发边界

| 内容 | 分发方式 |
| --- | --- |
| MyGameStudio 自有游戏技能与模板 | 随插件版本提供 |
| 基本工作流必需的通用 Skill 与引用资源 | 随插件提供可追溯的固定版本；例如用户指定的 writing-for-agents |
| 引擎、编辑器、构建工具与第三方服务 | 使用项目选择的外部能力，初始化或执行前核对实际条件 |

内置范围以工作流需要为准，包含必要的引用资源，不复制整套无关技能。已经决定需要独立设计的游戏环节按 MyGameStudio 的协议实现。

## 定位与维护

1. 调用内置通用能力时，从插件自身确定的入口定位版本。完成条件：可以指出来源、版本及所需引用资源，避免依赖开发机个人路径或混用全局同名技能。
2. 上游有更新时，维护者评估差异并验证与现有工作流兼容，再随插件更新引入。完成条件：内置版本及修改记录可追溯；运行中的流程不会仅因外部 Skill 更新就换用另一份规则。
3. 项目实例化后的文档由项目维护；插件模板更新如何应用，由初始化或升级方案说明，保留项目已有内容及用户修改。

固定版本减少环境差异，也意味着 MyGameStudio 需要承担这部分依赖的升级验证。具体版本、命名和调用入口在 Skill 划分及实际发现验证中确定。
