# 通用交接内容模板

状态：两类通用交接结构及按需专业补充已由用户确认；专用字段见[业务合同](../contracts/common.md)，物理存放方式见[记录合同](../contracts/records.md)。对应[项目记录、角色交接与跨会话恢复](../issues/04-project-handoffs.md)。本文件是框架设计材料，不是已安装 Skill 或实际游戏项目的交付记录。

用户已进一步要求完整的项目文档模板、目录结构模板及新建或接手项目时的初始化能力。本文件仅为其中交接内容的一部分，不代表完整模板集合。

## 使用原则

- 以工作请求和工作结果两类通用内容结构覆盖交接，再按具体 Skill 补充专业内容。
- 模板可以成为已有任务或专业工作记录中的段落，不要求每次额外创建独立交接文件；物理存放与写入边界使用记录合同。
- 输入由执行者主动读取项目资料并整理；已存在的基线、设计、原型和资源使用引用，避免复制多份当前要求。
- 小任务可合并字段或省略不适用项，但当前目标、依据、范围及结果事实需要能理解。关键未决信息明确指出，不用占位内容冒充已确定。
- 专业产物、设计基线与任务安排的维护责任沿用已确认分工。写工作结果不意味着专业角色获准修改整体目标或排期。
- 请求与结果关联同一项任务，注明实际采用的基线版本。开始、恢复或交接时核对适用性，版本变化按实际影响处理；逻辑版本与指纹使用记录合同。
- 任务记录维护分流状态、执行责任、验收方式、进度和依赖。使用交接模板时引用这份任务信息，已有字段只维护一处。

## 工作请求模板

```markdown
# 工作请求：{任务名称}

目标：{本轮希望得到的结果，以及它服务的当前项目目标}
任务信息：{任务记录引用；首次建立时明确分流、执行责任、验收方式、进度和依赖}
依据与输入：{适用的基线或设计条目及版本、必要的原型与资源引用}
范围与约束：{本次做什么、已授权的操作范围、必须遵守的限制}
完成标准：{约定检查或试玩及通过条件，是否需要开发者人工验收}
待定事项：{影响当前工作的未决问题；没有则可省略}
```

## 工作结果模板

```markdown
# 工作结果：{关联的任务名称或引用}

成果与改动：{实际交付了什么，文件、资源、版本或查看入口}
适用依据：{本次实现或分析实际采用的需求、设计依据及版本}
验证情况：{已执行的检查及结果，证据引用，尚未验证的部分}
遗留事项：{尚未完成的内容，需要开发者判断的问题；没有则可省略}
后续影响：{对相关任务、设计或验收的影响与建议；没有则可省略}
```

工作结果只记录事实与建议。尚待人工试玩、尚未验证和已经通过的内容应明确区分，不能用一个“完成”掩盖差异。统筹依据结果和实际成果维护整体进度。

## 按需的专业补充

| 场景 | 补充内容 |
| --- | --- |
| 方案设计 | 当前关键规则或设计变化、候选与已采纳内容的区分、必要的原型及验证结论 |
| 制作实现 | 必要的技术设计变化、实际运行或查看方式、集成结果及可复现的检查信息 |
| Review | 适用要求与被审查成果、问题位置和证据、检查范围及限制 |

详细设计仍在设计文档中维护，模板引用它；模板不取代游戏设计或技术设计的专业结构。创建具体资料时使用[模板入口](../templates/README.md)，按任务选择必要的专业字段。
