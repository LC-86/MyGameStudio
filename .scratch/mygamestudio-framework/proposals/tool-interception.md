# 工具拦截设计

状态：首版拦截目标与统一资源权限、执行边界优先复用的方向已由用户确认。具体承载方式和覆盖验证尚未完成。

## 目标

对受控流程中的违规写入，在工具执行前拒绝；拒绝时目标内容保持不变。职责约定和事后审查作为补充，不能代替实际拦截。

核对宿主事件、身份和故障语义时，读取[工具拦截研究](../research/tool-interception-contract.md)。它区分发布文档、上游源码和未验证的目标客户端行为。

## 拦截决定

每次写操作由受控执行入口执行以下检查：

1. 识别执行实例及其绑定角色。完成条件：身份来自宿主或可信调度记录，与当前任务匹配；不能由工具参数中的自报角色直接授权。
2. 确定工具的实际写入能力与目标。完成条件：操作类型及目标资源可核对，路径和引用已规范化；间接执行应有覆盖其副作用的限制。
3. 核对角色允许范围、当前任务、适用基线和写入占用。完成条件：请求同时满足角色与任务范围，当前文件版本及占用允许此次修改。
4. 执行或拒绝并记录结果。完成条件：允许操作有实际结果，拒绝操作未产生目标写入；记录包含规则依据，供统筹和独立审查核对。

角色允许范围沿用[角色决定](../issues/02-role-responsibilities.md)及[目录与交接决定](../issues/04-project-handoffs.md)。策略、身份绑定和占用状态的修改通道应与普通执行者权限分离。

## 受控写入条件

### 统一规则与执行边界

将角色与任务允许修改的资源范围作为统一策略。优先在受控执行环境落实文件写入限制，让在该边界内运行的工具共享限制；同步 hooks 或受控写入接口承担适用的调用校验、协调与记录。工具的命令、操作方法、输入输出格式属于能力适配，角色权限规则独立维护。

同一受控环境内更换工具，核对其仍处于既有边界及能否完成任务；不默认重写角色权限规则。连接已经运行的桌面程序、外部 MCP 服务或远端系统时，核对新增写入通路，不能假设它们自动继承本地进程的限制。

该方向依据 Codex 对沙箱内启动命令共享限制的说明，但不推定插件原生支持完整角色级文件白名单。[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing#what-the-sandbox-does)。实际角色隔离、进程启动方式及外部服务限制仍需验证。

### 需保持的保障

所有对受控项目产生写入的可用通路需要明确受何种执行边界约束。发现缺口时先分析新增运行方式及可用限制，不直接把“每个新工具都另写专用拦截器”设为主方案。

原生 hook 的存在不足以证明检查失败时会拒绝。检查器未运行、超时、崩溃、输出无效或失去可信绑定时，应由执行边界保持拒绝；具体保障方式需验证。

Shell、构建脚本、资源工具或持续运行的进程按其实际副作用控制，不能仅凭命令名称或正则匹配推断安全。主代理、子代理、直接调用与恢复路径分别验证身份绑定。

## 首版验收条件

- 正常角色写入可成功，角色范围外的写入在发生前拒绝，目标字节保持不变。
- 伪造角色、旧身份或未知身份不能增加可写范围。
- 同文件竞争和过时版本写入不会覆盖其他已完成成果。
- 检查器缺失、未启用、超时、崩溃或输出错误时，受限写入仍被阻止。
- 文件修改、脚本和工具产生的间接写入、已有交互进程等路径有覆盖结果；符号链接及目标变化有对应验证。
- 执行者不能通过修改检查规则或身份记录给自己扩大权限。

这些是必须验证的条件，不是当前已经通过的检查。

## 后续验证与接口

Q30 的逐工具暂停建议未获采用；统一资源权限与执行边界方向已确认。接入时验证同一环境内可复用的限制，以及新写入通路的约束方式；未达到当前要求的能力需明确说明其缺口。

能力适配确定允许的执行范围；初始化负责检查目标运行环境与所需配置；实现阶段必须提供真实拦截与故障测试。具体事件字段、配置格式及限制机制以验证后的目标版本为准。
