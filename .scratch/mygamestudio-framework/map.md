# MyGameStudio 通用工作流与角色分工设计

Labels: wayfinder:map
Status: resolved

## Destination

形成一份说明 MyGameStudio 插件应该怎样工作的完整设计：明确游戏开发工作流、角色职责、协作交接、文档与目录模板、新建和已有项目的接入初始化、开发者决策边界、Skill 划分及平台与工具扩展方式，并能据此开展后续实现。

## Notes

- 本轮为设计，不进入插件实现、安装或发布。讨论始于 2026-09-07，设计汇总于 2026-09-08；交付入口见[完整设计](spec.md)。
- 决策方法：使用 wayfinder；讨论决策时使用 grilling 与 domain-modeling。一次会话最多解决一张非 research 决策票；建图阶段不代替用户解决票内问题。
- 编写或修改 Agent 使用的文档时，使用 [writing-for-agents](/Users/cuilei/.agents/skills/writing-for-agents/SKILL.md)；这是用户明确要求的文档写入方法。
- 本地跟踪规则见 [issue-tracker.md](../../docs/agents/issue-tracker.md)。每张票保存自己的问题与最终答案；地图仅索引已解决票。
- 以下为建图前用户已明确的目标与约束，不是待讨论建议：
  - 产品面向个人独立游戏开发者，以 Codex 插件承载；当前交付为完整设计，重点包括工作流、角色和职责分工。
  - 通用框架不限定发布平台、工具或引擎；具体适配在后续版本逐步完善。
  - 设置制作统筹入口：检查进度、建议优先级、组织专业角色协作；开发者也可直接找专业角色处理工作。游戏方向、范围和重要阶段取舍由开发者决定。
  - 所有 Skill 都需要显式调用，不通过自动识别用户意图触发；详细调用规则见下方已解决决策。
  - 角色职责保持完整，执行方法按项目条件确定；检查项目资料和可用工具，必要时查文档、调用已有技能或实现，无法完成的部分明确交接，完成声明需要验证证据。调用已有技能也受显式调用约束。
  - 未提到的产品要求通过持续质询补齐，助手建议不能作为用户决定。
- 参考资料：[交接文档](/tmp/indie-game-handoff-20260907/HANDOFF.md)、[mattpocock/skills](https://github.com/mattpocock/skills)。交接中的阶段参考已通过工作流决策调整为轻量迭代，按项目条件选择检查；历史平台、引擎和工具示例不是本项目默认值。
- 术语见 [CONTEXT.md](../../CONTEXT.md)。

## Decisions so far

- [显式调用与制作统筹的协作边界](issues/01-explicit-invocation.md)：开发者显式选择入口，统筹在授权内连续调度专业技能，自身只写项目管理文档，遇到必要决策或检查点暂停。
- [专业角色的职责、产出与决定权](issues/02-role-responsibilities.md)：以三个角色覆盖完整生命周期，设计可制作验证原型，实现对集成负责，评审按需独立执行，明确进度同步与冲突处理责任。
- [游戏开发工作流与阶段通过条件](issues/03-workflow-gates.md)：六阶段仅作参照，按项目条件小步迭代并由人判断；统筹维护当前目标，目标变更优先同步后再继续受影响工作。
- [项目记录、角色交接与跨会话恢复](issues/04-project-handoffs.md)：已确定目录、基线版本、交接模板、任务分流与人机责任，按当前依据接手和恢复，并协调重叠修改。
- [通用职责与具体执行能力的衔接](issues/05-capability-adaptation.md)：必需技能随插件固定版本提供，外部工具按项目选用；首版保留写入拦截，统一资源权限并复用执行环境限制。
- [项目接入、深度分析与初始化](issues/08-project-onboarding.md)：已有项目只读分析、优先复用并确认清单后补齐；中断核对实际结果恢复，无缺口时不重复修改。
- [游戏项目文档用途与维护方式的一手依据](issues/07-documentation-evidence.md)：已核对简短设计逐步扩展、当前设计与决策历史分工的一手资料，作为文档体系的有限参考。
- [Matt 工作流技能的复用边界核对](issues/09-matt-workflow-fit.md)：已核对六项本地技能，识别任务分工、文档落点、自动提交及 HEAD 审查范围的适配要求。
- [Matt 五类 triage 标签与游戏任务分流的适配依据](issues/10-triage-labels-fit.md)：公开版与本地五状态一致，Human 分流涵盖人工判断和测试；不能替代独立的执行与验收记录。
- [Codex 插件依赖与角色写入限制的承载能力](issues/11-codex-capability-boundaries.md)：已核对技能打包、显式调用及沙箱/hooks 边界；外部 Skill 依赖和角色级写入强制限制需专门设计与验证。
- [工具拦截的调用契约、身份与覆盖条件](issues/12-tool-interception-contract.md)：首版工具拦截需覆盖可信身份、间接写入及检查器故障，单个 hook 配置不足以证明强制目标。
- [内置通用技能的引用依赖核对](issues/13-bundled-dependency-closure.md)：已核对基础内部方法、条件引用、资源指纹及游戏侧映射边界。
- [本地执行环境共享写入限制的隔离验证](issues/14-local-execution-boundary-proof.md)：本机临时夹具有限测试通过，完整 Codex 集成仍需实施验收。
- [Skill 划分、Agent 分工与完整设计验收](issues/06-skill-contracts.md)：完成十四入口合同、协作配置、十三份模板、包与运行设计、场景及实现验收矩阵。
