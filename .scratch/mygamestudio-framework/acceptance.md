# 设计检查与实现验收矩阵

本轮验证分三层：设计静态核对、有限本地边界实验、未来运行时验收。前两层的结果不替代最后一层。

## 设计场景核对

下表检查当前规则能否给出一致的预期路径；它是设计推演，不是实际游戏或已安装插件的运行结果。

| 场景 | 设计规定的行为 | 依据 |
| --- | --- | --- |
| 只想讨论新功能 | 显式调用统筹后组织设计讨论，交付选项和决定；需要实现时核对对应授权 | [调用边界](issues/01-explicit-invocation.md)、[设计合同](contracts/design.md) |
| 已有明确功能需求 | 直接形成可执行约定与原子任务，按必要性选择原型和验证 | [小闭环](proposals/game-work-loop.md) |
| 单独要一个图标或音效 | 直接调用对应 Skill，按实际能力产出资源和记录；统筹下次读取结果同步 | [制作合同](contracts/production.md) |
| 设计者写验证原型 | 在隔离原型范围内编码和调用资源能力；正式工程由制作实现集成 | [设计合同](contracts/design.md)、[运行保障](contracts/runtime.md) |
| 技术方案发现产品要求冲突 | 实现者记录冲突，设计与统筹处理要求及影响，不能自行改产品目标 | [制作合同](contracts/production.md) |
| 中途改变目标 | 先同步管理与专业依据，受影响任务重新分流；历史成果保留原版本事实 | [工作流决定](issues/03-workflow-gates.md) |
| Agent 完成制作，需要人判断手感 | 留在待人工验收，给出具体试玩要求；收到实际反馈再判断完成 | [审查与试玩](contracts/verification.md) |
| 两项任务修改同一场景或设计文件 | 同一资源单一写入者，排先后或拆分；明确最终集成人 | [运行保障](contracts/runtime.md) |
| 审查尚未提交的成果 | 包含实际新增和修改范围，独立读取规范、规格与成果 | [审查与试玩](contracts/verification.md) |
| 接手文档落后于代码的旧项目 | 只读分析并列出矛盾；已有实现不能自动变成已采纳产品意图 | [初始化](proposals/project-onboarding.md) |
| 原项目已经用 GitHub Issues | 沿用明确后端与标签映射，核心文档保留实际路径；不复制一套本地当前任务 | [配置](contracts/project-configuration.md) |
| GitHub 断连或写入超时 | 标明读取限制或未发布草稿，先回读确认，不静默切换或重复创建 | [记录](contracts/records.md) |
| 初始化中断后用户改了文档 | 核对实际结果和新变化，保留已完成部分，只重新处理受影响内容 | [初始化](proposals/project-onboarding.md) |
| 同执行环境更换工具 | 复用资源策略，检查运行方法与边界继承；外部服务单独核实写入通路 | [运行保障](contracts/runtime.md) |

设计静态完成条件：上述场景有明确入口、输入、责任、成果、停止或继续条件；14 个业务入口都有合同和可用模板映射；文档内部有效链接可解析。核对结果记录在[完整设计决策](issues/06-skill-contracts.md)的 Answer 中。

## 已运行的有限实验

[实验报告](research/local-execution-boundary-proof.md)记录本机临时夹具的允许目录写入、直接越界写、子 shell、持续 shell 后续输入及符号链接测试。原始运行输出和哨兵回读支持这次有限测试通过。它未覆盖真实插件注册、可信角色绑定、全工具路径或其他系统。

## 实现发布必须取得的证据

下表全部为待实施验收，不能从文档存在推定通过。

| 检查范围 | 必须观察到的结果 |
| --- | --- |
| 安装与入口发现 | 目标 Codex 版本识别全部 14 个业务入口；无额外同名通用入口；所有包内依赖在安装位置可读取 |
| 显式调用 | 普通对话不自动触发业务 Skill；用户直接调用和统筹明确委派都可工作，且角色绑定正确 |
| 权限交集 | 统筹可写管理资料、不可写设计和代码；设计可写原型区、不可借用编码能力扩大到正式工程；合法专业写入正常成功 |
| 独立审查 | 使用独立同专业实例及真实成果、当前规格和规范；审查者仅写审查记录，不自行修复待审成果 |
| 身份与策略保护 | 伪造、未知、过期身份及策略文件篡改无法扩大权限；主代理、子代理、直接调用、恢复路径都覆盖 |
| 直接与间接写入 | 覆盖所有启用路径，包括文件编辑、命令、构建和资源子进程、持续进程后续输入；拒绝后目标保持不变 |
| 路径与并发 | 链接、别名、目标变化、路径竞态与过时版本不会导致越权或覆盖；同资源占用冲突得到处理 |
| 故障拒绝 | 检查器缺失、未信任、超时、崩溃、错误输出和服务失联时，受保护写入仍不可执行 |
| 进程与恢复 | 旧任务失效后其持续进程不能继续写；占用回收前核对活跃执行；中断恢复只应用仍有效剩余动作 |
| 外部能力 | 每个声明支持的 MCP、GUI、远端或资源工具路径具备实际边界测试；不继承本地边界的部分明确限制 |
| 任务后端 | 本地与 GitHub 使用相同任务含义，身份、关系、标签和结果可回读；远端失败不会双写、静默降级或重复创建 |
| 项目初始化 | 新建、已有映射、缺口补齐、混合职责、手工修改、中断、重复运行和模板升级均保留有效内容；实际变更符合确认清单 |
| 基线变化 | 实质要求变化更新版本与受影响任务；格式变化不无故作废全部证据；未同步版本号的手工修改能被发现 |
| 人机验收与成果真实性 | 人工判断来自真实反馈；缺少制作能力只记录缺口；Review 覆盖未提交和新成果，构建对应所称版本 |
| 外部动作授权 | 选择后端或执行制作不会自行提交、推送、修改远端工单、上传或发布；明确授权按指定目标执行 |
| 依赖与升级 | 必需资源缺失有可定位错误，固定版本与许可证可追溯；插件更新不自动覆盖项目内容或客户端治理 |

首版兼容范围只列通过这些相关检查的宿主和执行组合。若不能满足用户要求的工具拦截，保留实现阻塞，不能用说明文档或事后 Review 替代通过。
