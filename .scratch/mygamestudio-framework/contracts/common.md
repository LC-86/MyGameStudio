# 业务 Skill 共同合同

本合同适用于十四个业务入口。名称与职责见[清单](../proposals/skill-catalog.md)；各分支只补充差异。

## 调用与角色

用户显式调用业务入口。Game-Producer 可按已授权需求明确委派；专业工作中的内部能力调用须由工作流程明确指定。普通对话内容不触发业务 Skill。

调用携带项目、工作目标、执行角色和任务引用。角色由受控运行方式绑定，Skill 名称与记录中的角色字段不授予权限。共用能力沿当前角色、任务和资源范围执行。

只读请求以分析和报告交付；已授权修改按对应角色写入。目标或范围变化时使用[变更同步规则](../issues/03-workflow-gates.md)，直接专业调用按该规则提示统筹同步。

## 输入与输出

使用[交接模板](../proposals/handoff-templates.md)。已有输入从项目读取，引用实际基线版本；关键缺口先调查，仍影响当前工作的事项明确交接。当前一步所需信息足够即可推进。

输出包含实际成果定位、适用依据、执行过的验证及未完成事项。提案、已采纳设计、实际实现和验收结果分别记录。记录结构见[工作记录合同](records.md)。

文档写入明确加载内置 writing-for-agents 及适用参考。原始资料保存出处，当前要求在对应基线维护，其余位置引用。

## 执行与完成

1. 核对当前目标、基线、输入、依赖和授权。完成条件：能说明本次成果及可以执行的范围。
2. 核对运行条件及资源范围。完成条件：本次操作处于已验证的执行边界，重叠修改有明确先后或占用。
3. 执行本次工作并保存必要证据。完成条件：成果实际存在，验证结果可定位，缺口有明确说明。
4. 按约定完成独立审查和人工验收。完成条件：需要的检查有结果；等待人的事项保留待验收。
5. 提交结果记录。统筹据事实更新整体状态；直接调用产生的普通工作记录在统筹下次介入时同步。

工具拒绝、输入不足、等待人或执行失败，都不等于工作完成。保留有效进度，恢复时重新核对实际状态。

## 写入与保障

项目管理资料、产品设计、技术设计及正式成果分别沿既定归属维护。审查、试玩等模式按本次用途收窄写入范围。实际写入按[运行保障合同](runtime.md)控制。

Git 提交、推送、标签、外部工单、上传和发布沿用户已明确的对应授权执行。普通实现或构建完成不自动授权下一项外部动作。

## 读取具体分支

- 产品方案、规格与原型：读取[设计技能](design.md)。
- 代码、视听资源、构建与集成：读取[制作技能](production.md)。
- 独立审查与试玩：读取[审查和试玩](verification.md)。
