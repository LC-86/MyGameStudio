# 固定场景:新设计(每日挑战核心模块)

**模式:** 新设计。独立报告,不与变更场景混合平均。
**起始资料:** 仓库 `samples/gear-city/` 的隔离副本(INDEX/CONFIG/PROJECT/GAME_DESIGN/TECH_DESIGN、`src/main.js`、README「当前请求」)。
**入口:** `$game-design` → 开发者回答 → `$game-design` → `$game-spec`。复用验收 06 的 app-server 客户端、隔离 HOME、mgs-gate 与 design 角色凭据。
**优化前行为:** 现行 Game-Design / Game-Spec(质询 + 规格同步),本票不改插件问答实现。

## 覆盖要求

- 范围提取与轻量设计地图(每日挑战核心模块;不为填模板新增系统)。
- 一组无相互依赖的问题(Q1–Q3)与至少一项后续依赖(Q4 依赖 Q3 的「每日身份」)。
- 部分回答后补答;多轮决定保存;最终规格同步。
- 成组提出前三项,第四项等 Q3 确定后再问。

## 语义一致的用户答案

首轮只回答 Q1、Q2;Q3 明确未答。次轮补答 Q3,并回答因此解除依赖的 Q4。

| 编号 | 决定 | 语义(比较时不得改成果含义) |
| --- | --- | --- |
| Q1 | 关卡来源 | 每日关卡从现有 20 关按日期抽取,不另生成或外购新关。 |
| Q2 | 与章节关系 | 与章节模式并存;从标题菜单进入;不替代、不要求先通关章节。 |
| Q3 | 每日身份 | 以玩家本机本地日历日(自然日 0 点切换)加固定种子确定当日关卡;不联网对时。 |
| Q4 | 记录(依赖 Q3) | 不设联网排行榜;只保留本机当日最佳步数,换日后清空。 |

未决:具体抽关公式的展示文案。不把「本轮不包含每日挑战」改写成已由设计入口修改 PROJECT。

## 决定集合与成果范围

必须可回读:

1. 过程决定记录至少一份,含上表已采纳四项、决定者=开发者、Q 以外内容未默认采纳。
2. `GAME_DESIGN.md` 在获准同步后纳入本模块可执行规格(目的、对象、触发、规则、边界、数值或配置、反馈、数据、验收),版本实质变化递增一次,变更索引引用决定记录。
3. 现行章节模式规则保留;不把后续愿景写成当前版本要求;不编造联网或新引擎。
4. PROJECT 范围变更只输出统筹交接,设计入口不改 `PROJECT.md`。

若优化前无法完成上述成果语义,该次标 **不可比**,不得用缺工作的短时长当效率基准。
