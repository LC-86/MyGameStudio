# 02: 识别任务并完成模块问答

**What to build:** 开发者描述一个想法或修改诉求后，方案设计读取相关资料、识别任务，并提出一组当前可以决定的问题。问题、选项和推荐清晰可辨，各种回答都能准确对应到决定与未决项；已授权且无歧义的局部微调使用简短流程。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Progress:** 待实施。

**规格依据：**《MyGameStudio：统一游戏设计问答框架》；用户故事 1～15、21、24、32、37～39、44、46、52；验收场景 1～5、9、10、15、19、23。本票先完成交互行为，记录可靠性由第 03 票深化；既有记录职责继续适用。

- [ ] 根据请求、当前有效设计和实际项目阶段，区分新设计、补充规格、设计变更、实现偏差及混合请求，并说明依据。实现偏差不通过擅自修改设计来消除；不新增公共 Skill。
- [ ] 读取已定内容与必要前置事实，不重复询问已有答案。优先处理全局影响、返工风险和阻断问题；可自行调查的事实由 AI 查清，仅依赖缺失事实的问题等待。
- [ ] 每轮标明目标、模块、轮次和问题数量；每题按 ❓ Q编号与标题、问题正文、A/B 等选项、➡️ 推荐及理由组织，题间清楚分隔。开放问题允许自由回答，不凑选项或固定题数。
- [ ] 同一模块有三项可立即决定问题、第四项依赖第三项时，首轮完整提出前三项，第四项等依赖确定后再问。不混入无关模块问题。
- [ ] 支持逐题选择、整体采纳推荐、只修改部分答案、自由方案、部分回答和模糊回答。整体采纳只覆盖已展示且指代明确的建议；已明确答案保留，只澄清有歧义的部分。
- [ ] 遵守每条消息及工具参数 6,000 字符上限和约 4,000 字符分批原则；按完整问题分批，编号连续。未展示或未回答的内容不自动采纳。
- [ ] 面对体验目标或“不知道”，提出有理由的方案、计算、具体例子或验证问题；临时推演假设保持提案身份，不成为已采纳基线。
- [ ] 用适用边界场景发现矛盾，明确修正后更新后续问题。按需显示 ✅ 已确定、⏳ 待讨论、💡 我的提案、🧪 待验证、🚫 当前不做；采纳与验证可以同时有不同状态。
- [ ] 已授权、无歧义且无连带影响的局部文案或提示调整，直接完成差异与必要核对，不强行提问或重开全游戏地图；未授权的产品与外部动作不执行。
- [ ] 在现有高层入口验证实际回复及结果，覆盖上述正常、部分回答、依赖、分批和偏差分流场景；仅检查 Skill 文本含关键词不能判为交互通过。
