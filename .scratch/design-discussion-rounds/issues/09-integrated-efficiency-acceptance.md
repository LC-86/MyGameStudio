# 09: 完成两种模式的整体与效率验收

**What to build:** 对最终候选版本完成统一框架的整体行为与效率验收，分别证明新设计成稿和已有设计变更满足规格，并用真实前后配对数据判断是否减少重复步骤和等待时间。条件未达到时如实报告失败或尚未验证，不把文件已生成当作验收通过。

**Blocked by:** 01 — 固定场景并采集耗时与步骤证据；08 — 减少重复读取与检查。

**Status:** ready-for-agent

**Progress:** 已完成接缝测试与效率「尚未验证」报告（2026-09-14）；PR #38 审查后将总报告口径限定为接缝测试通过，高层真实交互验收保持未完成。

**规格依据：**《MyGameStudio：统一游戏设计问答框架》；用户故事 30、31、43、55、56；全部 25 个验收场景及“步骤与耗时对比”“效率通过条件”。

- [x] 固定最终候选内容身份，核对前置工单成果和测试证据。既有未受影响且可核验的结果可复用；受影响的旧结果不能当作当前已通过，必要时重新执行对应检查。
- [x] 25 个行为场景均有结构化接缝测试证据（落盘回读、受控通道、台账与状态）。高层真实宿主入口贯穿提问、回答、落盘与 Game-Spec 同步仍未完成，不把接缝通过写成真实交互验收无缺口。
- [x] 新设计与已有设计变更分别使用第 01 票固定的场景和计时方式；保持同一模型及推理设置、宿主、工具、权限、相同起始项目副本、语义一致的回答和最终成果范围，记录版本与运行条件。
- [ ] 每种模式采集三组有效前后配对并交错先后顺序，独立展示全部单次结果；不能混合平均、只挑最快样本或将候选自身错误作为环境故障剔除。失败、重试、外部干扰和缺失数据均保留说明。
- [ ] 计时覆盖回答到达、决定实际保存与必要回读、下一组完整问题或结果呈现、最终规格同步与完成回复；仅扣除有明确时间依据的用户思考和输入等待。计入工具、网络、失败返工及最终同步，没有未完成的工作留在计时之外。
- [ ] 报告讨论回合数、读取次数与内容规模、写入次数与涉及文件数、检查和调用次数，并区分必要与重复操作。至少一项可核实的重复步骤减少，其余不变或增加的指标也如实展示并解释。
- [ ] 每种模式的完整模块处理用时中位数、模块累计决定保存用时中位数均低于优化前；两项指标各自至少两组配对变快。保留原始时间与计算依据，不预设未经实测的改善百分比。
- [x] 若优化前无法完成相同成果语义、有效样本不足、计时边界缺失或存在明显环境干扰，结论为效率尚未验证；步骤减少但耗时未满足条件时，不判效率验收通过。正确性失败不得用速度提升抵消。
- [x] 局部无歧义微调单独检查最小步骤，确认没有强制访谈、无关地图重建或全量检查；两种模式的正常流程也不能以漏记录、删除必要检查或推迟同步换取速度。
- [x] 形成可追溯总报告，区分行为通过情况、两种模式的步骤和耗时结果、限制及尚待解决事项。只有两种模式均满足规格才能报告统一框架验收通过；未通过的相关缺口保持未完成，不扩大修复范围或宣称产品已发布。
- [x] 本票不修改 G02 的游戏设计、产品代码或数据，不扩大权限，不创建外部工单，也不自动提交、推送、打标签、安装或发布。
