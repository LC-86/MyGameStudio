- **S1（P1）草稿发布写入错误仓库**：离线期间保存的草稿记录了原仓库坐标；切换仓库后发布草稿忽略草稿自身的仓库记录，向当前仓库发出请求并把旧草稿标记为已发布。期望：发布前逐份核对草稿记录的仓库与当前后端授权仓库一致，不一致即拒绝发布该草稿（不发出请求、不标记已发布、如实报告原因）；不得把选择新后端当作旧草稿的迁移授权。
- **S2（P2）回读失败后重复发布评论**：结果评论创建超时后按身份回读，回读本身失败（超时/错误）被当作「确认不存在」继续重发，替身出现两条相同评论而调用方只得到未确认报错。期望：区分「回读确认不存在」与「回读失败」；后者保留未知状态并停止重发，结果如实报告已尝试步骤与不确定结论，不虚报失败也不虚报成功。
- **S3（P2）GitHub→本地迁移后读取不到任务**：切换计划产出的 CONFIG 任务根写成旧 GitHub 坐标，任务文件实际生成在本地工作目录，统一接口读取结果为空；返回的产出目录指向不存在的路径；CLI 反向迁移入口未建立所需读取通道。期望：计划目标、本地文件落点、CONFIG 任务根、返回路径四者一致，并从 CLI 真实入口（不注入测试替身）验证一次反向迁移。
- **S4（P2）未验证引用就宣告远端可达**：交接基线核对只检查引用字符串存在，完全离线时仍逐项输出「远端可达」且整体通过。期望：可达性结论只能来自实际执行的检查；未执行检查（含上游不可用）时明确返回未验证/不可达，引用存在不等于检查通过。
- **S5（P2）离线开工报告隐去缓存状态**：统一开工接口取后端任务后丢弃缓存元信息（是否缓存、抓取时间、来源），断网时输出与在线无差别，调用方无法判断是否在依据旧状态安排工作。期望：缓存元信息传递到顶层结果，能区分缓存推断与当前确认。
- **S6（P2）同秒草稿互相覆盖**：草稿文件名由秒级时间、操作与任务身份生成并直接覆盖写入，同一秒两次不同结果的操作只剩后者。期望：每个待发布操作有稳定且唯一的身份（单调序号或内容哈希等），写入不覆盖既有草稿。
- **核验建议 1（P2）两套任务核验语义漂移**：GitHub 后端重复实现本地任务核验且漏掉工作请求必填字段的校验，同一畸形任务在两个后端得到不同核验结论。期望：规范化任务的核心校验（标签、核心文档、任务请求字段、重复类型等）提取为单一实现，两个后端共用，后端只保留存储特有检查。
- **核验建议 2（P3）动作参数三路不一致**：安排更新的说明参数在在线执行路径传递，在草稿保存与重放路径丢失，重放后变成默认文案。期望：动作参数规范共享，保存、在线执行、重放三路一致。
