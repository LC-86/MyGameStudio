# 01:curl 锚定前缀验证/诊断来源/主机身份(SP-24~SP-26)

**What to build:** 短 token 的禁用前缀(`-L`/`-K`)藏在带值字符前被跳过检查、响应正文中的失败措辞冒充连接诊断、主机子串把 127.0.0.10 当成 127.0.0.1。短旗标须按顺序验证、失败证据须可区分来源且按主机身份比较。

**Status:** ready-for-agent

**Category:** bug

## 缺陷与期望行为

审查详情:[../evidence/review-8.md](../evidence/review-8.md) SP-24~SP-26(3×P2),探针 [../evidence/new-probes/new-probes-8.py](../evidence/new-probes/new-probes-8.py)(17 例含 prefix/host/diagnostic 三守卫与 fixtures;当前 HEAD 复现:6 行假绿,见 [../evidence/triage-repro-verify.txt](../evidence/triage-repro-verify.txt))。三项同属 `acceptance/18-complete-package-acceptance/run.sh` 的 `curl_direct_denied` 一个函数域。

- **SP-24 短 token 禁用前缀被带值字符掩盖**(约 311~315 行):解析器先在整个 token 内寻找任意 `CURL_VALUE_SHORT` 字符,找到即消费,**未确认该字符前的每个字符均属无值白名单**。实际 `-Lm2 http://127.0.0.1:端口/redirect`(服务器 302 命中后转向、失败输出/exit 28)、`-LsSm2`、`-Lm 2`、`-K路径`(配置设 resolve 重映射)四例判据 OK 假绿——`L`/`K` 已被移出白名单却未「出现即不成立」。期望:**按顺序验证短参数**——首个带值字符**之前**的每个字符必须都在 `CURL_PLAIN_SHORT` 内,否则整个命令不成立(None→MISSING);正常聚合 `-sSm2`/`-sSm 2` 保持 OK。来源校准:前三例在 3e6ae30 为 MISSING(上一批粘连值消费修改引入的**新回归**),`-Lm 2` 旧新均 OK(同根既有遗漏)。
- **SP-25 响应正文伪装连接诊断**(约 362~364 行):`aggregatedOutput` 任意行只要同时含连接短语与 `.1` 即成立,不判断该行是否来自连接失败诊断。实际单 URL 返回 200、正文首行 `Failed to connect to 127.0.0.1` 后延迟剩余字节;curl stdout 含该正文、stderr 为 `Operation timed out … with 31 out of 41 bytes received`、exit 28——连接与部分响应已成功,判据却 OK。期望:**可接受证据约束到能区分连接阶段与响应阶段的记录**(如 curl 诊断行形态:错误前缀+连接短语+目标主机),或保守拒绝无法区分的形态;审方明示**单加一个正则不是完整方案**,残余模拟边界(正文逐字节模拟诊断行)如实留档。留存 g1 真实输出 `curl: (7) Failed to connect to 127.0.0.1 port 64026 after 0 ms: Couldn't connect to server` 须保持 OK(诊断行形态天然满足)。
- **SP-26 主机子串冒充身份**(约 363 行):`STANDBY_HOST in line` 是子串包含,不是主机身份比较。实际子进程 `http_proxy=http://127.0.0.10:端口`、URL 仍 `.1`,stderr 明确 `Failed to connect to 127.0.0.10 port 端口`,判据 OK——`.10` 包含子串 `.1`。期望:**解析诊断行中的目标主机身份并比对**(捕获诊断短语后的主机 token 与 127.0.0.1 相等,或等价的非子串边界),无关文字与更长地址不再形成绑定。事件已明确点名他址,不属已接受可见性限制。
