# 15：正确处理目标变化、并发工作与中断恢复

**What to build:** 当目标变化、多个执行者竞争成果或工作中断时，任务和基线能保持一致，恢复不会按过时依据推进或覆盖新成果。

**Blocked by:** [09：完成一个代码任务并交接实际结果](09-code-task-delivery.md)

**Status:** ready-for-agent

## 验收标准

- [ ] 目标或范围变化后识别受影响基线与任务，进入重新分流和同步流程；保留原版本下的完成事实，不自动算作满足新目标。
- [ ] 检测版本号未同步的手工内容变更，并按实质影响处理；格式变更不无故作废所有成果与证据。
- [ ] 两个执行者竞争同一资源时只有一个有效写入者；规范化标识处理别名，写入前版本核对防止覆盖他人已完成成果。
- [ ] 独立资源可并行，集成责任明确；使用真实竞争和过期输入样例证明冲突会被等待、拒绝或重新安排。
- [ ] 失联、崩溃或任务到期后，核对并撤销旧实例的写入能力及仍活跃进程，再回收占用；持续进程不能在旧授权失效后继续写。
- [ ] 中断恢复核对当前配置、实际文件、已应用部分、结果与用户后续修改，只继续仍适用剩余工作；本票用受控任务样例验收，完整统筹组合留给下一票。
