# 13：独立审查实际待交付成果

**What to build:** Game-Review 以独立同专业实例检查真实成果的规范与需求符合性，准确定位问题，并可对修复结果复核。

**Blocked by:** [06：把功能想法形成当前可执行规格](06-idea-to-current-spec.md)

**Status:** ready-for-agent

## 验收标准

- [ ] 按被审对象选择独立同专业执行实例，直接读取规范、实际成果、当前规格及必要证据，不仅依赖作者总结；不新增常设评审角色。
- [ ] 代码 Standards 与 Spec 两轴独立执行、分别呈现；设计或资源按其专业标准及需求符合性检查。
- [ ] 明确固定待审版本和完整范围，包含适用的已提交、暂存、未暂存和新建成果；预置缺陷样例能发现被仅比较 HEAD 漏掉的问题。
- [ ] 每项问题关联具体证据和影响，区分明确规则违背、专业判断与未能检查，避免以报告生成等同验收通过。
- [ ] 审查实例仅写报告和证据，不能修改待审专业成果；修复后针对实际新版本复核，旧结论不会被挪作新版本通过证明。
- [ ] 采用预置设计、代码或资源成果独立验收，不依赖后续完整制作流程；未实现的运行能力清楚标为覆盖限制。

## 实施依据

开始时读取[实施范围与验收约定](../spec.md)，再按本票分支读取[审查与试玩合同](../../mygamestudio-framework/contracts/verification.md)、[运行保障合同](../../mygamestudio-framework/contracts/runtime.md)。具体工程位置在实施时从当前项目读取。
