# 08：将规格拆成可接手的本地原子任务

**What to build:** Game-Plan 将当前规格拆成本地独立任务，记录真实依赖、执行与验收分工及基线引用，使执行者能找到当前可开工工作。

**Blocked by:** [06：把功能想法形成当前可执行规格](06-idea-to-current-spec.md)

**Status:** ready-for-agent

## 验收标准

- [ ] 从已采纳当前规格和现有任务读取输入，只细化当前及近期可交付成果，远期工作保持合适粒度。
- [ ] 每项任务具有稳定身份、标题、目标、范围、基线、完成标准、执行责任、验收方式、真实依赖及结果入口；已有要求使用引用。
- [ ] 五类 triage 与进度、执行者、验收方式分别保存；需要人工试玩不阻止前面的 Agent 制作，不把暂缓或依赖未完成误写成 wontfix。
- [ ] 支持创建、读取、更新安排、记录关系、追加结果并回读；重复处理同一拆解不会静默制造重复任务。
- [ ] 当前可开工集合同时考虑未完成依赖、输入、版本、能力和授权；ready-for-agent 不等同于依赖已完成或已获所有权限。
- [ ] 使用包含代码、专业资源和人工验收的样例验证任务可独立接手、关系可解析且无循环；明确共享成果的写入协调与集成人。

## 实施依据

开始时读取[实施范围与验收约定](../spec.md)，再按本票分支读取[管理技能合同](../../mygamestudio-framework/contracts/management.md)、[工作记录与任务后端合同](../../mygamestudio-framework/contracts/records.md)。具体工程位置在实施时从当前项目读取。
